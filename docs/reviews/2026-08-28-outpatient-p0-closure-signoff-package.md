# 门诊医保数据契约 P0 收口签认包

**适用范围：** 单院门诊，结算单 + 费用明细，医保办经办/运营人员的指标查询与下钻。

**当前状态：** `P0_REVIEW_EXECUTED / ADMISSION_BLOCKED / PENDING_SIGN_OFF`；P1 仍为 `blocked`。

**主证据：** [门诊数据契约核验记录（P0 Task 1–7）](./2026-08-27-outpatient-data-contract-review.md)。本文件只承接尚需人工决定、院方开通和正式签认的事项，不复制 119 行字段矩阵、Q01–Q50 或已完成的语义发现。

**隐私边界：** 仓库版不得填写患者姓名、证件号、手机号、原始票据、内部交易号、账号、连接信息或任何可反推患者的行级值。真实票据核对仅在医院批准的受控环境完成，仓库只保留脱敏批次号、聚合结论和签认状态。

## 1. 使用与通过规则

1. 项目协调人复制本文件到医院批准的受控流转渠道，分发第 3–6 节给对应责任人。
2. 医保办先签认业务口径，再执行至少 30 票据核对；信息科并行完成 CDC/等价变更日志和专用只读通道；安全负责人批准字段、阈值与下钻边界。
3. 所有填写项以规则编号、版本号或受控证据编号回填；不得把原始患者数据复制回仓库。
4. 项目组按第 8 节重跑验证，更新第 7 节 G01–G13。
5. 只有 G01–G13 全部为“通过”、无未解释差异且第 9 节完成真实签认时，P0 才可改为 `complete`，P1 才可进入规划。

[来源: P0 评审 Task 7] G01 内部锚点、G04 费用明细源已有技术证据，但仍须纳入 G13 正式签认；其余事项不得因“已找到字段”自动判定通过。

## 4. B：至少 30 票据人工核对

### 4.1 选样与验收

- 样本不少于 30 份；所有已发现的金额超差交易必须纳入，但仓库版不披露其精确数量。
- 其余样本覆盖不同时间、科室、门诊类别、险种和有效状态；当前数据存在退费/部分退费/冲正场景时必须覆盖。
- 每份样本必须能从受控票据唯一定位内部 `T_TradeNo`，并核对主金额、费用明细条数、明细合计及状态链。
- 每个差异必须落入“数据问题 / 业务规则 / 舍入 / 状态链 / 映射 / 票据问题”之一，并有处置结论。
- 通过标准：30 份均可复现；所有差异在已批准容差内，或已有逐项原因、修正规则和业务签认；不得留下“原因未知但通过”。
