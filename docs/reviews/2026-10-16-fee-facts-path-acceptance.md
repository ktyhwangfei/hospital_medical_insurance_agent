## 交付范围

- `/fee-decomposition` 按「结算事实 → 正向结算路径 → 逐字段核对」排列；policy-qa 沿用既有展示。
- 原单事实通过快照服务侧车携带，经共享公开投影进入 1.2 契约；内部金额结果版本保持 1.0。取得原单而分解不可用时，事实仍保留。
- 金额保持十进制字符串；零值、负值与缺失值分开。大病/救助放在金额事实，账户/现金单列支付方式。门特源表未返回个人支付合计时明确显示“未返回”，不拿算法或渠道加总回填原单。
- 路径只展示已执行步骤，分开已记录计算、零金额、不适用、未知、仅账面；缺失引用局部降级。全额自费不伪造目录重算，职工门特已有划分汇总明确命名。
- 复用现有费用明细接口与表格、公式组件和 Tabs；首次切换明细才请求，保留加载/空/失败/重试状态，卸载后忽略旧请求。390px 下单号输入独占一行。
- DTO、白名单解析器、历史响应兼容、组件和页面测试同步；1.0/1.1 无新增块时显示降级说明。

## 审查与修复

接手时先核对已有未提交改动、计划、四个快照入口与调用者；保留既有工作。以下确认问题均先用失败测试复现，再修复并复审：

| 问题 | 修复边界 |
|---|---|
| 门特费用明细节点错用医保内小计代表总费用 | 总费用取对应字段，医保内小计仅关联到已有划分汇总节点 |
| 费用合计/个人支付/渠道等终端计算没有分支引用，页面无法展开 | 纯投影补入有效终端引用，去掉重复与跨步骤引用 |
| 合并节点含未知分支却因局部有计算被标为已计算 | 未知/阻断/未评估优先；已知计算保留供展开 |
| 居民医事服务费、大病/救助及门特个人应付漏入路径 | 接入已有模块、字段及终端计算，无新增金额算法 |
| 定额基金节点混入患者统筹计算与采用理由 | 医院基金节点只关联 fixed_quota 分支，患者个人应付继续单列 |
| 定额基金记录含限额坐标，被展示成所有输入相加 | 改为输入清单与已记录结果，不拼造加法公式 |
| 全额自费提前返回后费用明细步骤消失 | 依据已执行的无待遇分支保留明细节点与个人承担理由，不补造目录步骤 |
| 大病/救助被混入支付方式，已读取机构等级没有传到事实区 | 纠正事实分组，透传已读取等级；缺失不猜测 |

本轮未修改待遇参数、取整、实际金额算法、鉴权、数据源配置或功能门控。原有主链及工作台门控语义继续保留。
