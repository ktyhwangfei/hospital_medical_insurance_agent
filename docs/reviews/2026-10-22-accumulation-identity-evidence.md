# 交易前累计（TB_/TA_ 列）增量恒等式取证记录（阶段 E 前置）

- 日期：2026-10-22（探针实跑时间 2026-10-23 17:23）
- 探针脚本：`scripts/eval/probe_accumulation_identity.py`（只读 SELECT，可重复跑）
- 原始结果：`.scratch/accumulation-identity-probe/results.json`
- 数据源：SQL Server bjybdb，`o_Trade`，院区 `T_HospCode='01110003'`（单院区 HIS 门诊交易表）
- 关联决策：D3（TB_FeeIn 交易前口径）、D4（TB_BigPay 交易前口径）签核前置证据
- 纪律：全部只读；未 SELECT/输出任何患者身份列（无 P_ICNo/P_IDNo/P_Name/P_CardNo）

## 探针口径

1. **Q1 全量增量恒等式**：`TB_Year == YEAR(T_TradeDate)` 子集（账面已维护子集）全量验证
   `TA_FeeIn - TB_FeeIn == T_FeeIn` 与 `TA_BigPay - TB_BigPay == T_BigPay`，
   容差 `ABS(diff) < 0.005`（money 4 位小数，覆盖退费负值）；NULL 单独计数。
   附加按 `(P_FundType, T_CureType)` 分组定位不成立行。
2. **Q2 TB_Year 分布**：按交易日期年份分组的 TB_Year 取值计数，含 2000/0 哨兵占比。
3. **Q3 居民 L1 分档列**：`P_FundType IN ('91','92','93')` 交易按机构等级档
   （`m_institution.H_LEVEL`，TRY_CAST 数值 >=10 为一级及以下）分组，统计
   TB_FeeInL1/TB_BigPayL1 的 NULL/0/非零，与 TB_FeeIn/TB_BigPay 对照。
4. **Q4 目标样例对账**：交易号 011100030X240408000002、011100030X241118000008 的
   TB_/TA_/T_ 各列 + 恒等式验证（仅交易号与金额列）。
5. **Q5 哨兵行形态**：TB_Year=2000 与 TB_Year=0 行上 TA-TB 与 T 的实际关系。

## 结果数字（实跑，未编造）

### Q1 增量恒等式（TB_Year==交易年子集，n=214）

| 恒等式 | 成立 | 不成立 | NULL | 成立率 |
|---|---|---|---|---|
| TA_FeeIn − TB_FeeIn == T_FeeIn | 181 | 33 | 0 | 84.6% |
| TA_BigPay − TB_BigPay == T_BigPay | 181 | 33 | 0 | 84.6% |

**33 笔不成立行全部集中在 T_CureType ∈ {17,18}（医事服务费通道）**，形态一致：
`TB == TA`（累计器未更新）而 `T_FeeIn/T_BigPay = ±40.00`（含退费镜像负值）。
按 (险种, 医疗类别) 分组：

- 非 17/18 通道（11/19 等）：**181/181 恒等式全部成立（100%）**，含职工/居民全险种、含退费负值行。
- 17/18 通道分险种表现不同：fund=80（15 笔）与 fund=91（9 笔）**全部不成立**；
  fund=3 部分不成立（cure17: 6/23，cure18: 2/10）；fund=33 全部成立（15 笔）；
  fund=93 cure18 有 1/3 不成立。即医事服务费是否计入年度门诊累计**按险种而异**。

|---|---|---|---|
| 2024 | 306 | 72 | 205 |

### Q3 居民 L1 分档列（P_FundType∈{91,92,93}，n=59）

本院区 `H_LEVEL='02'`（二级），全部居民交易落在 tier2 组：

| 列 | NULL | =0 | 非零 |
|---|---|---|---|
| TB_FeeInL1 | 0 | 54 | 5 |
| TB_BigPayL1 | 0 | 57 | 2 |
| TB_FeeIn（对照） | 0 | 27 | 32 |
| TB_BigPay（对照） | 0 | 37 | 22 |

两笔目标样例（均属本院二级）的 TB_FeeInL1/TA_FeeInL1/TB_BigPayL1/TA_BigPayL1 全为 0.00。

**结论**：L1 列存在、无 NULL、零填充，且确有 5/2 行非零——列被写入而非废弃；
但本院为二级机构，居民一级档累计天然应近似为零，非零行疑似记录的是他院一级机构就诊
后的跨院累计（与 TB_FeeIn 含跨院口径一致）。**仅凭本院数据无法判定 L1 列语义与维护质量**，
一级及以下机构的居民样本为零，L1 列结论保留为"有写入、语义未证实"。

### Q5 哨兵行形态

**TB_Year=2000（72 行）**：金额列无 NULL；TA−TB==T 仅 23/72（且与 TA==T 的 23 完全重合，
即 TB=0 时的巧合成立）；TA==TB 有 22 行、TB==T 有 27 行——三种形态混杂，样例行
TB_FeeIn=0/TA_FeeIn=1.44/T_FeeIn=0（TA 残留他值）。**哨兵行 TB/TA 列语义不一致，不可用作交易前累计**。

**TB_Year=0（306 行）**：TB_FeeIn/TB_BigPay **全部 = 0**（306/306），TA_FeeIn 126 行非零；
恒等式"成立"216/306 均为 TB=0 且 TA=T 的巧合形态。**TB 列零填充、未维护**。

## 对 D3/D4 签核的含义

1. **支持签核的部分**：在 TB_Year==交易年的已维护子集内，扣除医事服务费通道（17/18）后，
   增量恒等式 **181/181 = 100% 成立**（职工/居民全险种、含退费负值），TB_FeeIn/TB_BigPay
   作为"交易前年度累计"的全量证据成立，不再是 n 笔抽查。
2. **签核必须附加的口径边界**：
   - **医事服务费通道（T_CureType 17/18）按险种而异**：fund=80/91 的 17/18 交易
     累计器不更新（TB==TA，恒等式必然不成立）；fund=3/93 部分更新、fund=33 全更新。
     用 TB_FeeIn 作交易前累计时，17/18 通道是否纳入累计需按险种处理或显式排除，
     不能假定账面已正确累计该通道。
   - **哨兵行不可用**：TB_Year∈{0,2000}（63.9% 的行）TB 列要么零填充要么形态混杂，
     D16 同人推导路径仍是这些行的唯一取数方式；TB_Year==交易年 必须作为使用前置条件。
   - **跨院口径残留风险**：TB_/TA_ 列是医保中心结算回写的全口径累计（含跨院），
     本探针验证的是"账面自洽"（TA−TB==T），不证明累计基数等于政策要求的累计范围；
     跨院交易在本库不可见，TB 列与"同人同年本院累计"的差异由跨院部分吸收，属预期。
   - **L1 列**：居民一级档累计列有写入但本院（二级）样本无法证实其语义；
     居民一级机构样本出现前，TB_FeeInL1/TB_BigPayL1 不得作为一级档交易前累计的已证实来源。
3. **建议签核表述**：D3/D4 限定为「TB_Year==YEAR(T_TradeDate) 且 T_CureType∉{17,18} 时，
   TB_FeeIn/TB_BigPay 为交易前年度累计」；17/18 通道与哨兵行走既有降级路径并留痕。
