## 0. 总评

模块的**工程骨架是对的**（三步管线、变更集审核、版本快照、规则血缘、语义层值域、PDSC 主动发现——这些机制在国内医保知识库建设里已属前列），但当前处于**"治理闭环未接管线上服务、质量体系空转、行业核心维度缺失"**的状态。三个数字概括：

| 指标 | 数值 | 含义 |
|---|---|---|
| 接入文档 | **5 篇**（1 篇 raw 未提取） | 覆盖面无法支撑"医保政策知识库"定位 |
| 激活版规则数 | **4 条**（单一 rule_type） | 治理流水线产出与线上服务严重脱节 |
| 金标样本 / QA 用例 | **0 / 5** | 质量验证体系名存实亡 |

## 一、知识构建问题

### B1. 覆盖面：5 篇文档 + 险种目录缺位 `[来源]`

现状：5 篇北京文件（城乡居民办法及实施细则、基本医疗保险规定修改决定、住院/大病最高支付限额调整通知）。

医保知识库的行业基线至少应覆盖：

| 知识域 | 现状 | 行业影响 |
|---|---|---|
| 三大目录（药品/诊疗项目/医疗服务设施） | 无 | 费用解释类问答（本 Agent 主场景之一）无据可依 |
| DRG/DIP 支付政策 | 无 | 病案/结算场景的核心政策域缺失 |
| 门诊统筹、大病保险细则、异地就医、生育、医疗救助 | 无 | 城乡居民门诊、大病问答必错 |
| 修改决定/废止公告类文件 | 1 篇 **raw 状态未提取** `[来源]` | 政策修订恰是时效性主战场，最该先入库的那篇反而没进管线 |

`[推断]` 缺口排序的依据：本 Agent 的业务场景（结算异常导办、出院前质控）高频引用的正是目录类与支付方式类政策。

### B2. 发布闭环断裂：治理流水线未接管线上检索 `[来源]`

实测数据链：

```
PG: 278 行 reviewed 提取 / 546 条规则血缘
Milvus:
  policy_rules_v2                  337 条  ← 线上问答实际检索的 collection（硬编码）
  policy_rules_REL_202608182         4 条  ← 治理流水线"激活版"（全部 large_medical_mutual_aid_payment_ratio）
  policy_rules_REL_20260820_REINDEX 341 条  ← 08-20 重建，状态 building，卡死至今
```

后果：
1. **审核/发布/血缘做得再好，不影响线上答案**——`policy_active_release` 指向 REL_202608182，但检索服务 `RulesSearchService` 默认读 `policy_rules_v2` `[来源: rules_search_service.py]`；
2. 治理产物 99% 未生效（546 血缘 vs 4 条激活）；
3. REL_20260820_REINDEX1 卡 building 无人处理 `[推断: 无失败告警机制]`——发布失败静默。

### B3. 提取质量缺陷已量化 `[来源: PDSC 扫描实测]`

- **52 处值域越界**：`psn_type="在职职工,退休人员"`（拼接）、`med_type="购药/急诊/住院/门诊"`（简写）、`hosp_lv="一级及以下"`（粒度不符）、`psn_type="城乡居民"`（险种值写进人群字段，跨轴）；
- **值域基础设施空心**：`FUND_TYPE/YLLB/PERSON_TYPE` 值域为空数组；`m_institution.H_LEVEL` 14 个编码 0% 中文释义 `[来源: discovery 画像]`；
- **脏数据曾入库**：22 条"示例提取结果（dummy 模式）"archived 行，暴露环境隔离/门禁缺失；
- **置信度无校准**：reviewed 行均值 0.704（区间 0.7–0.95），无阈值语义、无抽检策略 `[来源]`。

### B4. 时间维度缺失——行业最核心维度 `[来源]`

- Milvus 检索 schema（`policy_rules_schema_v2`）字段：`hosp_lv/insu_type/med_type/psn_type/setl_type/rule_type/...`——**无生效起止时间、无发布机关层级、无统筹区**；
- 278 行 reviewed 提取仅 66 行（24%）含 `time_period` `[来源]`；
- 交叉验证设计里已有 `temporal_variant` 概念（PDSC），但 schema 层无承载位。

`[推断]` 医保待遇标准一年一调（起付线/封顶线/比例年年变），无时间维度意味着"今年标准"与"去年标准"同库混存，历史场景（补缴、追溯报销、申诉）必答错或答混。5 篇文档里"调整…的通知"就有 2 篇——政策库的本质是**时间序列**，不是静态表。

### B5. 概念体系单侧完备 `[来源]`

语义层（PG）已建成 zcgz 域 + 6 维度指标 + 值域字典，但检索 schema 只投影了 5 个维度字段：**jjgs（基金归属）在语义层有指标有值域，Milvus 却无该字段**——按基金类型过滤的检索（"大额互助资金报销比例"类问题）在标量层不可能执行，只能靠向量近似。PG 提取行 / Milvus v2 / Milvus REL_* 三处并存，无唯一权威源。

## 二、知识质量问题

### Q1. 质量验证体系空转 `[来源]`

| 机制 | 设计 | 实测 |
|---|---|---|
| 金标样本 | `policy_golden_sample` 表 | **0 条** |
| QA 用例 | `policy_qa_test_cases` | **5 条**（default 模板：起付线/门诊比例等通用问题） |
| 答案校验 | `answer_verification` 模块（代码完整） | **运行 0 次** |
| 发布门禁 | release 表有 quality_score/consistency_score | 激活版 1.0/1.0——4 条规则对 5 条模板用例，**分数无区分度**；case_set_version=0（未挂用例集） |

`[推断]` 这套体系是"建好了但没通电"：发布不跑用例、发布后不抽检、失败无告警（B2 的 building 卡死即证据）。

### Q2. 答案边界无护栏

- 项目规范要求 AI 输出必须携带 citations 或声明 uncertainties `[来源: AGENTS.md 安全约束]`。检索侧有 trace，但**无"知识库未覆盖即拒答"机制**——4 条规则的激活版与 337 条的 v2 之间，答案边界完全取决于检索器落在哪个 collection；
- 无失效政策下线链路：archived 文档的规则是否被检索排除，无验证。

### Q3. 一致性三处失守 `[来源]`

1. 提取值 vs 值域字典：52 处越界（提取侧不强制校验）；
2. 语义层 vs 检索 schema：jjgs 缺位；
3. PG vs Milvus 多版本 collection 并存（8 个 collection），权威源不明。

## 三、改进路线（按优先级）

### P0 止血（本周可做）

| # | 事项 | 验收标准 |
|---|---|---|
| 1 | **打通发布闭环**：修复 REL_20260820_REINDEX1 卡死；检索服务改为读 `policy_active_release` 指向的 collection（保留 v2 灰度开关）；发布失败必须有可见告警 | 线上问答命中激活版规则；v2 下线或明确为回退只读 |
| 2 | **时间维度落地**：提取 schema 强制 `time_period`（缺失标 unknown 并进审核必改项）；Milvus 增加 `effective_from/effective_to`（schema_version 机制已具备） | 新发布规则 100% 带时间；检索可按时间过滤 |
| 3 | **修改决定文档入库**：doc_1d44e2e1db0c 完成提取与审核；建立"修订类文件优先"的接入策略 | raw 文档清零 |

### P1 建制度（两周内）

| # | 事项 | 验收标准 |
|---|---|---|
| 4 | **金标与回归门禁**：建 ≥30 条金标（5 文档 × 主要待遇类型：起付/封顶/比例/大额/目录），发布前强制跑用例集、按 case_set_version 记分、低于阈值禁止激活 | 激活版 release 带 case_set_version>0 且分数有区分度 |
| 5 | **值域治理工单化**：消化 PDSC 发现的 52 处越界；补 FUND_TYPE/YLLB/PERSON_TYPE 值域；H_LEVEL 14 编码释义 | PDSC 扫描越界数趋零；业务字段释义率 ≥90% |
| 6 | **拒答护栏**：检索 top-k 相关度低于阈值时输出"知识库未覆盖 + 建议"，禁止硬答 | 有负例用例证明拒答生效 |
| 7 | **置信度语义化**：定义 0.7 的含义（如提取字段完整度函数），设审核阈值与抽检比例（如 <0.8 全审、≥0.8 抽 20%） | 审核工时下降且缺陷不升 |

### P2 扩面（按业务排期）

| # | 事项 | 说明 |
|---|---|---|
| 8 | 文档覆盖扩展 | 优先级建议：三大目录 > DRG/DIP 支付 > 门诊统筹细则 > 大病保险 > 异地就医 > 生育/救助。与结算导办、出院质控两个已上线场景的引用频次对齐排期 |
| 9 | 统筹区维度预留 | 跨地区政策区分；先加字段（默认"北京"），后建多区接入 |
| 10 | 政策效力层级 | 发布机关（市政府/局/部委）与文件效力类型（办法/通知/细则）入 schema，支撑"以最新效力为准"的消解规则 |

## 四、一句话结论

**这个模块当前是"机制完备、运营归零"**：三步管线、审核、版本、血缘、值域、主动发现都已就位——缺的不是架构，是让架构通电的运营闭环（发布接管检索、金标跑起来、值域字典喂饱、时间维度加上）。P0 三件事做完，这套底子在医保行业知识库里就能从"演示级"跨到"可用级"。
