# Issue #85：LLM 医保解释与医务审核的原始证据边界

研究日期：2026-11-06。仅讨论方向与评价，不修改当前实现。以下三项实证研究均不能证明中国医院医保审核的有效性；DECIDE-AI是早期临床评价指南，不是疗效试验。

## 对方向的约束与可被推翻的假设

以下是基于上述证据的**设计建议**，不是论文已经证实的医保结论。

1. **先定义要改善的审核结果，暂不规定“医生如何想”。** 同一批脱敏真实案例，比较现行人工、人工加最简证据辅助；模型独立输出只作能力基线。由未看到模型输出的医保与临床专家先建立参照答案，评价关键问题漏报、无证据指控、最终解释正确率、处理时间及人工改写量。若只增加篇幅、没有降低错误或工作量，就推翻“有帮助”。
2. **让模型处理开放材料与疑点，按需取证是否优于固定六问，需要比较。** 在同一输入、来源和模型下，对比自由生成、固定问题清单、可按疑点补证三种方案；控制或同时报告调用成本与延迟，重复运行观察不稳定性。六问与多轮 Agent 都只是候选。收益若在控制资源后消失，就不能归功于流程本身。
3. **验证结论与来源的关系，分别测临床依据和支付依据。** 对关键主张标记患者事实、临床解释或政策判断；核对对应病历位置、指南或当期本地政策的原文与适用范围。用“临床上合理但支付限制不满足”和“政策条件满足但病例信息不足”的成对案例测试。引用存在率、审核者喜好或模型自评都不能替代逐条支持率；原文不支持就算失败。
4. **把补证与保留判断当成可评价的结果。** 对完整案例逐项撤去诊断、适应证、时间、剂量或政策版本，再加入相互冲突材料；看系统能否定位缺口并调整结论，而非继续确定表态。评价误放行、误指控、补证问题有效率及有用结论覆盖率；不能用一律拒答获得表面安全，也不能把“医生未记录”写成“医生未考虑”。

尚无这些来源能回答：本院数据下什么模型足够、一次调用还是多轮更好、哪个协作界面能改善医保办工作。因此建议先用小批真实案例和盲评推翻弱方案，再决定最小实现；不据此扩建架构。

未做系统综述、模型复测或真实医保现场试验；本笔记只建立原始证据边界与可证伪评价方向。
