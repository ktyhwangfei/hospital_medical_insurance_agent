## 先读这段，再动手

**目标：在保留现有金额内核、确定性回答和诚实缺证机制的前提下，修复七项已复现缺陷。** 用户授权的是这七项修复，不是重做整个结算系统。

先读根及相关目录 `AGENTS.md`、`PROGRESS.md`，记录当前未提交修改和基线。按符号重新定位，不把昨日行号当永久地址。若某项已被其他人修复，用本文反例证明当前已满足后保留实现，不重复改写。

| 顺序 | 对应缺陷 | 本批完成条件 |

### 全程必须保持的约束

1. 费用解释继续由后端确定性证据生成，金额、比例、公式及来源不交给模型自由生成。
2. 保留真实金额、政策参数、取整模式、累计门控、资格未知状态与安全鉴权。涉及它们的新业务裁决属于后续任务。
3. 字段名、目标 ID、来源引用保持跨层一致。若确实需新增公开字段，同时改后端契约、前端解析器与契约测试；优先复用现有字段，避免为局部修复扩大接口。
4. 修改现有调用链上的共享入口，检查单字段、单行、多行、mixed、cover_all、追问及会话恢复的调用方。仅修一个 helper 而实际路径绕过它，不算完成。
5. 正式测试和必要的脱敏夹具进入仓库；`.scratch` 只是取证参考。保留他人未提交修改，交付本任务文件清单与可逆的差异，不暂存、回滚或删除整份他人文件。

## A. R1＋R6：先明确状态归属，再加异步保护

定位：`src/apps/portal/src/components/policy-qa/settlement-time-browser.tsx` 的 `load/handleLocate/handleSwitchPatient/onCandidatesChange`；同目录 `settlement-agent-workspace.tsx` 的 `handlePatientChange/handleSelect/sendQuestion`。

### 状态规则

**患者/查询上下文与对话会话是两种生命周期。** 新建对话不改变当前患者，也不让当前有效列表失效；换人立即清除该患者的列表、候选、选单、解释和会话锚点。

采用现有局部状态与 ref 实现，不引入全局状态库。列表保留一个有效结果的生产入口，父层命令候选作为该结果的投影；不能让父子组件独立拼接/恢复两份不同候选。若给回调补上下文标记，使用组件内不透明代次，不把患者身份原文加入持久化缓存或日志。

| 事件 | 列表与候选 | 解释与对话 |
|---|---|---|
| 定位/切换患者 | 立即使旧请求失效，清空旧结果；只接收新患者结果 | 使旧解释请求失效；清当前单、锚点及旧对话 |
| 提交新查询 | 新请求替代旧请求；加载期间不可把旧候选当新查询结果选用 | 同患者已选单可保持明确单号锚定，不因筛选条件暗换单 |
| 编辑日期/预设、日期无效 | 本任务采用清空旧列表和候选的策略；有效查询成功后恢复 | 当前单仍显式显示，不把它自动加入新候选 |
| 列表请求成功 | 只有当前患者代次、查询上下文、最新请求均匹配才更新列表及候选 | 不自动选单或发问 |
| 列表请求失败/结束 | 只有当前请求能更新 error/loading；旧 catch/finally 无作用 | 不影响其他患者/新请求的解释 |
| 新会话 | 保留有效患者、查询、列表及候选；正在进行的同患者有效列表查询可继续 | 清选单、解释、锚点及追问目标；旧解释响应不能回填 |
| 组件卸载 | 在途结果不得回调发布候选或再产生有效状态写回 | 保持现有流清理机制 |

**请求规则：**用递增请求序号和上下文代次校验所有成功、失败、finally 分支。患者 A→B→A 也必须拒绝第一次 A 的响应，所以仅比较患者 key 或日期值不够。AbortController 可用于节省请求，但请求身份校验仍需存在，不能假设取消一定及时生效。

命令和点击都只使用当前有效列表的完整条目，保留同一 `settlementId/decompositionChain/settlementDate/serviceType`；候选外仍提示调整时段。新会话单独重置对话，不再复用会清候选的换人函数；页面按钮和 `@新会话` 命令复用同一重置入口。选单使用 reset 返回的新 session ID，并与后续问答保持一致。

### 必须加入的测试

| 用例 | 输入/到达顺序 | 必须断言 |
|---|---|---|
| A1 | A 列表挂起→定位 B→B 返回→A 返回 | B 的列表、候选、loading/error 均不被改；点击/命令都不能请求 A 的解释。 |
| A2 | 同患者旧日期查询挂起→新查询先返回→旧请求成功或失败 | 新结果保留；旧异常不展示；旧 finally 不把新请求 loading 提前关闭。 |
| A3 | A 第一次挂起→B→A 第二次查询→第一次 A 返回 | 第一次 A 仍过期，不能因为 key 又相同而接受。 |
| A4 | 查询挂起→编辑为无效日期，或卸载 | 无旧列表/候选重新发布；命令不能选用被清除条目。 |
| A5 | 正常选单→新会话→点击/命令选择仍可见的同单 | 两种入口请求同一正确链路，使用新 session；随后提问使用相同 session/单号。 |
| A6 | 新会话或换人发生在解释请求挂起时 | 旧解释不能恢复到新会话；换人后旧单命令拒绝；旧追问目标不继承。 |

复用两个现有组件测试文件，使用 deferred promise 精确控制到达顺序，测试不用随机延时。至少一个联合用例挂载真实 `SettlementTimeBrowser`＋workspace，仅 mock 网络/服务边界；否则父层 stub 主动重新推候选会掩盖 R6。会话 mock 每次 reset 返回不同 ID，不能用固定 `sess-reset-1` 假装验证了新会话。

## B. R2＋R3：数值保真与证据展示资格分别处理

定位：`src/runtime/policy_qa/fee_decomposition/model_explanation.py` 的 `build_target_evidence/build_line_target_evidence/_build_lines_model_input/build_model_input/_target_evidence_text/render_evidence_answer`。资格和现有说明来源同时查 `explanation_scope.py/public_view.py/field_explanations.py`。

### R2：数值规则

删除 `render_evidence_answer` 对整段正文的 `re.sub(... :.2f)`。由已知类型的结构化字段决定展示，已有合适 helper 就复用。

| 数据 | 正确处理 |
|---|---|
| 结算展示金额、已取整的最终支付 | 可展示两位小数；不能改 underlying Decimal、取整位置或模式。 |
| 数量、分数量、比例 | 保留有效精度；百分比和小数转换须数值等价。0.0005 不得变 0.00。 |
| 单价、限价等公式输入 | 原始输入可能超过两位；公式内保留计算所需精度。不能把“带元”一概视为可截断成两位。 |
| 未取整中间值 | 保留精度及明确取整节点，避免显示出错误等号。 |
| 版本、代码、日期及来源文本 | 原样保留，继续使用已有脱敏/内部字段消毒入口；不做数值舍入。 |

这也修正上一份简略建议的歧义：**“金额两位”只适用于相应展示金额，不等于所有货币操作数都允许改成两位。** 若高精度中间值转为分，应显示实际取整步骤，而非把近似值直接放进精确等式。

### R3：证据资格规则

选定一处共享证据装载入口生成“可展示内容”，各目标路径都调用它；renderer 只消费处理后的证据。现有 `payload.decomposition` 清理结果不能被原 `public` 的 target/line evidence 绕过。局部 helper 足够时不新建框架、规则引擎或一套财务算法。

| 对象/状态 | 允许交付 | 必须保留的边界 |
|---|---|---|
| 普通字段已独立核对且 `explainable=True` | 本字段实际依赖中的允许计算、操作数、已执行采用档及来源 | 终端计算属于本字段，不能随意选引用数组最后一条；不能借其他字段相同金额作证。 |
| 费用行 `explainable=True` | 本行核对过的费用划分及实际路径 | 每行独立，不能借相邻行的金额/来源；总额和分拆口径分开。 |
| 未算平/依赖未核对/缺计算的普通字段或行 | 原单事实、明确缺项和边界 | 候选公式/比例/路径不得作为本项原因或“采用”进入可信正文。 |
| GRZIF1 专门的计算构成 | 继续展示已被现有投影允许的补助前分量构成及计算值 | 保留 `SELF_PAY_1_BOOK_COLUMN_UNMAINTAINED` 的准确语义；不称原单金额或独立账面核对通过。缺上游依据时也不能借该原因码放行任意公式。 |
| 账面恒等/支付渠道 | 可展示原单及已支持的账面构成 | 不提升成待遇原因已独立解释；不删除已有可追溯构成。 |
| 不适用或模板无映射 | 明确的不适用依据，或原单事实及映射缺口 | 0 元不是资格否的证据；无映射不得借相邻字段 matched。 |

检查 `sentence/explanation.composition/basis_text/formula/formulas/ratios/notes` 等所有实际可渲染入口，不能仅清空独立 formula 后让同一内容留在 sentence 中。原单单价×数量与账面费用不相等时，事实可以并列展示，不能强写等号。公式诊断如需保留，沿用诊断视图并标明候选，不在本任务新建诊断产品。

当前“金额核对资格”与“政策来源治理确认状态”继续分开：参数待签核但已按当前口径相符的结果保留现有边界；未执行 `eligible` 候选不称“采用”；不得为解决泄漏给所有字段一律要求政策已签核。

## C. R4＋R5：局部绑定，最后合并目标

定位：同一 `model_explanation.py` 中 `resolve_question_target/_claimed_item_name/_mixed_summary_codes/_item_name_hits` 及行号、列表编号入口；核对 `followup_target.py` 和路由的来源、`calculation_checked` 消费方式。

### 解析顺序和语义

先收集行定位子句、显式汇总字段及范围意图；在每个行子句内校验行号/名称/金额线索，再构造既有 `QuestionTarget`。名称唯一命中只是一个目标，不能立即 return 并丢掉同句其他目标。可以沿用正则做有界定位，无需通用自然语言解析器或额外 LLM。

| 问题组成 | 期望 |
|---|---|
| 明确整单“全部费用/所有展示金额”＋项目强调 | cover_all；包含全部展示字段（含 bill.*）和全部费用行。 |
| 明确汇总字段＋项目名/行号 | mixed；两类目标均保留，先后顺序不改变集合。 |
| 只问某行“医保内/外、数量、单价”等 | 仅该行属性；这些词不额外变成整单合计。 |
| “第1行、第2行全部解释/两个晶体都解释” | multi_line；这里“全部/都”只限定两行。 |
| 明确行号＋名称 | 逐个局部配对核验；不能把全句行号集合与名称集合做无序比较。 |
| 无项目名的属性问句 | 正常定位；请求前缀、连接词、问句尾不是名称。 |
| 明确未知名/行名错配/越界 | 按现有 invalid/ambiguous 提示核对，不能静默改成另一个项目并核对成功。 |
| 无法可靠解析的定位部分 | 澄清，不能把无法识别改成“无项目名”后继续宣称已完整回答。 |

行子句边界要保留前后独立汇总部分；只在对应行子句中识别属性。明确名称位置优先使用引号内容、已知项目匹配、行号到已知属性/疑问词之间的名称槽；只有在该位置成立时才把未知内容视为项目名，不能“删完停用词剩余汉字就是药名”。有限的语法词可以使用，但补一个“请解释”不是根因修复。

显式错误定位不能被 cover_all 吞掉；例如“全部费用，尤其第1行阿莫西林”应核对错误定位，而不是声称已解释这个不存在的项目。重复名称且用户明确要全单时，全单已覆盖对应各行，无需假定其中一行；仅问重复名称单行时仍按已有金额/行号消歧。

| C3 | 请解释第1行的医保内外；麻烦说明第1行医保内外；第1行的数量、单价和金额分别是什么 | fee_line；没有“请解释/数量单价”为不存在项目的提示。 |

| C6 | 第1行阿莫西林；1. 阿莫西林；全部费用尤其第1行阿莫西林 | 所有编号入口同一校验；明确未知名不放过。 |

## D. R7：让验收能否定实现，而非复述实现

定位：`src/tests/unit/runtime/policy_qa/fee_decomposition/test_acceptance_grading.py`，以及 `.scratch/four-chain-remediation-20261026/accept.py/verify-key-amounts.py`。将要长期使用的验收规则、必要夹具/脚本迁入仓库现有测试/评估目录；临时脚本不能是唯一资产。

### 先固定独立预期

金额目标用 `(case, template.key)` 唯一标识并记录 field_code 或 bill.* 映射；费用行用 `(case, line_id)`，保留当次展示序号。中文标签和金额相同都不能替代目标 ID。

每个要求至少包含：目标、预期金额及其口径、预期四态、必要构成/操作数/已执行分支、该目标应有的来源类别或引用、必须声明的缺项/边界、禁止作为原因的候选。原单或数据来源是来源的一类，不要求所有费用行都有政策原文。

预期由取证记录、现有黄金样本及显式 Decimal 算式固定，并记录依据。实际 response 只用于取“实际”，不能把实际 `explainable/amount/calculation_refs` 再复制成 expected。允许从模板枚举展示目标，但必须与固定清单比对新增/遗漏；不能从本次响应自动决定它本应属于哪种解释状态。

### 判定必须分成两个轴

- **内容状态**继续用 reason_explained / book_fact / not_applicable / missing_evidence。GRZIF1 的计算值与原单事实用现有构成边界明确区分，不能因归入统计就改称账面金额。
- **验收断言结果**独立为 pass/fail：有没有交付该目标、金额口径是否正确、证据是否匹配、缺项是否明确、是否夹带错误。诚实说明缺证可以通过“如实交付”检查，但解释状态仍是 missing_evidence；漏答或空文不能冒充诚实缺证通过。

reason_explained 必须同时满足目标金额绑定、必要构成正确、所用分支/来源属于本次目标、最终正文与证据对应。没有必要构成/来源要求的 explainable 验收配置本身应报错，不能因为默认空 tuple 就通过。来源允许在该目标此次回答的 citations 中，不强迫都挤进同一行；禁止借另一轮 cover_all 的 citations。

既校验结构化事实，也校验最终正文：结构化金额正确而正文把乘法改减法，仍然失败。对已登记公式使用独立的 Decimal 小算式和明确操作顺序检查，再比对受控公式正文；不导入被测 renderer 生成 expected，不建设任意自然语言数学解析器。空格/全角符号可归一化，运算符、目标归属、比例及取整位置不能被归一化掉。

缺证判断只影响该目标所需的实际依赖；来源治理待签核、跨院边界声明不能一概导致所有正确构成降为缺证。反之，正确目标金额旁出现年份或其他金额，不等于存在构成。

### 判定器必须拒绝的反例与必须接受的正例

| 用例 | 断言 |
|---|---|
| D1 | “大额支付1597.50元；计算过程尚未提供，来源2024年”不能算原因已解释。 |
| D2 | “3195×50%－2304.50＝1597.50”不能因数值和来源都出现而通过。 |
| D3 | “大额支付1597.50；暂无计算，但其他金额100”不能借其他金额通过。 |
| D4 | 同金额放错字段/行，或某字段用其他行来源，应失败。 |
| D5 | 已验证0＝0＋0的分支允许解释；数字种类只有一种不应误失败；0元未知资格仍缺证。 |
| D6 | 同一目标诚实说明具体缺项，与目标漏答、空正文、仅“资料不足”分别断言；后几种不得作为已如实交付。 |
| D7 | 保持金额、数字和来源不变，只改乘/减操作符，调换两行的归属，删除来源，或追加不可解释候选：对应断言必须失败。 |
| D8 | B1精度正确/B3缺证正确/C1全部目标保留等正例必须通过，避免用全拒绝判定器达成“所有负例通过”。 |

用参数化样例做这些变异即可，无需新增测试框架。84项重跑结果以新输出重算，不能把旧54/18/9/3当必须达到的配额。若发现解释覆盖下降，逐项说明是否原先误计、有效事实丢失或新回归，不能通过降低 expected 来调平统计。
