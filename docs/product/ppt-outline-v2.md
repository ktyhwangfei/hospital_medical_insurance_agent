## P3 · ① 需求是否够痛（痛点页 · 需用真实数字）
- 标题：**需求够痛：不是"会不会解释"，是"解释贵、解释乱、解释不出依据"**
- 定性痛点（可溯源：`docs/specs/11 门诊…需求分析` 第三章、`docs/specs/13 …讨论纪要` 第二章）：
  1. **解释不一致 → 投诉**：医院真正怕的不是咨询量，而是"解释不一致导致投诉"——投诉率远比咨询量重要【待补：某院月均医保相关投诉 N 起 / 投诉占窗口事务比】
  2. **复杂计算耗时**：费用拆解 / 待遇分析 / 退费影响需查多系统 + 医保办 + 人工确认，过程长【待补：单笔复杂咨询平均耗时 X 分钟 / 高峰窗口排队 X 分钟】
  3. **患者不理解费用**："为什么我要交这么多钱"→ 误解"医院乱收费、医保不报"→ 投诉【待补：退费纠纷 / 费用争议 N 起】
- 组织级延伸（供领导视角，需你确认是否展开）：DRG/DIP 支付改革下科室亏损与医保拒付/扣款风险、飞检合规压力、申诉繁琐【待补：本院 DRG-DIP 亏损科室数 / 上年度医保拒付扣款 X 万 / 飞检问题项 N】
- 收口：这正是 AI 导办能啃的硬骨头——把"经验依赖"变成"可复制、可一致、可追溯"的能力

## P4 · ② 我们怎么满足（定位与价值）
- 标题：**定位：院端医保 AI 导办与运营协同中枢，不替代系统、只做导办与闭环**
- 一句话定位（源自现状 slide-2）：不替代医保结算/事前审核/DRG/病案/费用调整，把分散的专业系统结果 → 可理解、可执行、可追踪的业务任务
- 六类角色入口：医生工作站 / 病案质控 / 收费窗口 / 医保办 / 科主任 / 院领导（AI 融入既有工作流，不形成信息孤岛）
- 八类业务场景：政策问答 / 结算异常导办 / 出院前联合质控 / 模型服务 / 知识库管理 / 技能管理 / 运营看板 / 嵌入式 Chat
- 服务模式（可溯源 `docs/specs/13` 第五章）：**默认解释 + AI 补充 + 人工兜底**——AI 不是第一入口，是第二层能力
- 四大价值（可溯源 `docs/specs/13` 第七章）：① 助患者速懂费用、降焦虑 ② 减少复杂咨询进窗口、降压力 ③ 提升解释一致性 ④ 降低投诉风险
