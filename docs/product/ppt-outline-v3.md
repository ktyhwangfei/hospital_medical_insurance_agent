## P3 · 一、建设背景与必要性
- **章节标题**：一、建设背景与必要性
- **页面标题（结论先行）**：**现场调研揭示门诊医保咨询呈"四高一重复"特征，智能化导办建设势在必行**
- 真实调研底座（来源：`docs/specs/协和调研.md` 82 条保真记录 + `协和调研单据-需求分析.md` 6 类实物单据）：
  - 协和医保科 **82 条现场咨询保真记录**，聚类为 **9 大业务域**
  - 80%+ 咨询可归结为 4 类模式：**政策解释 + 身份识别 + 费用解释 + 办理指引**
  - 高频分布（占比 / 案例数）：慢特病办理 **18%（15）**、异地医保 **13%（11）**、医保身份问题 **9%（7）**、费用报销解释 **7%（6）**、退费 **6%**、挂号亲情账户 **6%**、住院 **5%**、费用计算 **5%**、政策资格 **4%**
  - 费用解释被调研明确为 **"AI 价值最大的部分"**（"为什么这次报得少 / 自费增加了"）
- 组织代价（定性，源自调研归纳）：大量人工时间消耗在解释与引导；患者因"解释不一致、解释不出依据"产生误解与投诉
- 实体化依据：系统须读懂 6 类真实单据（D1 收费票据 / D2 实时结算单 / D3 特殊事项申请表 / D4 就诊须知 / D5 北京 14 种特病清单 / D6 异地 9 种直结清单），且须拦截退费、改身份等高风险动作
- 收口结论：**需求真实、痛点明确、场景高度标准化——建设智能导办契合一线刚需，而非锦上添花**

## P4 · 二、总体定位与建设目标
- **章节标题**：二、总体定位与建设目标
- **页面标题（结论先行）**：**定位院端医保 AI 导办与运营协同中枢，补能力而不替代既有系统**
- 一句话定位（来源 `docs/specs/13`）：不替代医保结算 / 事前审核 / DRG / 病案 / 费用调整，将分散的专业系统结果 → 可理解、可执行、可追踪的业务任务
- 六类角色入口：医生工作站 / 病案质控 / 收费窗口 / 医保办 / 科主任 / 院领导（AI 融入既有工作流，不形成信息孤岛）
- 八类业务场景：政策问答 / 结算异常导办 / 出院前联合质控 / 模型服务 / 知识库管理 / 技能管理 / 运营看板 / 嵌入式 Chat
- 服务模式（来源 `docs/specs/13` 第五章）：**默认解释 + AI 补充 + 人工兜底**——AI 是第二层能力，非第一入口
- 建设目标（对应调研缺口）：优先补齐慢特病办理、异地医保、费用解释三类最高频/最高价值场景

## P5 · 三、建设基础与核心优势
- **章节标题**：三、建设基础与核心优势
- **页面标题（结论先行）**：**依托医保核心平台建设积淀，我们具备他人短期难以复制的可信能力**
- 1. **医保业务 know-how**（来源 `docs/specs/13` 第一章）：北京市医保核心平台建设团队，深谙医保业务规则 / 结算 / 费用计算逻辑；已把多年业务代码沉淀为**可解释规则资产**
- 2. **可演进知识底座**：政策知识管线重构 P0→P10，M1–M6 达成；结构化事实 + 字段级溯源 + 质量门禁 + schema 可演化
- 3. **安全三层防线**（来源 `docs/specs/沙箱能力对标分析`）：鉴权 + 脱敏 + 高风险拦截，全链路审计，适配器防腐层（Agent 不直连 HIS/EMR）
- 4. **工程纪律可审计**：四条硬约束（领域语言统一 / 解耦防腐 / 来源可追溯 / 高风险拦截）——经得起领导与监管推敲
- 5. **真实数据验证**：281 验证用例通过（semantic 139 + rule 142，含 Milvus 真集）
- 优势凝练：**医保业务 know-how × 可信工程纪律 × 真实数据验证 = 别人短期拼不出的组合**

## P6 · 四、技术架构与核心能力
- **章节标题**：四、技术架构与核心能力
- **页面标题（结论先行）**：**构建"可解释、可溯源、可回滚"的技术底座，以工程纪律筑牢可信**
- 四层架构体系（SaaS / PaaS / DaaS / 接入与基础设施）+ PaaS 七类服务域（接入安全 / 会话上下文 / 智能编排 / 模型服务 / 知识服务 / 业务适配 / 任务闭环）
- 主线突破：政策知识管线"**平行建新通路 → 最后一把灰度切换**"，生产零停摆、可随时回滚（M1–M6 已达成，M7 价值兑现点）
- 边界纪律（对应"坚决不做"，来源 `docs/specs/13` 第六章）：不替代结算/事前审核/DRG/病案/费用调整；高风险动作一律拦截转人工确认；AI 输出必带 citations 或声明 uncertainties
- 核心能力落点（对应调研 D1–D6）：费用解释 Skill / 结算计算复现 / 政策知识库（D4 7条 + D5 14种 + D6 9种）/ 办理流程指引 / 高风险拦截（均已实现或已规划）
- 收口：用工程纪律把"可解释、可溯源、可回滚"做成默认能力，而非项目期承诺
