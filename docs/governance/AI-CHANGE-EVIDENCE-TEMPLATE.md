# AI 改动证据包模板

> 适用范围：`hospital_medical_insurance_agent` 项目  
> 当前状态：v1.0  
> 文档定位：每次 AI 参与生成或修改代码时，必须随改动附带的证据清单  
> 配套文档：`AI-CODING-GOVERNANCE.md` / `AI-CODING-MODULE-BOUNDARIES.md`

---

## 使用说明

本模板用于回答三个核心问题：

1. **这次改了什么、为什么改、边界在哪**（认知交付）
2. **怎么验证这次改动是安全的**（质量证据）
3. **出问题时怎么回滚、影响面多大**（故障收敛）

提交前，在 PR 描述或 commit body 中逐项填写。**不允许留空**——如某项不适用，必须明确说明理由。

## 八、一票否决自检

> 逐项确认，任一项为"是"则本次改动不得进入主干。

| 否决条件 | 是否触发 |
|----------|----------|
| 修改红区但无人工先行设计说明 | 否 |
| 引入跨层调用，绕开既有统一入口 | 否 |
| 涉及高风险动作但未进入人工确认链路 | 否 |
| 没有异常分支测试且无合理豁免理由 | 否 |
| 缺失来源引用、脱敏、权限边界或不确定性声明 | 否 |
| 通过补丁绕过现有规范，而非沿既有职责扩展 | 否 |
