# PR Reviewer 检查清单

> 适用范围：`hospital_medical_insurance_agent` 项目  
> 当前状态：v1.0  
> 文档定位：人工 Review 操作手册，在没有 CI 自动化时作为唯一硬卡点  
> 配套文档：`AI-CODING-GOVERNANCE.md` / `AI-CODING-MODULE-BOUNDARIES.md` / `TEST-VERIFICATION-MATRIX.md`

---

## 1. Reviewer 快速判定法（30 秒初筛）

按以下顺序快速筛查，任一步发现明显缺失，可直接退回要求补证据，不必进入逐行细读：

| 步骤 | 检查内容 | 不通过则 |
|------|---------|----------|
| ① 看目录 | 改动是否落在合理区域？是否触及红区？ | 退回，要求说明边界 |
| ② 看风险 | PR 标注的风险等级是否正确？ | 退回，要求重新标注 |
| ③ 看边界 | 是否沿用既有统一入口（adapters/、model_service/、risk_control/）？ | 退回，要求修正 |
| ④ 看证据 | 是否补了对应的测试？是否说明异常分支？ | 退回，要求补证据 |
| ⑤ 看回滚 | 如果上线出错，能不能快速撤回？影响面多大？ | 退回，要求补说明 |

## 2. 按风险等级分级 Review

### 2.1 R1 绿区 Review（轻量）

**Review 重点**：

- [ ] 目录是否正确（属于绿区吗？）
- [ ] 是否偷穿基础设施边界（skill 直接连 DB 等）？
- [ ] skill 是否保持自包含？
- [ ] 文档是否与代码现状一致？

**不必审的**：代码风格、低风险样板代码的逐行通读。

**过关标准**：目录对、边界对、自包含。

### 2.2 R2 黄区 Review（标准）

**Review 重点**（R1 全部 +）：

- [ ] 前端改动是否修对了页面路径？（查 `AGENTS.md` §排障零步骤）
- [ ] 流式问题是否先确认了数据层（curl），再改的渲染层（CSS/TSX）？
- [ ] 可观测性埋点是否真正接入应用入口，而非只写骨架？
- [ ] 管理端改动是否说明了权限与回滚？

**过关标准**：R1 全部通过 + 数据时序可验证 + 观测点可追踪。

### 2.3 R3 橙区 Review（严格）

**Review 重点**（R2 全部 +）：

- [ ] 测试是否按 T1 → T2a → T2b 串行通过？
- [ ] 是否引入了第二套编排路径但未清理旧路径？
- [ ] 异常分支是否可证明（有测试 + 有日志）？
- [ ] 高风险动作是否仍走 `waiting_human_confirmation` 链路？
- [ ] 模型调用是否仍通过 `model_service/gateway` 统一入口？
- [ ] 知识输出是否携带 `citations` 或 `uncertainties`？

**过关标准**：R2 全部通过 + 串行测试全部绿 + 异常路径可证明 + 无跨层耦合。

### 2.4 R4 红区 Review（最高标准）

**Review 重点**（R3 全部 +）：

- [ ] 是否有**人工先行设计说明**？（没有则直接退回，不进入逐行审查）
- [ ] 通用语言字典（`src/domain/AGENTS.md`）是否同步更新？
- [ ] 数据库变更是否附带回滚脚本？
- [ ] 权限变更是否有拒绝路径断言？
- [ ] 高风险策略变更是否经过安全评审？

**过关标准**：R3 全部通过 + 人工设计说明存在且完整 + 回滚策略明确 + 兼容性已验证。

## 3. 各模块 Review 速查

| 模块 | 关键审查点 | 常见 AI 越界行为 |
|------|-----------|-----------------|
| `src/domain/` | 通用语言一致性、聚合边界 | 自行新增领域概念、修改枚举值 |
| `src/data_platform/storage/` | Schema 变更是否可逆、迁移脚本 | 自主改表结构、改主键策略 |
| `src/security/` | 高风险链路是否完整、拒绝路径 | 降低拦截门槛、绕开审计 |
| `src/runtime/api/` | 路由是否收口、协议是否兼容 | 新增旁路入口、改流式事件格式 |
| `src/runtime/` 其他 | 是否引入第二套路径 | 双路径并存、调试分支遗留 |
| `src/model_service/` | 调用是否统一入口 | 业务模块绕过 gateway 直接调模型 |
| `src/knowledge_extension/` | 答案是否可追溯 | 无 citations 的确定性输出 |
| `src/adapters/` | 是否只做翻译不做决策 | 在适配器中夹带业务判断 |
| `src/skill_infra/` | skill 权限是否扩大 | 打开全权限执行、绕过安全层 |
| `skills/` | 是否保持自包含 | 直接连 DB、调外部系统 |
| `src/apps/` | 修的是否是用户实际在用的路径 | 修 A 页面但用户在 B 页面 |

## 4. Review 决策速查

| 发现的问题 | 决策 |
|-----------|------|
| 红区改动但无设计说明 | **直接退回**，不进入逐行审查 |
| 跨层调用（绕过 adapters、model_service、risk_control） | **直接退回** |
| 高风险动作未进入确认链路 | **直接退回** |
| 测试证据缺失且无合理豁免 | **退回，要求补证据** |
| 可观测性缺失且无合理豁免（R3+） | **退回，要求补埋点** |
| 目录边界正确但实现细节可优化 | **可合并 + 提 follow-up issue** |
| 代码风格微差异 | **忽略**，不阻塞合并 |

## 5. 审查节奏建议

| 风险等级 | 建议审查时间分配 | 逐行阅读范围 |
|----------|-----------------|-------------|
| R1 | 5-10 分钟 | 仅边界和入口 |
| R2 | 10-20 分钟 | 核心逻辑路径 |
| R3 | 20-40 分钟 | 全部改动 + 异常分支 |
| R4 | 40+ 分钟 + 设计评审 | 全部改动 + 设计文档 |

## 6. 与 PR 模板的对接

| PR 模板字段 | Reviewer 对应检查项 |
|------------|-------------------|
| 风险等级标签 | §2 分级 Review 标准 |
| 验证证据 | §2 对应等级的测试通过要求 |
| 异常分支 | §2.3/R3 —— 异常路径可证明 |
| 可观测性 | §2.2/R2 —— 观测点可追踪 |
| 一票否决自检 | §4 —— 触发任一即直接退回 |
| 回滚说明 | §2 对应等级的回滚要求 |
