## 3. 修订后落地方案（回归 P2-P5 编号）

### 阶段一：受控查询引擎 + 指标运营化（P2 前置，P3 核心，~2.5 周）

| 任务 | 内容 | 验收 |
|---|---|---|
| 1.1 指标治理字段补齐 | `semantic_metrics` 增列（中文名/同义词/兼容维度/默认时间角色/刷新频率/权限等级/负责人/审核人，CREATE+ALTER 双写）+ portal 录入界面 + §11 首批运营指标录入（首个闭环 + ~20 个） | 每个发布指标 15 项治理字段齐备；未发布指标不可被查询 |
| 1.2 `query_planner` 受控聚合引擎 | 指标+维度+筛选+时间→SQL（仅限 `mz_trade/mz_fee_item` 发布批次 + 语义版本锁定 + 权限等级过滤）；越权/越界元素 403/404；查询计划可解释 | 设计 §10：受控语义查询 + 查询理解展示；就诊人次保持 unavailable |
| 1.3 可信问题库 | 新表（标准问题/同义/角色/查询计划/预期特征/审核人/版本）+ 匹配引擎（优先匹配可信问题，长尾走受控语义生成）+ 管理界面 | §14 规格；可信问题结果 100% 正确门槛 |
| 1.4 治理看板 | 数据治理中心内嵌：批次→投影→指标血缘 + 同步 P95/质量门 SLA | 任一指标可溯源到数据批次与语义版本 |

### 阶段二：P2 门诊结算核验（~2 周，按既有基线修订执行）

九 Profile、Decimal 勾稽、字段四态、政策证据、回归矩阵（基线计划已写好，仅按 P0/P1 冻结事实做最小修订）。

### 阶段三：P3 运营受控问数 + 运营指导（~2 周）

指标卡/图表/表格/下钻前端（消费阶段一引擎）；**运营仪表盘包**（科室/险种/趋势/TopN + 周报订阅 + AI 异动解读带 citations）——这就是"单独提供运营指导"的产品面。

### 阶段四：P4 统一助手（~1.5 周）

`/assistant/stream` 意图路由（政策咨询/门诊核验/运营指标），前端不要求结算 ID；复用 policy-qa 会话骨架。

### 阶段五：P5 上线加固（按医院 SSO 排期）

## 4. 调研结论在此方案中的落点（不重复造轮子）

- **不引入**：Airbyte/DataX/Debezium（接入已自研上线）、Cube/WrenAI 引擎（语义层库表界面已建）、Dify（skill 体系+模型网关已有）、DataEase（GPL）、Superset（先自研仪表盘）
- **借鉴落地**：SuperSonic 管线形态 → 阶段一 1.3 匹配引擎结构；WrenAI 版本化评审 → 已有提议流沿用；SQLBot 术语/示例校准 → 可信问题同义表达运营；RagFlow 表格解析 → P2 政策证据升级
- **保留差异化**：契约同步+医保码表值域+政策引用规范+金额 Decimal 勾稽——这些开源项目都没有
