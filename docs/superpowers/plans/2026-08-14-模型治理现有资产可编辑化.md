# 模型治理现有资产可编辑化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将只读台账中的现有提示词、模型档案和路由规则显式导入为可编辑治理草稿，并补齐提示词、模型的关键编辑与草稿删除能力。

**Architecture:** 新增一个只读“当前配置 → 治理资产”转换器，由现有治理服务执行幂等导入；存储层只增加带 revision 的草稿删除。Portal 复用现有工作区和 API 客户端，增加导入按钮及缺失字段编辑，不改变运行时配置来源。

**Tech Stack:** Python 3.12、FastAPI、Pydantic v2、PostgreSQL、Next.js 16、React 19、TypeScript、Vitest。

---

## 文件职责

- `src/model_service/governance_import.py`：把当前提示词、模型和路由快照转换为治理资产，不写存储。
- `src/model_service/governance_service.py`：幂等导入和草稿删除业务门禁。
- `src/data_platform/storage/model_governance/{ports,in_memory,postgres}.py`：revision 安全的草稿删除。
- `src/runtime/api/model_governance_{schemas,routes}.py`：导入和删除端点的类型化契约。
- `src/apps/portal/src/lib/model-governance-api.ts`：导入、删除客户端与 DTO。
- `src/apps/portal/src/components/model-governance-workspace.tsx`：导入入口、完整提示词/模型字段和删除交互。

- [ ] **Step 3: 实现最小转换器和删除契约**

转换器输出 `list[GovernanceAssetContent]`；模型 ID 使用可读的规范化名称，路由引用同一模型 ID。提示词仅保存稳定指令和显式变量，动态业务内容保持变量。`PromptAssetContent.system_prompt` 允许空字符串，以精确保留当前仅发送 user message 的调用。

存储删除签名：

```python
def delete_draft(self, draft_id: str, *, expected_revision: int) -> GovernanceDraft: ...
```

内存实现用现有 `RLock` 原子检查 revision 后删除；PostgreSQL 使用 `DELETE ... WHERE draft_id=%s AND revision=%s RETURNING *`。

- [ ] **Step 4: 实现服务幂等导入和删除门禁**

```python
def import_current_assets(self, *, actor: str) -> GovernanceImportResult: ...
def delete_draft(self, draft_id: str, *, expected_revision: int) -> GovernanceDraft: ...
```

导入跳过已存在 `asset_id` 的草稿或版本；删除拒绝 approved 草稿和已有版本的资产。
