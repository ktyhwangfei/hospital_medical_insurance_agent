# 后台管理真实资产版本与模型接入设计

日期：2026-08-17

## 1. 目标

把 `/model-governance` 从“代码台账 + 独立治理草稿”升级为运行时真实配置的资产中心：用户可以查看实际提示词内容，基于当前生效版本创建可编辑新版本；可以配置真实的 OpenAI-compatible 外部模型地址和 API Key；提示词、模型与路由发布后对新请求实际生效。

[来源：`src/apps/portal/src/components/model-governance-workspace.tsx` 当前将代码资产、治理草稿和发布记录分开展示。]

[来源：`src/model_service/governance_assets.py` 与 `src/model_service/governance_service.py` 已提供草稿、审核、不可变版本、活动发布和回滚模型。]

[来源：`src/model_service/gateway.py` 当前仍从 `ModelServiceConfig` 和静态 `ModelRouter` 读取模型、地址与路由。]

[决策：用户确认发布后的提示词、模型和路由必须成为运行时真实配置源。]

本设计取代 `2026-08-14-后台管理信息架构与编辑抽屉设计.md` 中“不修改后端 API、数据库和运行时”的旧范围；旧文档的导航、标签和右侧抽屉决策继续有效。

## 2. 已确认决策

1. 页面采用方案 A“资产中心”：每个资产在列表中只出现一次，详情抽屉集中显示当前生效内容、未完成草稿和版本历史。
2. 当前生效版本不可直接编辑；“新建版本”复制当前生效内容生成草稿。
3. 新版本必须依次完成编辑、校验、审核和发布；发布前旧版本持续生效。
4. API Key 使用应用主密钥加密后保存到数据库，不使用明文列。
5. 模型草稿允许先保存，但发布前必须通过与该草稿内容绑定的连接测试。
6. “模型档案”统一改名为“模型”。
7. 所有角色当前均可查看页面；细粒度查看、编辑、审核和发布权限后续单独实施。

## 3. 现状与问题

### 3.1 已有能力

- `GovernanceDraft` 支持乐观锁 revision 和编辑、校验、待审核、已审核状态。
- `GovernanceVersion` 保存不可变内容与内容哈希。
- `GovernanceRelease` 保证同一资产、同一环境最多一个活动发布，并支持回滚。
- PostgreSQL 和内存存储均实现相同治理端口。
- Portal 已有右侧编辑抽屉、错误保留、审核和发布交互。

### 3.2 主要缺口

- 提示词台账只显示名称、来源和参数，看不到完整系统提示词与用户模板。
- 已发布草稿仍显示“编辑”，没有“当前生效版本只读、新建版本可编辑”的语义。
- Portal 没有读取和展示 `GovernanceVersion` 的版本历史。
- `ModelProfileAssetContent` 只有 `credential_ref`，没有真实外部 API 地址，也没有密钥密文存储。
- 治理发布明确标记为“尚未接入运行时”，`ModelGateway` 继续读取环境变量和静态路由。
- 概览存在两组统计，“代码当前值”“治理库 revision”“发布状态”并列，用户难以判断实际生效配置。

## 4. 核心资产与版本模型

### 4.1 稳定资产与不可变版本

- `asset_id` 是提示词、模型和路由的稳定业务标识。
- 活动发布指向不可变 `GovernanceVersion`；活动版本只能查看、复制或回滚。
- `GovernanceDraft` 增加 `base_version_id`，记录草稿基于哪个历史版本创建；首次从代码或环境变量纳管时允许为空。
- `GovernanceDraftStatus` 增加 `published`。发布成功后原草稿转为只读已发布状态，不继续作为可编辑草稿复用。
- 同一资产最多存在一个未完成草稿；未完成状态包括 `editing`、`validated`、`review_pending` 和 `approved`。重复创建返回 409，并把现有草稿返回给前端继续编辑。
- 版本号只在发布时分配。首次治理库发布为 v1，此后按资产递增。

### 4.2 当前代码与环境变量回退

- 尚无治理库活动发布时，运行时继续使用当前代码提示词、环境变量模型和静态路由，避免升级后中断业务。
- UI 将这类资产标记为“代码默认值（运行中）”或“环境配置（运行中）”，不伪装成治理库 v1。
- 用户点击“新建版本”时，服务端复制当前真实回退值生成草稿；模型 API Key 在服务端复制并加密，明文不经过读取响应返回浏览器。
- 一旦某资产存在活动治理版本，该资产不再因治理库读取、解密或校验失败而静默回退旧配置；运行时明确报配置不可用，防止页面显示与实际调用不一致。

### 4.3 环境

- 沿用 `dev` 和 `test` 两个治理环境，各自维护独立活动发布。
- 新增 `MODEL_GOVERNANCE_ENV` 指定运行时读取环境，本地默认 `dev`。
- Portal 顶部展示当前环境选择器，所有“当前生效”判断均以所选环境为准。

## 5. 提示词真实内容与运行时解析

### 5.1 内容展示

提示词详情返回并展示：

- 系统提示词全文。
- 用户提示词模板全文。
- 变量名称、必填性和说明。
- 输出模式、场景和模型类型。
- 当前来源、生效版本、内容哈希、发布时间和发布人。
- 未完成草稿及完整历史版本。

当前生效内容使用只读代码块显示；只有草稿抽屉提供输入控件。

### 5.2 运行时绑定

- 增加轻量 `PromptResolver`，以 `asset_id` 解析所选环境的活动提示词；没有活动发布时使用调用方提供的代码默认值。
- 现有提示词调用点逐个改为通过 `PromptResolver` 获取模板，仍由原调用点负责传入变量和调用 `model_service/gateway`。
- 当前登记的资产包括 `intent.classify`、`intent.discriminate`、`skill.route`、`policy_qa.intent_detect`、`policy_qa.patient_explain`、`policy.extract.schema`、`policy.extract.legacy`、`policy.fact_extract`、`policy.synonym_discovery`、`policy.domain_discovery` 和 `skill.settlement_explain`。[来源：`src/model_service/governance_import.py::_prompt_assets`]
- 实际可达调用点完成绑定后标记为“运行时生效”；无法定位真实调用入口的遗留资产显示“未绑定运行时”，不得显示为当前生效。
- 模板变量继续使用现有安全校验，未声明变量、缺少必填变量和不安全格式均阻止发布。

## 6. 模型、密钥与连接测试

### 6.1 模型内容

`ModelProfileAssetContent` 调整为真实 OpenAI-compatible 模型配置：

- 显示名称与稳定资产标识。
- `provider_id`，当前只支持 `openai_compatible`。
- `base_url`。
- `model_name`。
- 内部 `credential_id` 引用。
- `timeout_seconds`。
- `temperature`。
- `max_tokens`。
- `enabled`。

生产环境要求 HTTPS；开发环境允许 `localhost` 和 `127.0.0.1` 使用 HTTP。URL 禁止包含用户名、密码、查询参数或 fragment。

### 6.2 密钥加密存储

- 新增 `model_governance_credentials` 表，保存 `credential_id`、认证加密密文、掩码、密钥版本、创建人和创建时间。
- 新增并声明 `cryptography` 依赖，使用 Fernet 认证加密；主密钥由 `MODEL_GOVERNANCE_MASTER_KEY` 提供，数据库不保存主密钥。
- 主密钥缺失或格式错误时，保存 Key、复制环境 Key、连接测试和使用治理模型均失败关闭，不允许明文降级。
- 创建模型时 API Key 必填；基于现有版本新建草稿时，留空表示沿用当前密钥，填写新值则创建新的不可变凭据记录。
- 读取接口只返回 `configured` 和类似 `••••7a9c` 的掩码，不返回密文、明文或可用于解密的内部字段。
- API Key 不进入日志、审计详情、异常文本、内容预览或内容哈希的明文输入；版本内容哈希包含不可变 `credential_id` 引用。

### 6.3 连接测试门禁

- 增加模型草稿连接测试端点，服务端解密 Key 后发送不含患者数据的最小聊天请求。
- 测试结果保存草稿 ID、草稿内容哈希、成功状态、延迟、操作者和时间；不保存上游响应正文。
- 地址、模型名、Key、超时或启用状态变化会改变内容哈希，使旧测试自动失效。
- 模型草稿可以在未测试时保存，但校验和发布必须要求当前内容哈希存在成功测试。
- 上游认证失败、超时、限流和服务错误继续使用 `model_service/exceptions` 分类，不在错误消息中带出 Key。

## 7. 路由与 ModelGateway 生效

- 路由编辑器从文本输入改为模型选择器，只列出目标环境中已发布、启用且连接测试有效的模型。
- 路由发布继续校验主模型和备用模型已在目标环境发布。
- `ModelGateway` 通过运行时治理解析器一次取得场景路由、主模型、备用模型、参数、地址和解密后的凭据。
- 治理环境没有活动模型或路由时，沿用现有 `ModelServiceConfig` 和静态 `ModelRouter`。
- 一旦活动治理路由存在，后续新请求使用治理版本；发布和回滚不修改正在执行的请求。
- 流式与非流式调用共享相同解析路径，避免两种调用读取不同配置。

## 8. API 设计

沿用 `/api/v1/medical-insurance-ai-agent/model-governance` 前缀。

### 8.1 查询

- `GET /assets?environment=dev&asset_type=prompt`：返回一项资产一条摘要，包含当前来源/版本、未完成草稿、运行时状态和最后更新时间。
- `GET /assets/{asset_id}?environment=dev`：返回当前生效内容、未完成草稿、历史版本、运行时绑定和模型凭据掩码。
- `GET /releases`：保留跨资产发布审计记录。
- `GET /published-snapshot`：保留运行时活动快照接口，但模型内容经过内部解析后才可取得凭据。

### 8.2 写入

- `POST /assets/{asset_id}/drafts`：基于当前活动版本或真实回退值创建唯一未完成草稿。
- `POST /drafts`：创建没有历史版本的新资产。
- `PATCH /drafts/{draft_id}`：保存草稿，不允许修改资产标识和类型。
- `POST /drafts/{draft_id}/validate`：执行模板、模型和路由校验。
- `POST /drafts/{draft_id}/connection-test`：仅模型草稿可用。
- 审核、发布和回滚端点保持现有路径与职责。

所有响应继续使用类型化响应模型和统一 `{error_code, message, audit_event}` 错误结构。

## 9. 页面信息架构

### 9.1 顶层

标签保持五项：

1. 概览
2. 提示词
3. 模型
4. 路由规则
5. 发布记录

页面顶部展示环境选择器和“运行时已接入/配置不完整”状态。开发身份切换移入仅开发环境显示的次要“开发工具”区域，不占用主标题栏。

### 9.2 概览

- 只保留一组指标：生效提示词、生效模型、有效路由、待处理草稿。
- 展示需要处理的事项：未绑定提示词、连接测试失败、路由引用无效、待审核草稿。
- 删除“发布内容尚未接入运行时”横幅和重复代码资产计数。
- 来源与不确定性保留，但改为可展开的诊断区，不与日常操作争夺首屏。

### 9.3 提示词

- 每个资产一行，显示名称、标识、场景、当前生效版本/来源、草稿状态和更新时间。
- 没有草稿时主动作是“新建版本”；已有草稿时主动作是“继续编辑”。
- 详情抽屉包含“当前生效”和“版本记录”两个标签。
- 当前生效页只读展示真实全文；版本记录显示版本号、状态、发布时间和回滚动作。
- 新建版本抽屉复用现有提示词表单与焦点管理。

### 9.4 模型

- 列表显示模型名称、端点主机、模型名、凭据状态、连接状态、当前版本和草稿。
- 新建/编辑版本抽屉配置真实 API 地址、模型名、API Key、超时、温度、最大 tokens 和启用状态。
- API Key 使用密码输入框；编辑时留空沿用，不回填明文。
- “测试连接”与“保存草稿”分离；测试结果在抽屉内联展示。

### 9.5 路由与发布记录

- 路由主模型和备用模型使用选择器，不再手填资产 ID。
- 发布记录保留跨资产时间线；单资产版本历史不再依赖发布记录页查找。

### 9.6 状态与可访问性

- 加载使用与列表结构一致的骨架状态；失败使用内联警报，不伪造空数据。
- 抽屉保存或测试失败时保留用户输入。
- 390px 宽度无横向页面溢出，宽表在自身容器内滚动或切换为紧凑卡片。
- 所有抽屉保持 `aria-modal`、可访问名称、Escape 关闭和焦点恢复。

## 10. 错误与并发策略

- 修改活动版本：409 `MODEL_GOVERNANCE_ACTIVE_VERSION_IMMUTABLE`。
- 同一资产已有未完成草稿：409 `MODEL_GOVERNANCE_DRAFT_EXISTS`。
- 草稿 revision 变化：409 `MODEL_GOVERNANCE_CONFLICT`。
- 模板、URL、模型或路由校验失败：422 `MODEL_GOVERNANCE_VALIDATION_FAILED`。
- 主密钥不可用：503 `MODEL_GOVERNANCE_KEY_UNAVAILABLE`。
- 连接测试失败：502 `MODEL_CONNECTION_FAILED`，草稿不丢失。
- 当前模型内容没有匹配的成功测试：409 `MODEL_CONNECTION_TEST_REQUIRED`。
- 发布和回滚继续使用事务保证活动版本原子切换。

## 11. 迁移与兼容

1. 先以增量 SQL 创建凭据和连接测试表，并为草稿增加 `base_version_id` 与 `published` 状态支持。
2. 现有代码提示词、环境模型和静态路由继续作为真实运行时回退值，不自动绕过审核发布为 v1。
3. 现有导入草稿保持可读取；首次发布后进入正式版本序列。
4. Portal 切换为资产聚合接口后删除“代码当前值/治理库 revision”双轨展示。
5. PromptResolver 和运行时治理解析器接入后再删除“尚未接入运行时”文案。
6. 回滚只切换活动版本指针，不删除后续版本、草稿、审批、凭据或连接测试证据。

## 12. 验收与验证

按项目硬性顺序执行单元测试、API 测试和 Flow 测试，再执行 Portal 与真实浏览器验证。

### 12.1 单元测试

- 活动版本不可编辑，新建版本正确复制当前内容。
- 同一资产只允许一个未完成草稿。
- 发布后草稿关闭，新版本号递增，回滚恢复目标版本。
- PromptResolver 在有活动版本时读取数据库，无活动版本时读取代码默认值。
- Fernet 加密往返正确，错误主密钥失败关闭。
- 序列化 DTO、日志和异常不包含 API Key 明文。
- 连接测试证据与内容哈希绑定，配置变化后失效。
- ModelGateway 流式和非流式调用解析同一活动路由和模型。

### 12.2 API 测试

- 资产列表和详情返回真实提示词内容、当前版本、草稿和历史版本。
- 当前生效内容没有 PATCH/编辑入口。
- 新建版本、校验、审核、发布和回滚状态流正确。
- 模型创建响应、读取响应和错误响应不泄露 Key。
- 未通过连接测试的模型无法发布。
- 主密钥缺失、上游认证失败、超时和 revision 冲突返回标准错误。

### 12.3 Flow 测试

- 提示词：读取代码默认值 → 新建版本 → 编辑 → 校验 → 审核 → 发布 → 新请求实际使用新内容 → 回滚后恢复。
- 模型：创建外部模型 → 密文入库 → 连接测试 → 审核发布 → 路由发布 → ModelGateway 实际使用该地址和模型。
- 运行时配置损坏时明确失败，不静默回退造成页面与实际调用不一致。

### 12.4 Portal 与浏览器

- 提示词资产始终显示真实正文，生效版本只读，新版本草稿可编辑。
- “模型档案”已统一为“模型”，外部 API 和 Key 输入行为符合设计。
- 概览无重复统计和“尚未接入”旧文案。
- 路由通过模型选择器配置。
- 定向 Vitest、ESLint、Next.js 生产构建和 Chromium E2E 通过；真实浏览器验证 1440px 与 390px。

## 13. 分阶段实施

### 单元一：提示词版本与运行时

完成资产聚合、活动版本只读、新建版本、版本历史、PromptResolver、可达调用点接入和提示词 Portal。

### 单元二：真实模型与密钥

完成模型字段、凭据加密存储、连接测试、运行时治理解析器、ModelGateway 接入和模型 Portal。

### 单元三：页面收口

完成路由选择器、概览去重、发布记录整理、开发工具降级、响应式和全链路验证。

每个单元独立测试、提交和回滚；单元二不依赖单元三的视觉收口才能验证运行时模型调用。

## 14. 明确不做

- 本阶段不实现医院 SSO、RBAC 或细粒度权限管理。
- 不接入 Vault/KMS；主密钥由部署环境变量提供。
- 不支持 Anthropic 等非 OpenAI-compatible 私有协议。
- 不提供 API Key 明文查看、下载或导出。
- 不增加批量编辑、A/B 实验、提示词自动优化或在线 Playground。
- 不增加新的前端组件库或动画依赖。
