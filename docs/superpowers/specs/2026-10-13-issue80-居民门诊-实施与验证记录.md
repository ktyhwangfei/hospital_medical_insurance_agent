## 三、问题修复记录（原因 + 范围）

### 缺陷修复 1：诊疗目录限额列未映射（医事服务费 10 笔无法核对）
- **现象**：17/18 类医事服务费交易全部 SELF_PAY_RULE_PARAM_MISSING（sfxmdj=2 且 zfbl=0 且限额存在却无法分解）。
- **根因**：`record_query_mappings.py` 的 `cat_svc_unit_price_limit` 映射为空串，注释称「2026-09-28 实测 yb_xzzlfwxm 无此列」——**schema 核实漏报**，`xb` 列实际存在（561 行有值，含医事服务费限额 40/60）。
- **修改**：`src/adapters/data_supply/record_query_mappings.py` 一处：`cat_svc_unit_price_limit` → `"xb"`。
- **影响面**：职工链路零影响（职工 81 笔 ItemType=1/2 中 sfxmdj=2 且 zfbl 空的行数=0，实证；回归 78/81 不变）。

### 缺陷修复 2：sfxmdj=2 且 zfbl=0 误走比例分支
- **现象**：zfbl=0（语义=不按比例，issue80「B_bxbs=4 或 Null 按单价限额」）被当作 0% 比例分解（in=fee），与账面限额拆分不符（医事服务费 50 元应为 40/10，算出 50/0）。
- **修改**：`catalog_split.py::_split_service` 一处：比例分支条件 `svc_ratio is not None` → `svc_ratio is not None and svc_ratio > 0`；比例缺失或为 0 且有单价限额时落入限额分支。
- **影响面**：职工零影响（该路径职工从未触发，实证 + 回归验证）。

### 缺陷修复 3：材料缺结算事实限价分支（人工晶体超限）
- **现象**：人工晶体 1935 元（结算时限价 SP_SCALE=1835）按 2023 门槛规则 80% 算 1548，账面 1835（限价内全额纳入）。
- **修改**：`catalog_split.py::_split_material` 新增限价分支：SP_SCALE>0 且单价超限 → 限内纳入、超限自担（类推药品 D17，候选口径 MATERIAL_PRICE_LIMIT_RULE_CANDIDATE）；退费行（单价正、数量负）同样成立。
- **影响面**：职工零影响（职工 81 笔无 SP_SCALE>0 且超限材料行；回归验证）。

### 能力扩展 4：集采药品 SP_SCALE>0 优先限价公式
- **现象**：居民 240506 组乌拉地尔（集采、SP_SCALE=9.8、单价 100）内核按集采 a_xbbl 口径算 90/10，账面 8.82/91.18（issue80 公式：SP_SCALE>0 时 FeeIn=限价−限价×zfbl、FeeOut=超限+限内自付）。
- **修改**：`catalog_split.py::_split_drug` 新增结算事实限价统一优先分支（SP_SCALE>0 且单价超限 → 限价公式，集采/非集采一致）。
- **影响面**：职工零影响（职工 81 笔集采超限价行 SP_SCALE 全为 0，实证；回归验证）。

### 行为变更 5：居民退费交易支持（职工保持拦截）
- **原因**：居民 59 笔中 13 笔退费（22%），职工式拦截会使全量准确率上限仅 78%；mz.docx 居民退费规则明确（ROP-REF-001/002），区间重叠公式实证 8 笔正常退费全闭合。
- **范围**：仅居民内核（resident_deductible/resident_big_pay 区间+clamp 公式）；职工内核 `UNSUPPORTED_REVERSAL_OR_NEGATIVE` 拦截不变。

### 行为变更 6：快照扩展渠道观测列
- **范围**：`ObservedSettlementAmounts` 加 `bigill_pay`/`civil_pay`（默认 None）；`outpatient_decomposition_queries` 的 `_TRADE_COLUMNS` 加两列读取、`build_snapshot` 组装；映射加 `op_bigill_pay→T_BigillPay`、`op_civil_pay→NT_CivilPay`。
- **影响面**：职工/门特内核不消费新字段（默认 None）；职工 81 笔、门特 mz 回归均与基线一致。
- **用途**：仅渠道存在性检测与账面恒等核对，不作同字段重算输入（遵守「禁止观测值反推」）。

### 行为变更 7：内核分发与 profile 注册
- `integration.py`：`_PROFILE_EXACT_MATCH` 单值 → `_PROFILE_MAP` 映射表，注册 `("城乡居民基本医疗保险","普通门诊")→("resident","outpatient")`。
- `snapshot_service.py`：第 7 步按 `_KERNEL_BY_PROFILE` 分发内核；未注册组合 fail-closed（UNSUPPORTED_PROFILE，附读元数据 citation）。
- `TradeAnchor` 加 `cure_type`/`fund_type` 原值字段（居民通道分流依据；职工内核不消费）。
