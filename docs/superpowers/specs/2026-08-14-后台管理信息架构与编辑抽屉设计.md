# 后台管理信息架构与编辑抽屉设计

日期：2026-08-14

## 1. 目标

调整现有模型与提示词治理页面的信息架构和编辑交互，使后台入口定位清晰、重复信息集中展示，并让用户在编辑具体资产时始终保留列表上下文。

[事实依据：`src/apps/portal/app/layout.tsx` 当前将“模型治理”放在业务导航中部。]

[事实依据：`src/apps/portal/app/model-governance/page.tsx` 当前在治理工作区下方固定展示统计、提示词台账、模型、Provider、路由和来源说明，切换管理标签后这些内容仍重复出现。]

[事实依据：`src/apps/portal/src/components/model-governance-workspace.tsx` 当前把新建/编辑表单固定渲染在列表上方，从列表条目点击“编辑”会让编辑目标与表单脱离。]

## 2. 已确认方案

用户在交互草图中选择方案 A：右侧编辑抽屉。

设计取向为医院信息科使用的受控后台产品界面，延续现有蓝灰色视觉语言。设计参数为变化度 3、动效 2、信息密度 6，不增加新的组件库或动画依赖。

## 3. 导航调整

- 导航名称从“模型治理”改为“后台管理”。
- 页面主标题同步改为“后台管理”，副标题明确其管理提示词、模型档案、路由和发布记录的职责。
- 后台管理入口固定在左侧导航最底部，与业务功能入口形成层级区分。
- 路由继续使用 `/model-governance`，不做 URL 迁移。
- 当前阶段移除前端角色门禁，所有角色均可看到入口并访问页面；细粒度权限管理后续单独设计。

## 4. 页面信息架构

管理页标签调整为：

1. 概览
2. 提示词
3. 模型档案
4. 路由规则
5. 发布记录

“概览”作为默认标签，集中展示：

- 草稿、待审核、已发布和运行时接入状态。
- 当前提示词、模型、路由和 Provider 数量。
- 代码当前值、来源和数量的摘要。
- 参数不一致告警、Provider 凭据状态和待核验说明。
- 导入现有配置入口与“尚未接入运行时”的安全提示。

提示词、模型档案和路由规则标签分别展示对应的代码当前资产清单与治理草稿；即使尚未导入、治理草稿为空，代码资产清单仍必须可见。发布记录只展示发布历史。各资产标签不重复概览的汇总、告警、Provider 凭据和来源说明。

## 5. 编辑抽屉

### 5.1 打开方式

- 点击具体资产的“编辑”后，从右侧打开抽屉。
- 新建资产也使用同一抽屉，保持交互一致。
- 抽屉标题显示操作类型和资产名称；副标题显示资产标识与 revision。
- 列表不滚动、不跳转，用户关闭抽屉后仍处于原列表位置。

### 5.2 布局

- 桌面端抽屉宽度约 560px，覆盖在当前页面右侧，并使用遮罩区分层级。
- 小于 768px 时抽屉占满可视宽度。
- 表单字段继续按现有资产类型动态展示，不改变字段含义和提交 DTO。
- 抽屉支持标题栏关闭、底部取消和保存；按 Escape 可关闭。
- 打开抽屉时焦点进入面板，关闭后焦点返回触发按钮；抽屉使用 `role="dialog"`、可访问名称和 `aria-modal="true"`。

### 5.3 状态与错误

- 保存成功后关闭抽屉，并在原列表位置更新对应资产。
- 保存失败时保持抽屉打开，错误信息显示在表单内，不丢失用户输入。
- 切换标签时关闭抽屉和预览，避免跨资产类型保留错误上下文。
- 忙碌状态禁用重复提交，但仍清晰展示当前正在编辑的资产。

## 6. 最小改动范围

- `src/apps/portal/app/layout.tsx`：后台管理导航名称与底部位置。
- `src/apps/portal/app/model-governance/page.tsx`：页面标题和概览内容边界。
- `src/apps/portal/src/components/model-governance-workspace.tsx`：概览标签、资产标签和右侧抽屉交互。
- 可按职责新增一个模型治理概览组件和一个轻量抽屉组件；优先复用仓库现有组件，禁止增加依赖。
- 更新模型治理 Portal 定向测试。

不修改后端 API、数据库、发布生命周期、模型路由和运行时消费者。

## 7. 风险与控制

- 风险：移动大量概览 JSX 时遗漏现有来源、告警或 Provider 信息。控制：保留现有断言，并新增概览标签范围断言。
- 风险：抽屉遮挡或焦点管理不完整。控制：使用原生按钮、Escape 关闭、焦点恢复和移动端全宽回退。
- 风险：导航仅改变数组顺序但没有真正固定到底部。控制：为后台入口使用独立的底部导航区域，并以源码/组件测试验证。
- 风险：编辑表单迁移后提交 DTO 发生变化。控制：复用现有 `formContent`、`formFromDraft` 和 API 函数，不改数据转换逻辑。

## 8. 验收与验证

1. 所有角色均看到左侧导航最底部的“后台管理”，无需切换到信息科即可访问页面。
2. 页面默认打开“概览”，只展示汇总、告警、Provider 凭据、来源和接入状态，不展示详细资产台账。
3. 提示词、模型档案和路由规则标签在治理草稿为空时仍展示各自的代码当前资产；发布记录只展示发布历史。
4. 导入现有配置后点击某个模型草稿的“编辑”，右侧抽屉显示该模型名称、标识、revision 和原有字段，列表位置不变。
5. 新建资产使用同一抽屉；取消、关闭、Escape 和保存后的状态符合设计。
6. 失败路径先通过 Portal 组件测试复现，再完成实现。
7. 运行模型治理 Portal 定向测试、定向 ESLint 和 Next.js 生产构建；不运行无关测试目录。

## 9. 明确不做

- 不把治理发布结果接入当前业务运行时。
- 不增加搜索、分页、批量编辑或多抽屉并行。
- 不更换视觉主题、字体、组件库或路由地址。
- 不在本阶段新增细粒度权限管理。
