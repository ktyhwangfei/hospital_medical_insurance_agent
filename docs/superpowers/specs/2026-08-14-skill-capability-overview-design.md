# Skill 能力与场景概览设计

## 目标

将 `/skills` 从治理待办工作台改为 Skill 能力与场景概览，让用户无需进入详情即可看清每个 Skill 的能力、业务动作与对象、执行场景，以及每个场景依赖的业务指标。治理状态保留为卡片头部的辅助信息。

## 页面结构

- 顶部导航首项由“治理待办”改为“概览”。
- 页面标题为“Skill 能力与场景概览”，附 Skill、场景和业务指标总数。
- 工具栏提供一个全文搜索框及业务动作、业务对象两个筛选器。
- 每个 Skill 使用一张全宽卡片，4–5 个 Skill 可在同一页面连续浏览，不依赖选择、展开或跳转。
- 卡片头部紧凑展示 Skill 名称、能力描述、动作/对象、版本、治理状态、场景数、指标数和公共指标。
- 卡片主体以响应式网格展示场景：移动端一列，中等宽度两列，桌面三列；单个 Skill 支持最多 10 个场景自然换行。
- 场景块展示场景名称、用途说明和该场景依赖的业务指标；指标使用内联文本，避免标签堆叠。

## 数据口径

- Skill 能力描述来自正式制品 `skill_manifest.yaml` 的 `description`。
- 场景来自 `execution_contract.profiles`。
- 公共指标来自 `execution_contract.common.metric_inputs`。
- 场景指标来自对应 profile 的 `metric_inputs`。
- 指标优先展示 `alias`，缺失时展示 `metric_code`。
- 指标数按公共指标与所有场景指标的唯一 `metric_code` 计数。
- 治理状态沿用 workbench 聚合结果，只作为卡片状态提示，不在概览提供治理操作。

## 数据流

草稿物化时将 `description` 与 `execution_contract` 写入 `skill_manifest.yaml`。版本目录从当前制品快照解析这两个字段，workbench 聚合接口直接返回，前端一次请求加载全部 Skill 并在本地搜索筛选，避免详情页 N+1 请求。

历史制品没有执行契约时返回空契约，卡片明确显示“尚未配置执行场景”，不从旧字段推断或伪造场景。

## 页面状态

- 加载：显示与卡片结构一致的骨架屏。
- 错误：显示错误信息和重试按钮。
- 无 Skill：显示“暂无 Skill”。
- 筛选无结果：显示“没有符合条件的 Skill”并提供清除筛选。
- 无场景：在对应 Skill 卡片显示中性空状态。

## 可访问性与响应式

- 搜索和筛选控件均有可见标签或 `aria-label`。
- 状态信息不只依赖颜色表达。
- 卡片与场景使用语义化标题层级。
- 页面不使用横向滚动；场景网格随视口从三列降为两列、一列。

## 非目标

- 不在概览中复制评测、审批、发布等治理操作。
- 不新增详情抽屉、折叠面板、图表或可视化依赖。
- 不修改旧治理工作台组件，以保护现有治理页面逻辑和未提交改动。

## 验收标准

1. `/skills` 直接展示所有 Skill 卡片，无需点击查看能力、场景和场景指标。
2. 4–5 个 Skill 和每个最多 10 个场景在桌面端保持紧凑、可扫描。
3. 搜索可命中 Skill、场景和指标；动作与对象筛选可组合使用。
4. 新物化 Skill 的能力描述和执行契约贯通制品、目录、workbench API 与前端。
5. 历史 Skill 无执行契约时页面可用且信息诚实。
