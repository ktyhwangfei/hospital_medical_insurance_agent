# 门诊数据治理测试环境就绪判定补充设计

日期：2026-08-31

状态：用户已明确成功条件，作为《门诊数据治理中心与双模式同步设计》的实施补充

## 1. 唯一成功条件

当前测试环境满足以下两项即判定门诊数据底座接入成功：

1. SQL Server 的 `dbo.o_Trade`、`dbo.o_FeeItem`、`dbo.o_Diagnose` 可使用当前凭据读取，且现有门诊契约要求的全部字段可查询；
2. PostgreSQL 可直接初始化门诊表和视图，并可在门诊控制表中完成事务性读写。

CDC 是否开通不参与总体接入成败。CDC 继续单独显示 `未检测 / 等待 DBA / 已就绪 / 配置异常`；只有管理员选择 CDC 同步模式时，`CDC 已就绪` 才是任务启动条件。[来源: 2026-08-31 用户明确“成功唯一条件”]

## 2. 当前环境核验基线

- SQL Server 三张门诊表可读，87 + 20 + 10 个契约字段全部可查询，三表均有数据；
- PostgreSQL 的 6 张门诊表和 2 个查询视图齐全，事务写入后回滚验证成功；
- SQL Server 数据库当前未开启 CDC；
- PostgreSQL 控制面当前尚未登记数据源和同步任务。

核验过程不输出连接串、用户名密码或患者数据。[来源: 2026-08-31 当前测试环境只读及回滚探测]

## 3. 方案选择

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 强化现有控制面 | 升级现有 SQL Server 与 PostgreSQL 探测，复用现有状态字段和页面 | 采用；改动最小且没有重复状态源 |
| B. 新增总体验收服务 | 新增独立 readiness API、持久化状态和页面 | 不采用；与现有数据源/PG 状态重复 |
| C. 自动开启 CDC | 使用测试环境高权限账号执行 CDC DDL | 不采用；CDC 不是成功条件，且数据库级变更仍须 DBA 确认 |

## 4. 后端行为

### 4.1 SQL Server

`POST /data-sources/{source_id}/test` 不再只执行 `SELECT 1`，而是对三张固定源表执行受控的 `SELECT TOP 1` 全契约字段查询。查询结果不返回，仅用于同时验证：

- 登录和数据库连接；
- 三张固定表存在；
- 117 个契约字段存在；
- 当前账号对三张表具有读取权限。

全部通过时沿用 `connection_status=healthy`，安全消息显示“门诊 3 张源表及 117 个契约字段可读”；任一表、字段或读取权限不满足时返回 `source_contract_mismatch`，不回显驱动原始错误。

### 4.2 PostgreSQL

`GET /postgresql/status` 每次执行：

1. 幂等初始化门诊表、索引和视图；
2. 检查 6 张门诊表和 2 个查询视图；
3. 在 `outpatient_sync_checkpoints` 内写入唯一探测记录并在同一事务删除，提交后不保留探测数据。

三步全部通过才返回 `healthy + schema_ready=true`，安全消息明确为“PostgreSQL 门诊结构及读写已就绪”。

### 4.3 启动门槛

- 任意同步模式：源端三表必须已检测为 `healthy`，PostgreSQL 必须可初始化和读写；
- CDC 模式：在上述门槛之外，还必须 `cdc_status=ready`；
- 定时 SQL 模式：不要求 CDC。

## 5. 当前测试环境自动配置

启动前的本地引导脚本复用现有环境变量和 gitignored Docker 环境文件，不新增或回显密码：

1. 确保持久的数据治理主密钥存在；
2. 从当前 `MSSQL_*` / `POSTGRES_*` 配置读取测试环境连接信息；
3. 幂等初始化 PostgreSQL 门诊投影与治理控制表；
4. 幂等登记或更新 `bjybdb` 数据源及其加密凭据；
5. 执行 SQL Server 三表契约检测和 PostgreSQL 读写检测；
6. 数据源首次出现时创建默认的 `scheduled_sql` 草稿任务，不自动启用或执行全量读取。

共享测试凭据优先从当前工作区读取；Orca worktree 缺少 `deploy/docker/.env` 时，通过 Git common-dir 定位主检出目录的同名 gitignored 文件。凭据只进入进程环境和加密存储。

## 6. 页面

- 运行概览顶部显示“数据底座可用 / 未就绪”；
- 医院状态表将“连接”改为“门诊源表”，`healthy` 表示三表和全部契约字段可读；
- CDC 继续作为相邻的独立列展示，未开通时显示“等待 DBA”，不把总体状态改为失败；
- 数据源页展示 SQL Server 安全探测消息和 PostgreSQL 结构/读写状态；
- 页面不展示密码、连接串、患者样本或原始 SQL。

## 7. 验证

严格按 Unit → API → Flow → Portal/E2E 顺序：

1. Unit：三表/字段/权限失败、PG 事务读写、CDC 与总体状态解耦、自动配置幂等和秘密不输出；
2. API：探测响应、概览总体状态、CDC 未开启但定时 SQL 可启动；
3. Flow：从空控制面自动登记当前测试环境，完成两端检测并创建暂停任务；
4. Portal/E2E：页面显示“数据底座可用”、三表可读、PG 已就绪及 CDC 等待 DBA，且配置操作可用。
