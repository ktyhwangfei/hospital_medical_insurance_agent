# 知识资产概览重构设计

**日期**：2026-08-14

**范围**：`/policy-knowledge` 概览页
**状态**：视觉方向已确认，待书面规格复核

## 1. 背景与目标

现有页面以治理流水线、待办卡、统计卡、生命周期、质量和快捷入口平铺信息。相同数字在不同区域重复出现，文档、单元、知识、审核和发布又被当作同一层级，导致用户无法快速判断当前拥有多少资产、哪些可用、哪些仍在治理。

本次重构的唯一首要目标是：用户打开概览页后，先完成知识资产盘点，再查看资产的治理状态和阻塞位置。

## 2. 信息架构

页面按以下顺序组织：

1. **资产台账**：首屏主区域，展示五类资产的规模、可用量、治理中数量和需关注数量。
2. **结构化知识详情**：默认展开台账中的结构化知识，展示知识状态、编译管线和四个现有工作域。
3. **治理进度与待办**：只展示各阶段当前积压和阻塞项，不重复资产总量。

页面不再展示独立统计卡带、生命周期分布、影响分析占位和快捷操作卡。

## 3. 资产口径

| 资产类型 | 规模口径 | 可用口径 | 治理中/关注口径 | 入口 |
|---|---|---|---|---|
| 政策文档 | `documents_count` | 已解析文档 = 总量 - `documents_raw` | `documents_raw` | `/policy-knowledge/documents` |
| 政策单元 | 去重后的叶子 Unit 总量 | `reviewed` 或 `published` Unit | 待审核 Unit、可构建 Unit | `/policy-knowledge/units` |
| 结构化知识 | 当前工作台知识记录总量 | 已批准变更规则、已进入检索池知识 | 构建任务、待审核规则 | `/policy-knowledge/knowledge/build` |
| 语义资产 | `metrics_count` | `mapped_count` | `unmapped_count`、`mapping_rate` | `/policy-knowledge/knowledge/semantic-discovery` |
| 发布快照 | 当前活动正式版本存在时为 1，否则为 0 | 活动 `release_id` | 待发布任务、质量门禁状态 | `/policy-knowledge/knowledge/releases` |

硬性口径：`policy_extractions` 记录数不是 Unit 资产数。后端聚合必须以去重叶子 Unit 为准，概览不得继续用 `extractions_count` 标记“单元”。

## 4. 资产台账

资产台账使用一张高密度表格，不使用五张同构统计卡。列固定为：

- 资产类型
- 当前规模
- 可用资产
- 治理中
- 需关注
- 查看入口

“结构化知识”行默认选中，通过浅蓝底色和左侧 1px 强调线建立唯一视觉焦点。点击其他资产行直接进入其现有页面；本期不实现台账内多资产展开，避免把概览变成新的工作台。

## 5. 结构化知识详情

### 5.1 状态摘要

展示四个与知识资产直接相关的指标：

- 当前知识总量
- 已批准变更规则
- 待审核规则
- 已进入检索池知识

标签必须带完整业务含义，不能把变更项数量简写为稳定知识资产数量。

### 5.2 编译管线

横向展示实际七阶段：

`INPUT_SNAPSHOT → LLM_EXTRACTION → CANONICALIZE → COMPOSE → RESOLVE → DERIVE → VALIDATE`

概览只承担“管线存在且当前编译结果是否存在阻塞”的说明：

- 节点展示阶段名称和稳定英文代码。
- 右侧展示真实 `PASS / WARN / REVIEW / FAIL` 汇总。
- `REVIEW` 或 `FAIL` 明确说明会阻断正式发布。
- 未获得逐阶段聚合数据时，节点保持中性，不根据问题代码猜测阻塞阶段。
- 点击需复核状态进入现有知识审核页面，不新增运行详情页。

### 5.3 知识工作域

右侧列出四个真实入口，不增加新概念：

1. 知识构建：运行中构建任务数。
2. 知识审核：待处理变更集数。
3. 发布管理：审核通过待发布数量。
4. 语义发现：未映射指标或待审核提议数量；概览优先展示现有稳定接口可提供的指标。

## 6. 治理进度与待办

底部保留一条轻量主线：

`文档 → 单元 → 知识 → 审核 → 发布`

每个阶段只显示当前积压，例如“1 待解析”“6 待审核”“2 构建中”。右侧最多展示三条优先待办，按阻断发布、需要人工审核、一般治理缺口排序。数字为 0 时显示“当前畅通”，接口失败时显示“暂不可用”，不得显示为 0。

## 7. 数据与最小改动

复用现有请求并做两处最小聚合补充：

1. 扩展 `/policy-pipeline/summary`，增加去重 Unit 的 `units_count`、`units_audited`、`units_pending`；删除概览页对慢速 `eligible-units` 请求的首屏依赖。
2. 扩展 `/policy-workbench/governance/dashboard`，增加当前工作台 `knowledge_total` 和 `compilation_by_status`。前者来自现有工作台文档摘要，后者在现有 ChangeSet 遍历中顺手聚合 `compilation_status`。

不新增接口、不新增依赖、不修改知识构建、审核、发布或语义发现业务流程。

## 8. 状态与降级

- 每类资产独立显示加载、失败和空状态，部分接口失败不阻塞其他资产。
- 活动版本 404 表示“尚无正式版本”，不是错误。
- 编译状态缺失时显示“暂无编译记录”，不渲染虚假健康状态。
- 语义发现接口不可用时，仅该行显示“暂不可用”。
- 所有可点击行和链接保留键盘焦点样式、语义标签和足够对比度。

## 9. 响应式策略

- 桌面端：资产台账完整六列；结构化知识区为主内容 + 工作域双列。
- 窄屏：资产台账允许横向滚动；结构化知识区改为单列；编译管线允许横向滚动，不压缩阶段名称。
- 不为移动端复制另一套数据结构。

## 10. 验收标准

1. 首屏第一块内容是资产台账，且结构化知识为唯一默认焦点。
2. 用户能在一屏内识别五类资产、真实规模和主要治理缺口。
3. Unit 数量来自去重叶子单元，不再使用 extraction 数量冒充。
4. 知识区域可见七阶段编译管线和真实编译状态汇总，`REVIEW / FAIL` 的发布阻断语义明确。
5. 知识构建、知识审核、发布管理和语义发现四个入口及数量与现有功能一致。
6. 治理进度不重复资产总量；页面不再出现影响分析占位和快捷卡片。
7. 任一数据块失败时不影响其他块展示，并有明确降级文案。
8. Portal 组件测试、TypeScript 检查和生产构建通过；后端聚合字段覆盖单元测试和 API 测试。

## 11. 非目标

- 不新增资产导出。
- 不新增独立运行详情页。
- 不在概览内执行审核、发布或语义提议审批。
- 不实现资产关系图、趋势图、图表框架或自定义仪表盘配置。
- 不调整 `/policy-knowledge` 现有一级导航和知识工作域二级导航。
