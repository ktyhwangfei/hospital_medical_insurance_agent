# Skill 管理工作台详细设计

## 1. 背景与目标

当前 Skill 页面主要展示版本、评测和 Test 发布状态，缺少真正的管理闭环：用户无法从工作台创建、导入、复制、编辑和删除草稿，也无法清晰理解 Skill 的输入指标与语义层之间的关系。

本设计将 `/skills` 从“治理观测台”升级为“Skill 管理工作台”，对齐语义层和政策知识页面的扁平页面骨架，支持完整的 Skill 管理生命周期：

```text
创建 / 导入 / 复制
  → 独立草稿
  → 结构化编辑
  → 输入指标绑定
  → 语义层校验
  → 包预览
  → 生成正式 Skill
  → 版本登记
  → 评测
  → Test 激活
  → 停用 / 恢复 / 归档
```

本期范围止于 Test 激活，不实现生产发布。

## 2. 已确认的产品决策

| 领域 | 决策 |
|------|------|
| 主页面 | 管理列表 + 独立详情/编辑页，页面骨架对齐语义层和政策知识 |
| 创建入口 | 模板向导、导入 Skill、复制已有 Skill，模板向导为主入口 |
| 编辑方式 | 结构化表单为主，文件树和源码编辑为高级能力 |
| 草稿保存 | 独立草稿存储，校验通过并确认后才写入正式 `skills/` |
| 操作权限 | Skill 管理员可完成全部操作，但关键动作必须二次确认和审计 |
| 删除策略 | 草稿可永久删除；正式 Skill 只能停用、恢复或归档 |
| 发布范围 | 本期仅支持 Test 激活 |
| 查询方式 | Skill 只声明输入指标；指标所属语义对象已经确定查询方式，Skill 不覆盖查询策略 |

## 3. 信息架构与页面布局

### 3.1 一级导航

`/skills` 采用与其他治理页面一致的“平台页签 → 页面标题 → 内容区”结构：

- `Skill`：正式 Skill 管理列表
- `草稿`：独立草稿列表
- `评测记录`：评测用例和评测运行记录
- `发布记录`：Test 发布、确认、停用、恢复、归档和审计记录

页面不再使用“外层工作台大卡片包裹内层详情卡片”的深层嵌套结构。

### 3.2 管理列表页

页面顶部包含：

- 页面标题和简短说明
- `新建 Skill` 主按钮
- `导入 Skill` 次按钮
- 全部、草稿、待评测、待发布、Test Active 等摘要数量

主体使用平面管理表格，列包括：

- Skill 名称和 `skill_id`
- 当前版本
- `BusinessAction` / `BusinessObject`
- 治理状态
- 最近修改人和时间
- 与当前状态匹配的行内操作

典型行内操作：

- 草稿：继续编辑、校验、删除
- 已登记：查看、创建新草稿、运行评测
- 待发布：查看证据、确认发布
- Test Active：查看、创建新草稿、停用
- 已停用：查看、恢复、归档

### 3.3 独立详情与编辑页

点击 Skill 后进入独立详情页，不把详情嵌套在列表内部。详情页包含：

- 生命周期状态和当前 Active 版本
- 输入指标契约
- 版本记录
- 评测证据
- Test 发布记录
- 开发详情和文件预览
- 审计记录

编辑始终作用于草稿。已登记版本不可直接修改，只能基于版本创建新草稿。

### 3.4 路由

```text
/skills
/skills/drafts
/skills/evaluations
/skills/releases
/skills/new
/skills/import
/skills/[skillId]
/skills/[skillId]/edit
```

## 4. 创建、导入与编辑

### 4.1 模板向导

模板向导分为四步：

1. 基本信息：`skill_id`、名称、说明、负责人
2. 业务挂载：`BusinessAction`、`BusinessObject`、关键词、排除意图
3. 输入输出契约：输入指标、必填性、别名、用途、输入/输出 Schema
4. 生成预览：展示 `SKILL.md`、清单 YAML、Schema、模板和目录结构

完成前允许保存草稿。预览阶段必须显示生成文件差异和校验结果。

### 4.2 导入入口

支持三种导入来源：

- ZIP 上传
- Git 地址
- 受控服务器目录

服务器目录只能从配置的导入根目录选择，不能接收任意文件系统路径。

导入后先生成独立草稿，不自动写入正式 `skills/`，也不自动执行其中脚本。

### 4.3 复制入口

复制已有 Skill 时必须填写新的 `skill_id`。复制内容包括结构化配置和文件内容，不复制：

- 版本历史
- 评测运行记录
- 发布记录
- 审计记录
- 敏感配置

## 5. 输入指标与语义层交互

### 5.1 核心原则

Skill 的输入不是数据库字段，也不是政策知识检索配置，而是业务指标契约。数据库、政策知识和其他外部系统只是指标的不同查询实现。

```text
Skill 场景
  → 声明所需输入指标
  → 语义层解析指标
      ├─ 结构化数据库查询
      ├─ 政策知识检索
      ├─ MCP / 外部系统查询
      └─ 常量或派生计算
  → 统一生成 Skill 输入
  → Skill 执行业务逻辑
```

### 5.2 语义对象决定查询方式

- 语义对象定义数据来源类型。
- 指标隶属于语义对象，并继承该对象确定的查询实现。
- Skill 编辑时只选择输入指标，不保存 SQL、物理字段、知识库集合、检索策略或查询优先级。
- 一个 Skill 可以引用多个对象下的指标，运行时按对象分组查询后合并为统一输入。
- 查询计划在 Skill 编辑器中只读展示，不能由 Skill 覆盖。

### 5.3 输入选择器

输入选择器采用级联关系：

```text
业务域 → 语义对象 → 业务指标
```

每个指标展示：

- 指标编码、名称和定义
- 所属语义对象
- 来源类型
- 物理映射或政策知识状态
- 质量分和值域完整性
- 当前发布版本
- 被哪些 Skill 引用
- 本 Skill 中的核心/可选标记

推荐的输入契约：

```yaml
inputs:
  - metric_code: zydyxx.bcqfje
    alias: deductible
    required: true
    purpose: 判断是否达到起付线
  - metric_code: policy.settlement_rule
    alias: settlement_policy
    required: true
    purpose: 提供适用政策规则和引用依据
```

### 5.4 语义校验与查询预览

编辑器提供：

- 输入指标完整性校验
- 只读查询计划预览
- 样例取数测试
- 来源引用和不确定性预览
- 语义对象/指标详情跳转

校验门禁：

- 指标不存在或未发布：阻止登记
- 指标所属对象未配置查询实现：阻止登记
- 结构化指标没有有效字段映射：阻止登记
- 政策知识指标无法提供来源引用：阻止登记
- 可选指标异常：警告，不阻塞登记

语义对象或指标发生变化时，引用它的 Skill 标记为“语义依赖已变化”。当前 Test Active 版本保持不变，但未经重新校验不得发布新版本。

## 6. 领域模型与生命周期

不把所有状态塞进单一 Skill 状态字段，拆分为四类对象：

- `SkillDraft`：创建、导入、复制和编辑中的草稿
- `SkillDefinition`：正式目录中的可加载定义
- `SkillVersion`：完成校验并登记的不可变版本快照
- `SkillEvalRun` / `SkillRelease`：评测证据和 Test 发布记录

生命周期：

```text
草稿编辑
  → 校验失败 / 校验通过
  → 生成正式 SkillDefinition
  → 登记不可变 SkillVersion
  → 运行评测
  → 管理员确认发布
  → Test Active
  → 停用
  → 恢复或归档
```

规则：

- 草稿可反复编辑和永久删除。
- 正式定义修改时自动创建新草稿。
- 已登记版本不可修改。
- Test Active 始终指向不可变版本。
- 停用只解除 Test Active，不删除定义、版本和审计记录。
- 归档后默认不参与路由，但历史证据仍可查询。
- 健康、待评测、待发布等治理状态由事实对象聚合得出，不单独作为事实源存储。

## 7. 后端组件与接口

### 7.1 组件职责

- `SkillDraftService`：草稿创建、复制、保存、删除
- `SkillImportService`：ZIP、Git、受控目录导入
- `SkillDraftValidator`：结构、领域分类、输入指标、Schema、脚本安全校验
- `SkillPackageGenerator`：根据结构化草稿生成标准 Skill 包
- `SkillMaterializer`：管理员确认后将校验通过的包原子写入正式 `skills/`
- 复用现有 `SkillVersionService`、评测和发布服务
- 草稿存储遵循 port/adapter 模式，提供 PostgreSQL 和内存实现

### 7.2 草稿接口

```text
POST   /infra-skills/drafts
POST   /infra-skills/drafts/import
POST   /infra-skills/{skill_id}/copy
GET    /infra-skills/drafts
GET    /infra-skills/drafts/{draft_id}
PATCH  /infra-skills/drafts/{draft_id}
DELETE /infra-skills/drafts/{draft_id}

POST   /infra-skills/drafts/{draft_id}/validate
GET    /infra-skills/drafts/{draft_id}/package-preview
POST   /infra-skills/drafts/{draft_id}/materialize

POST   /infra-skills/{skill_id}/disable
POST   /infra-skills/{skill_id}/restore
POST   /infra-skills/{skill_id}/archive
```

### 7.3 语义预览接口

```text
POST /semantic/skill-inputs/validate
POST /semantic/skill-inputs/query-plan
POST /semantic/skill-inputs/test-query
```

这些接口接收 `InputSpec[]`，不要求草稿已经写入正式目录。

## 8. 安全、确认与失败处理

### 8.1 二次确认与审计

以下动作必须展示 Skill、版本、影响范围和状态变化，并经管理员二次确认：

- 写入正式 `skills/`
- 激活或替换 Test Active
- 停用、恢复、归档
- 永久删除草稿

审计记录包括管理员、时间、操作前后状态、原因、幂等键和关联版本。

### 8.2 导入安全

- ZIP 校验大小、数量、扩展名、目录穿越和符号链接
- Git 地址限制协议和允许主机，禁止本机及内网敏感地址
- 受控目录限制在配置的导入根目录
- 导入后只解析和校验，不自动执行脚本
- 检测密钥、患者信息或其他敏感内容时阻止登记

### 8.3 一致性与恢复

- 草稿使用修订号进行乐观锁，冲突返回 409，不覆盖他人修改。
- 正式写入先生成临时包，校验通过后原子替换。
- 写入或重新加载失败时回滚，不产生半成品 Skill。
- 版本登记失败时保留草稿和校验报告。
- 写接口支持幂等键，避免重复点击产生重复版本或发布。

### 8.4 输入查询失败

- 必填指标失败：阻止 Skill 执行，返回缺失指标、所属对象和失败原因。
- 可选指标失败：继续执行，但写入 `uncertainties`。
- 政策知识指标必须返回引用；无引用视为查询失败。
- 结构化取数测试中的患者标识和返回数据必须脱敏。

## 9. 验证策略与验收标准

### 9.1 后端单元测试

- 模板、复制、导入三种草稿创建
- 草稿修订冲突和删除规则
- ZIP 路径穿越、符号链接、大小限制
- Git 地址和受控目录校验
- 输入指标契约校验
- 结构化指标与政策知识指标的来源约束
- 查询计划生成和必填/可选指标失败处理
- Skill 包生成、正式目录原子写入和失败回滚
- 停用、恢复、归档状态转换
- 幂等键和审计事件

### 9.2 API 与前端测试

- 草稿完整 CRUD 和三种创建入口
- 输入指标预览、查询计划和样例测试
- 校验报告、错误字段和冲突返回
- 物化、版本登记、发布确认、停用、恢复、归档
- 管理列表筛选、排序、行内操作
- 模板向导、指标级联选择、编辑器和源码高级编辑
- 未保存提示、二次确认、URL 恢复和响应式布局

### 9.3 Flow / E2E 主链路

```text
模板创建
  → 选择结构化指标 + 政策知识指标
  → 查询计划预览
  → 校验通过
  → 生成正式包
  → 登记版本
  → 运行评测
  → Test 激活
  → 生成新草稿
  → 停用旧版本
  → 归档 Skill
```

同时覆盖导入失败、必填指标缺失、语义指标失效、写入回滚和重复发布等异常链路。

### 9.4 验收标准

- `/skills` 能找到新建、导入、复制、编辑、校验、发布、停用和归档入口。
- 编辑器可以配置完整输入指标契约。
- Skill 不需要关心指标背后的数据库或政策知识查询方式。
- 语义层提供统一输入、来源引用和不确定性。
- 正式变更都有不可变版本和审计记录。
- 当前 Test Active Skill 不会被草稿编辑直接破坏。
- 页面层级与语义层、政策知识页一致，不再出现深层嵌套工作台。

## 10. 非目标

- 本期不实现生产发布。
- 本期不允许 Skill 覆盖语义对象确定的查询方式。
- 本期不提供任意服务器路径访问。
- 本期不实现在线脚本执行环境。
- 本期不删除已有版本、评测和发布审计记录。
