# 基于算平结果与本单实际分支的费用解释设计

状态：用户已确认三个推荐选项；展示与公开契约已实施。局部未算平及缺少独立推导的内容属于后续算法补全范围，本轮不改金额算法。

依据：用户2026-10-19补充——只有费用分解算法算平的内容才进入解释；费用明细应显示实际医保类别、集采及限价比较、自付比例等本单涉及分支；先把设计想清楚，有歧义集中提问。

## 1. 已明确的产品原则

1. 解释回答「本单这个金额怎么得到」。金额未算平的字段不生成原因解释，也不用“待核实”占据解释位置。
2. 解释以既有确定性算法的本次实际输入、经过的分支、采用的参数和运算结果拼接。前端和模型不重新判断目录或计算金额。
3. 金额核对与来源治理是两条信息：主视图表达“已算平”；参数来源、版本及其原有确认状态在依据中保留，不将它们误写成金额未算平，也不自动把待签核来源改成正式规则。
4. 本单没有经过的分支不展示；决定实际路径的true与false判定均保留。例如“单价≤限价”为false是进入超限路径的依据。
5. 原单事实独立查看。原单可读、明细可加总或支付渠道有记录，不自动等于相关金额已由算法独立复现。
6. 默认聚焦关键数字；后台逐行展开分支、算式和来源。

## 3. 两条入口：结果解释与核对诊断

### 结果解释

采用同一套后端资格判定筛选字段和明细：目标金额精确一致、存在实际计算记录、实际依赖无金额失败/引用冲突/循环；账面复制和账面勾稽不作为独立重算。字段、计算及明细分别带 `explainable`，页面按同一资格筛选。后续模型接入也必须使用这些合格节点。

结构化类型明确区分：算法重算、明细汇总、账面勾稽、仅原单事实。汇总或恒等式可以展示构成，但只有其实际组成与依赖成立时才拼接算法原因链，避免相同金额互相自证。

### 核对诊断

未算平、缺账面值、计算未得到结果、上游未通过等情况进入独立的「核对诊断与算法待补全」，只展示字段/行号、账面值、计算值、差额与核对状态，不生成报销原因。保留同单中已算平且依赖成立的部分。算法补全留待后续实施。

## 4. 一条明细的结构化解释内容

| 内容块 | 必要内容 | 产生位置 |
|---|---|---|
| 项目身份 | 唯一行号、项目编码/名称、药品/诊疗/设施/耗材、费用日期 | 同笔明细快照 |
| 目录分类 | 原始收费类别、标准中文类别、分类来源、目录条目及适用版本 | 本次实际分类器 |
| 本次条件 | 集采标志、自制剂、包装等本次用到的条件；每个值附实际读取/映射/计算采用等来源 | 适配快照及执行节点 |
| 判定路径 | 顺序、条件名、比较符、实际值、比较值、true/false结果、选中分支及规则引用 | 实际执行时记录 |
| 采用参数 | 比例、限价、作用基数、参数来源及优先级；单位明确 | 实际选择器及计算操作数 |
| 运算结果 | 已执行公式、操作数、医保范围内/外、先行自付等本次实际金额；只列执行过的项 | 既有CalculationRecord/LineDecomposition |
| 金额核对 | 医保范围内、医保范围外及先行自付的账面值、计算值、差额和核对结果 | 逐项精确一致，不能用行内/跨行差额抵消放行 |

类别与待遇分开：项目先行自付比例不是基金报销比例。超限价分支需同时展示“采用比例作用于什么基数”，不能只显示一个百分数。

缺少的事实保留未取得，不从自付比例、医保外金额或未进入某分支推断。例如全额个人承担不自动等于丙类；0自付不自动等于甲类；默认False不自动等于确认非集采。

## 5. 只拼接本次实际路径

药品执行顺序需服从现有内核，不能按UI预想重排：

1. 按编码及费用发生日期匹配目录，确定实际收费类别和比例来源。
2. 命中全自付档可直接结束；自制剂有机构/标准价及与集采重叠的分流。
3. 正值结算时限价且超限的早返回路径优先于后续集采分支。
4. 实际进入集采比较时，记录实际单价、实际采用限价、整包/拆包规则的来源及比较结果。
5. 超限后记录本次真正采用的最终比例及来源；未超限时也要说明这一比较结果。
6. 实际进入非集采限价或普通分类路径时，记录对应限价检查与类别规则。

诊疗/设施保留本次sfxmdj与比例/限额选择；耗材保留本次日期规则、单价门槛、纳入比例或结算限价等实际路径，不强套药品甲乙丙。

例如一行实际经过“集采→单价超过限价→采用超限最终比例→分解金额”，解释应同时提供每一步的输入、比较和结果；若前面的结算限价路径已返回，则不能再虚构它执行了后面的集采比较。

依据：`catalog_split.py:436-695,729-798,876-925`。其中自制剂机构不符、价格超标准、集采超限、材料门槛不满足等false判定都会决定金额；单价×数量与原单费用不符属于数据核对问题，单列诊断。

## 6. 当前数据与轨迹的补齐边界

| 缺口 | 处理原则 |
|---|---|
| a_ypbs原值被_truthy压成bool，空/未识别值也可能False | 保留原始值及已知性；不能直接写“非集采” |
| 包装未映射，内核默认整包 | 能陈述“本次按整包规则计算”，不能陈述“原单已确认整包” |
| 一致性评价未映射，当前None | 不能陈述“已通过一致性评价” |
| 拆包限价未映射 | 不补造限价或超限结论 |
| 收费类别0301/0302属于可报草药分组，0103等原义含“其它类” | 优先使用权威字典中文名，保留原码；不从自付档把所有分组强行改名甲乙丙 |
| 普通分类成功、参数优先级选择、部分未超限判断缺显式执行记录 | 在执行点补记录，避免前端解析旧字符串猜测 |

来源：`src/adapters/data_supply/outpatient_decomposition_queries.py:462-463,614-631,705-726`、`record_query_mappings.py:104-127`、`catalog_split.py:346-425`。未映射不代表源库无字段，后续必要时按既有映射适配层核实源数据，不要求用户提供可自行调查的库事实。

如果发现计算默认值本身有缺陷，按缺陷驱动测试先复现再修复并回放核对，不能为展示补标签时暗改算法。也不能为保留某个算平结果编造输入事实。

## 7. 复用接缝与输出一致性

`split_catalog` 每行调用 `catalog_item_explanation` 时，已同时持有item、line、实际branches/calculations和命中entry（`catalog_split.py:201-211`），是补齐解释侧车的最小接缝。缺失的分类/选择轨迹在实际执行位置追加，不另写一套选择器。

公开投影升级为1.5，内部结果仍为1.0。侧车保留分类与采用条件、顺序判定路径、实际计算引用、逐金额核对结果；沿用已有金额字段、引用ID、规则来源及统一递归脱敏入口。

页面仅根据结构化节点展示；未来AI只消费通过资格的节点及其实际依赖。原单事实、核对诊断、来源版本分块提供，禁止模型把未算平项补成原因或把条件输入说成独立推导。本轮没有接入模型调用，原始 `summary_text` 仍是核对摘要，不能当作合格解释节点直接喂给模型。

## 8. 用户裁决与本轮边界

- **解释范围**：按字段保留合格解释，实际使用的上游依赖也必须成立。
- **默认展示深度**：关键标签、单价/限价、采用比例和金额默认可见；完整实际路径按行展开。
- **明细算平粒度**：医保范围内、医保范围外及先行自付逐项与原单一致，缺值保留事实及诊断。
- **算法边界**：局部未算平/缺独立计算属于后续算法补全任务；本轮只补结构化轨迹、解释资格与展示，保留原金额及核对状态。

账面起付直接复制不作为独立算平；职工门特的账面医保内汇总只有逐行目录分解也逐项一致时，才允许进入原因链。原单支付事实始终保留。
