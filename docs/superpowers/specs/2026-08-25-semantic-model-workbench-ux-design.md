# 语义模型工作台与联动查询验证设计

日期：2026-08-25
状态：交互已确认，待文档确认
范围：`/semantic-layer/mapping` 查询模型工作台、`/semantic-layer/query` 联动查询验证、锚点随机取值。

## 1. 决策摘要

1. 查询模型改为结构化“模型工作台”，不再要求管理员直接编辑整份 JSON。
2. 数据集定义为“已登记且具有稳定行粒度的物理表或稳定视图”；它通过 `object_code` 归属业务对象，通过数据源、Schema 和表名绑定物理来源。
3. 主键对应的 `entity_code + columns` 定义数据集“每行代表什么”，不新增重复的行定义元数据。
4. 业务对象切换成为页面唯一主上下文，同时联动查询模型、指标映射、实体、锚点字段、指标及验证结果。
5. 查询验证仅允许使用可查询模型；实体、锚点和指标都从已发布模型派生，不再由用户填写内部编码或 JSON。
6. 锚点值支持手工输入和显式“随机取值”；服务端只从当前已发布锚点字段中返回一个非空样本。
7. 继续复用现有查询模型批量读取/保存接口与查询验证接口，仅为随机锚点增加一个最小 API；不引入 Cube、新前端状态库或新的逐项 CRUD API。

## 2. 问题与根因

### 2.1 查询模型难以定义

当前页面只有模型数量摘要、物理来源表格和“编辑 JSON”。用户看不到以下概念之间的关系：

```text
业务对象
  └─ 数据集（表/视图，归属对象）
      ├─ 键（定义实体和行粒度）
      ├─ 语义字段（标识、维度、事实）
      └─ 关系（通过两端已登记的键连接）
          └─ 质量规则（非空、唯一、覆盖）
```

现有元数据已表达这组关系：`SemanticDataset.object_code` 绑定业务对象，`DatasetKey` 的主键决定行粒度，`SemanticField` 受控声明列角色，`DatasetRelation` 通过两端键声明关联。[来源: `src/semantic_layer/models.py:56-114`]

因此问题主要是编辑交互没有呈现既有模型，而不是元数据缺少一套新概念。

### 2.2 切换业务对象没有形成联动

映射页选择对象后只重新加载查询模型；指标集合仍是所有业务对象的全量集合，统计与列表也未按所选对象过滤。[来源: `src/apps/portal/app/semantic-layer/mapping/page.tsx:300-338,347-376`]

查询验证页只在首次进入时加载对象列表。对象、目标实体、锚点字段、指标、过滤和排序分别保存为互不相关的文本状态，切换对象只修改 `objectCode`。[来源: `src/apps/portal/app/semantic-layer/query/page.tsx:36-87`]

这会产生两类错误：

- 新对象继续携带旧对象的实体、锚点和指标；
- 用户必须知道内部编码和 JSON 契约，页面无法指导其构造有效查询。

### 2.3 默认对象误导

映射页默认选择对象列表第一项，而不是第一个可查询模型。[来源: `src/apps/portal/app/semantic-layer/mapping/page.tsx:300-307`]

当第一项没有数据集时，用户首先看到“0 数据集、不可查询”，但下方又显示全局指标，形成互相矛盾的页面语义。

## 3. 目标与非目标

### 3.1 目标

- 不阅读 JSON 也能理解并维护查询模型。
- 页面明确解释数据集、业务对象绑定和“每行代表”的来源。
- 切换业务对象后所有依赖字段都来自同一模型，不保留无效旧值。
- 查询验证能通过选择完成常用请求，仅高级条件需要展开配置。
- 可一键取得有效锚点样本，降低管理员寻找测试数据的成本。
- 保存、验证和查询仍使用现有后端模型与权限边界。

### 3.2 非目标

- 不建设可视化拖拽关系图。
- 不增加独立的“行定义”字段；主键已经是行粒度的唯一事实来源。
- 不引入 Cube、MetricFlow 或新的 SQL 拼接组件。
- 不让前端提交物理表名、列名或任意 SQL。
- 不把随机取值做成自动加载，避免页面打开即暴露业务数据。
- 不重做值域管理与数据发现页面。

## 4. 元数据模型解释

| 概念 | 定义 | 绑定方式 | 工作台展示 |
|---|---|---|---|
| 业务对象 | 用户查询的稳定业务主题，如住院结算 | `BusinessObject.object_code` | 页面主选择器 |
| 数据集 | 已登记、可查询的物理表或稳定视图 | `object_code + datasource_id + schema_name + table_name` | 名称、物理来源、状态 |
| 行粒度 | 数据集每一行所代表的实体 | 该数据集唯一的 primary `DatasetKey.entity_code + columns` | “每行代表：实体 / 主键字段” |
| 语义字段 | 物理列的受控业务声明 | `dataset_code + column_name` | 标识、维度、事实分组 |
| 数据集关系 | 两个数据集间受控等值关联 | `from_key + to_key + cardinality` | 来源、目标、基数 |
| 指标 | 对外可查询的业务度量 | `object_code`，事实指标引用 `fact_field_code` | 查询验证的指标选择 |
| 质量规则 | 发布和执行时的完整性约束 | 对数据集或关系声明 not-null、uniqueness、coverage | 模型健康和验证问题 |

服务端现有校验已经要求每个数据集恰好一个主键、键列存在、主键列非空、关系两端键有效、同一模型不跨数据源且模型包含覆盖规则。[来源: `src/runtime/api/semantic_routes.py:473-550`]

[建议] 工作台只把这套约束可视化，不另建一套前端专用模型。表单状态最终仍序列化为现有 `QueryModelDocument`。

## 5. 映射页：模型工作台

### 5.1 页面结构

```text
业务对象选择器 + 模型状态 + 保存/校验
┌──────────────────┬────────────────────────────────────┐
│ 模型概览         │ 当前分区的结构化编辑表单           │
│ 数据集           │                                    │
│ 键与行粒度       │                                    │
│ 语义字段         │                                    │
│ 数据集关系       │                                    │
│ 质量规则         │                                    │
│ 高级 JSON        │                                    │
└──────────────────┴────────────────────────────────────┘
所选对象的指标映射
值域管理
```

### 5.2 对象选择行为

首次加载：

1. 加载业务对象列表。
2. 并行读取各对象现有 query model，结合对象的 `current_version` 得到可查询、已发布状态；对象数量当前较少，复用现有接口比新建聚合 API 更小。[建议]
3. 默认选择第一个 `queryable=true` 且存在 `current_version` 的对象；若不存在，再选择第一项并展示配置引导。
4. 所选对象同时驱动模型工作台和指标映射。

切换对象：

1. 若当前模型有未保存修改，先使用现有页面内确认方式提示放弃或取消切换。
2. 加载目标对象模型。
3. 指标统计和列表过滤为 `metric.object_code === selectedObject`。
4. 清空当前编辑项和错误，不复用旧对象表单状态。

### 5.3 空模型引导

没有数据集时不再只展示五个零值，改为：

- 说明“查询模型需要从一个数据集开始”；
- 主操作“添加数据集”；
- 三步提示：绑定表/视图 → 定义主键和每行实体 → 登记字段及覆盖规则。

### 5.4 分区编辑

- 数据集：编辑名称、数据源、Schema、表/视图、状态。
- 键与行粒度：为每个数据集编辑 primary/unique/foreign key；主键区域同步展示“每行代表”。
- 语义字段：选择数据集列并声明 identifier/dimension/fact、语义类型、可空和值域。
- 数据集关系：仅允许选择已登记数据集和键，基数使用枚举选择。
- 质量规则：选择规则类型、目标、严重级别和受控参数。
- 高级 JSON：保留为折叠的批量维护入口，与结构化表单共享同一份文档状态。

点击“校验并保存”时继续调用现有 `PUT /objects/{object_code}/query-model`。该接口已进行完整引用校验并在一个事务中批量替换模型。[来源: `src/runtime/api/semantic_routes.py:553-607`]

## 6. 查询验证：模型驱动表单

### 6.1 字段来源

| 字段 | 来源 | 联动规则 |
|---|---|---|
| 业务对象 | 有已发布、可查询模型的对象 | 不可查询对象隐藏或禁用并标注原因 |
| 目标实体 | 模型 keys 的 `entity_code` 去重值 | 切换对象后选择首个可用实体 |
| 查询范围 | 受限枚举 | 默认整次住院 |
| 锚点字段 | 当前实体键所覆盖的 identifier 字段 | 优先选择 blocking not-null 对应字段，否则首个可用字段 |
| 锚点值 | 手工输入或随机取值 | 切换对象、实体或字段时清空 |
| 指标 | 当前对象中有 `fact_field_code` 或 `expression` 的已发布指标 | 多选，默认选择推荐指标；无推荐则不自动全选 |
| 分组、过滤、排序 | 当前模型可用字段和指标 | 使用结构化行编辑，放入“高级条件”折叠区 |
| Limit | 数字输入 | 保留现有 1—100 约束 |

### 6.2 状态转换

```text
选择对象
  → 加载模型与指标
  → 派生实体
  → 派生锚点字段
  → 清空锚点值、条件和旧结果
  → 用户输入/随机取值
  → 选择指标
  → 执行验证
```

任何上游选择变化，都必须重置其下游状态。请求未满足“可查询对象 + 实体 + 锚点字段 + 锚点值 + 至少一个指标”时禁用执行按钮，并在对应字段附近说明原因。

### 6.3 模型上下文卡片

表单顶部显示当前模型的只读摘要：

- 已发布版本；
- 主体实体/行粒度；
- 数据集数量；
- 模型是否可查询；
- 覆盖规则是否存在。

查询结果继续展示查询范围、结果粒度、分段覆盖、质量状态、逻辑计划和只读参数化 SQL。[来源: `src/apps/portal/app/semantic-layer/query/page.tsx:91-98`]

## 7. 锚点随机取值

### 7.1 交互

锚点值输入框右侧增加按钮：`随机取值`。下方辅助文案：`再次点击可重新取样。`

规则：

- 仅用户点击时请求，不自动取样；
- 请求期间按钮显示加载态且不可重复点击；
- 成功后填入锚点值，但不自动执行查询；
- 字段没有非空值时显示行内错误并保持输入为空；
- 切换对象、实体或锚点字段后清空旧值与旧结果。

### 7.2 API

新增：

```http
POST /api/v1/medical-insurance-ai-agent/semantic/query/anchor-sample
```

请求：

```json
{
  "object_code": "inpatient_settlement",
  "entity_code": "inpatient_admission",
  "field_code": "inpatient_registration.registration_id"
}
```

响应：

```json
{
  "value": "1671213"
}
```

服务端校验顺序：

1. 对象存在且具有可查询的已发布版本；
2. 字段已发布、角色为 identifier；
3. 字段对应列属于所选实体的一条已登记键；
4. 数据集属于当前对象且模型只使用一个数据源；
5. 由服务端元数据生成参数化/受控 SQL，从该列取得一个非空值。

[建议] 在现有 `SemanticQueryService` 增加一个小方法完成取样，复用 `_get_semantic_query_runtime()` 的数据源连接和 Planner 的已发布版本解析，不新建 sampler 抽象。当前 Planner 本身只从不可变发布快照编译查询。[来源: `src/semantic_layer/query_planner.py:616-625`] SQL Server 使用受控标识符和 `TOP 1 ... ORDER BY NEWID()`；这是管理员验证功能，若大表实测出现性能问题，再改为有界候选取样。

### 7.3 安全边界

- 复用 `SemanticReviewPrincipalDependency`，权限与 `/query/test` 相同。[来源: `src/runtime/api/semantic_routes.py:1973-1979`]
- 前端只提交语义编码，不提交表名、列名或 SQL。
- 物理标识符全部由已发布注册表解析。
- 错误响应不返回连接串、表名、SQL 或数据库异常原文。
- 不记录或展示额外患者信息，只返回一个锚点值。

## 8. 错误处理

| 场景 | 页面行为 |
|---|---|
| 对象无查询模型 | 显示创建引导，查询页禁用该对象 |
| 模型校验失败 | 显示服务端 validation issues，禁止查询 |
| 切换对象加载失败 | 清空依赖状态并显示可重试错误 |
| 无可用实体/锚点/指标 | 对应区域显示缺失配置，不保留旧值 |
| 随机取值为空 | 行内提示“当前锚点字段没有可用样本” |
| 随机取值无权限 | 保留手工输入，展示权限错误 |
| 查询执行失败 | 保留本次表单，清空旧结果并显示安全错误 |

## 10. 验收标准

1. 打开映射页默认落到第一个可查询对象，而不是空模型对象。
2. 所选业务对象同时控制查询模型、指标统计和指标列表。
3. 管理员可通过结构化表单维护数据集、键、字段、关系和质量规则；高级 JSON 仍可用。
4. 页面明确显示数据集物理绑定及主键定义的“每行代表”。
5. 查询页切换业务对象后，实体、锚点字段和指标选项随模型更新，旧值、条件和结果被清空。
6. 普通验证不需要输入实体编码、字段编码、逗号列表或 JSON。
7. 点击“随机取值”可从当前合法锚点字段填入一个非空样本，再次点击可重新取样。
8. 随机取值不能通过请求指定物理表、列或任意 SQL，且受语义审核权限保护。
9. 原有 `PUT query-model` 和 `POST query/test` 契约保持兼容。
10. 前端组件测试与对应 API 测试覆盖对象联动、状态清理、空模型和随机取值错误路径。
