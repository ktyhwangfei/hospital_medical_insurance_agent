## 2. 逐单据需求

### D1 — 门诊收费票据(样张:乔雯雯 / 2025-09-30 / 城镇职工医保 / 3623.66 元)

**关键结构字段**

- 票据标识:票据代码、票据号码、校验码、开票日期、业务流水号、医保交易流水号
- 患者标识:交款人、门诊号、医保编号、就诊日期、性别
- 费目明细(每行):项目名称、数量/单位、金额、自付标识(有自付/无自付)
- 费目大类汇总:治疗费、卫生材料费、检查费、西药费
- 医保支付侧:医保类型、统筹基金支付、其他支付、个人账户支付、个人现金支付
- **自付分类**:自付一、自付二、个人自费
- **年度累计**:年度大病保障范围内、年度医保统筹支付、年度住院大额支付、住院医保范围内
- 其他支付:住院大额支付、大病保障支付、医疗救助住院支付、补助支付、单位补充[原公疗]
- 状态:门特/医保已实时结算

**衍生需求**

- **FR-D1-1 费用解释**:输入票据(图像或结构化数据),输出每一类金额的含义、计算来源、是否合理。
- **FR-D1-2 自付分类解释**:必须区分并向患者解释"自付一 / 自付二 / 个人自费"三者差异(这是咨询高频痛点,见案例 38/40)。
- **FR-D1-3 年度累计解释**:能回答"为什么这次报得少"——引用年度累计字段说明起付线/封顶线进度(案例 14/38/40/56)。
- **DR-D1-1 数据**:票据字段必须建模为领域对象(`domain/order_fee` 或新增结算聚合),字段命名遵循 `domain/AGENTS.md` 通用语言。
- **DR-D1-2 解析适配**:需在 `adapters/` 增加票据 OCR/结构化解析端口(当前为内存适配器,真实接入需对接)。

### D2 — 医保门诊实时结算单(样张:杨坦 / 普门诊 / 单位补充公务员待遇)

**关键结构字段(两大区块)**

区块一·交易相关信息(输入项):
- 医疗总金额、医疗保险范围内金额、医疗保险范围外金额
- 个人支付自付(一)金额、个人支付自付(二)金额、大额自付金额
- 起付金额、大额超封顶金额
- 基金支付金额、当次门诊大额基金支付金额、大病支付
- 当次个人帐户支付金额、当次个人现金支付金额
- 单位补充医疗保险(原公疗)支付金额、退役军人补助支付金额、补充保险支付金额、救助支付

区块二·病人基本信息:姓名、性别、医保号、医疗类别、待遇、身份证号、救助类别

**底部计算公式(OCR 部分乱码,关系待核)** 可辨认的关系骨架:
- `范围内 / (范围内 + 范围外) = 比例`
- `个人支付总金额 = 自付一 + 自付二 + 自费 + ...`
- `基金支付 = 范围内 - 自付一 - 起付线...`(系数项含 0.3 等,需原件复核)

**衍生需求**

- **FR-D2-1 结算计算复现**:系统必须能按结算单公式复现各项金额,用于验证票据数字与解释差异(案例 38/68/82)。
- **FR-D2-2 报销差异解释**:对比两次结算单,输出差异归因(起付线进度、报销比例切换、待遇年度切换、自付二出现等)。这是"AI 价值最大"的能力(见 `协和调研.md` 一级分类 3)。
- **DR-D2-1 规则**:结算公式应沉淀为 `policy_engine` 规则或 Skill 的计算脚本,而非硬编码在 LLM prompt 里。
- **DR-D2-2 存疑**:精确比例系数(0.3 等)OCR 不可靠,**实现前必须向协和医保科索取结算单原件或官方公式说明**,禁止凭 OCR 数值编码。

### D3 — 医保报销特殊事项申请表(空白模板,2022 年 6 月制表)

**模板字段**

- 患者信息:姓名、身份证号、联系电话、ID、社保卡号
- 就诊信息:就诊科别、发票日期、发票张数
- **身份三选一(互斥单选)**:北京医保 / 异地直结(省市)/ 异地门诊慢特病(是/否)
- 申请说明(手写区)、申请人签字 + 年月日

**办理流程(表尾备注)**

1. 病人到 **1 号或 2 号窗口**领表,填写清楚
2. 转交**收费处或医保处专人**办理

**衍生需求**

- **FR-D3-1 办理指引**:当意图为"特殊事项报销/补报"时,AI 输出此表的用途、领取窗口、填写要点、流转去向(对应案例中大量"流程怎么走"类咨询)。
- **FR-D3-2 表单预填辅助**:在线下领表前,AI 可基于已查到的患者信息提示需要填哪些项(不做高风险的代填/代签)。
- **KR-D3-1 知识**:此表的"何时需要"判定规则须入政策知识库(例:门特注销最后一次费用未超一周不允许注销——案例 61)。

### D4 — 门诊就诊须知(7 条,院内权威规则)

**7 条规则要点**

1. **异地备案前置**:异地患者就诊前须先备案(参保地医保局或国家医保 APP CHS);津冀慢特病患者门诊+住院都要备案;北京城乡居民/超转人员须社区医院转诊否则无法换医保号。
2. **取医保号流程**:医保患者(含 114/医生加号)就诊前持医保卡或医保电子码到**1 层大厅 5-13 收费窗口**取医保号;**机器上不要关联**,由收费员关联;特需号虽不报销也需取号。
3. **异地慢特病直结**:就诊前取医保号,号条上印有"异地慢特病"5 字。**可直结 9 种**:恶性肿瘤、高血压、糖尿病、慢阻肺、类风湿关节炎、冠心病、病毒性肝炎、强直性脊柱炎、血液透析。
4. **报销比例疑问**:异地直结/慢特病对挂号费、门诊报销比例有疑问 → 咨询**参保地医保局**(同省不同市政策不同)。
5. **改身份**:要改就诊身份(如北京医保→异地医保)→ 收费窗口重新关联信息并取医保号,否则无法报销。
6. **线上诊疗**:异地线上诊疗不报销;北京医保线上交 **10 元医事服务费**可报销,**50 元**则本次门诊费用无法报销。
7. **北京特殊病办理**:接诊医生提交特病申请 + 开证明书 → 持医保卡/医保码到**门诊一层收费处 2 号窗口**办特殊病身份 → 特殊病交费**东院到 17-19 号窗口**(北京医保无"慢病"概念)。

**衍生需求**

- **KR-D4-1 必入知识库**:这 7 条须作为协和院端政策知识库的**权威原文条目**,AI 回答时必须引用条目编号(满足 AGENTS.md "来源可追溯"硬约束)。
- **FR-D4-1 规则可引用**:意图命中(备案/取号/改身份/线上报销/特病办理)时,AI 按"适用条件 + 操作步骤 + 窗口位置"结构化输出,并标注来源=就诊须知第 N 条。
- **FR-D4-2 阈值数字高敏**:10 元 vs 50 元医事服务费、5-13 窗口、2 号窗口、17-19 号窗口——**数字必须精确**,实现时以原件二次校验。

### D5 — 北京医保可办理特殊病清单(14 种)

**清单(病名 + 生效日期)**

耐多药结核、恶性肿瘤门诊治疗、再生障碍性贫血、血友病、C 型尼曼匹克病、多发性硬化、眼底病变眼内注射治疗、肺动脉高压靶向治疗、中重度过敏性哮喘生物制剂治疗、肺间质病抗纤维化治疗、肾透析、肾移植术后抗排异、肝移植术后抗排异、肝肾联合移植术后抗排异。

(生效日期集中在 2000-01-01 与 2017/2020,具体日期以原件为准。)

**衍生需求**

- **KR-D5-1 判定基准**:`policy_eligibility` Skill 判断"是否符合北京特殊病资格"时,**必须以此 14 种清单为白名单**,清单外病种不予认定。
- **FR-D5-1 资格预判**:输入诊断 → 输出是否在清单内、对应办理路径(接医生开证明→2 号窗口)。对应案例 3/29/39 的资格审核类咨询。
- **DR-D5-1 数据治理**:清单须可配置(政策会更新),存于政策知识库而非代码常量。

---

### D6 — 异地慢特病提醒

**要点**

- **可直结 9 种**(与 D4 第 3 条一致):高血压、糖尿病、恶性肿瘤、慢性阻塞性肺病、类风湿关节炎、冠心病、病毒性肝炎、强直性脊柱炎。
- **非直结慢特病**:若想享受待遇,**不要用社保卡缴费**(可用身份证缴费)。
- **后续**:与参保地协商,携带参保地要求材料,**回当地人工报销**。

**衍生需求**

- **FR-D6-1 分流决策**:异地慢特病意图 → 先判病种是否在直结 9 种内:
  - 在内 → 引导直结流程(D4 第 3 条)
  - 在外 → 明确告知"勿刷社保卡、用身份证、回参保地人工报销"
- **KR-D6-1 知识**:9 种直结病种清单须入知识库,并与 D5(北京 14 种)明确区分——这是两套不同清单,易混淆。

## 3. 跨单据的系统级需求

### 3.1 票据/结算单解析能力(P0)

- 系统须能从 D1(票据)和 D2(结算单)提取结构化字段。
- 当前 `adapters/` 为内存实现,**真实接入需新增票据 OCR/结构化解析适配器**,并遵循 ports/adapter 解耦纪律(AGENTS.md)。
- 解析结果须能驱动费用解释 Skill(已规划 `SettlementExplainSkill` / `BenefitCalculationSkill`)。

### 3.2 费用计算解释引擎(P0,价值最高)

- 必须能解释:D1 自付一/自付二/自费的区别、起付线进度、报销比例、统筹 vs 个人账户、年度累计影响。
- D2 的计算公式是引擎的**算法真相源**——但 OCR 不可靠,**实现前必须向协和医保科索取官方公式**。
- 输出须带 citations(来源=票据字段 / 结算单字段 / 政策条目),满足来源可追溯硬约束。

### 3.3 政策知识库内容清单(P0)

以下必须作为权威语料入库,且 AI 引用时标注条目来源:

| 来源单据 | 知识条目 |
|----------|----------|
| D4 | 门诊就诊须知 7 条原文 |
| D5 | 北京 14 种特殊病清单 + 生效日期 |
| D6 | 异地 9 种可直结慢特病清单 |
| D4/D6 | 收费窗口分布(5-13 取号 / 2 号特病 / 17-19 东院特病交费 / 1-2 号领表) |
| D4 | 线上诊疗报销阈值(10 元可报 / 50 元不可报) |

### 3.4 办理流程指引(P0)

- D3 申请表 + D4 须知 共同定义了多条办理流(领表→填→交;取号→关联;特病申请→盖章→交费)。
- AI 须能按意图输出**分步流程 + 窗口位置 + 所需材料**,对应案例中"流程怎么走"类高频咨询。

### 3.5 高风险动作拦截(硬性,已由 AGENTS.md 规定)

- 本组单据涉及的高风险动作:**退费、冲正、特病身份变更/撤销、改就诊身份**——必须经 `security/risk_control` 拦截转 `waiting_human_confirmation`,AI 仅做指引不代执行。
- D6 的"用身份证缴费而非社保卡"属**患者侧操作建议**,不构成系统高风险动作,但 AI 须明确这是患者自主行为。

### 3.6 易混淆清单治理

- **三套病种清单须严格区分**:
  - 北京特殊病(D5,14 种,门诊治疗类为主)
  - 异地可直结慢特病(D4第3条 / D6,9 种)
  - 当地认定的慢特病(因参保地而异,AI 不可枚举,须引导问参保地)
- AI 回答前必须先确定"问的是哪套清单",这是案例 39/53/61 的核心混淆点。

## 5. 实施前必须澄清的事项(阻塞项)

1. **D2 结算单计算公式的精确形式**:OCR 乱码,系数(0.3 等)不可靠 → 需协和医保科提供官方公式或可读原件。**在拿到前,BenefitCalculationSkill 不可凭 OCR 编码。**
2. **D4 中的精确数字**:窗口号(5-13 / 2 / 17-19 / 1-2)、医事服务费阈值(10/50 元) → 须原件二次核对,窗口号可能随院区调整。
3. **D5 生效日期**:OCR 部分乱码,如需精确到日须核对原件。
4. **D3 申请表的"特殊事项"边界**:哪些情形必须填此表(门特注销超期、补报、费别纠错等),需医保科给出触发条件清单,而非仅靠案例归纳。

> 以上 4 项是"OCR 不可信/边界不清"的硬阻塞,实现对应能力前必须回协和医保科确认。
