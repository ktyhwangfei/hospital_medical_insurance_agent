# data_platform 数据与知识底座详细设计

## 1. 模块定位

`data_platform/` 是医保 AI 平台的 DaaS 数据与知识底座，负责结构化数据、文件数据、向量数据、缓存数据、主数据、患者医保画像、指标体系和数据质量监控的统一管理。

该模块为上下文管理、RAG 检索、规则解释、任务规划、申诉材料生成、医保运营驾驶舱提供可信数据依据。

## 2. 设计目标

1. 汇聚医保专业系统和医院业务系统关键数据。
2. 建立患者医保画像、医保主数据和指标体系。
3. 支持结构化查询、文件检索、向量检索和缓存访问。
4. 支持数据质量监控和数据来源追溯。
5. 为 AI 输出提供可引用、可追溯、可审计的数据依据。

## 4. 数据资产设计

### 4.1 结构化数据

| 数据 | 来源 | 用途 |
|---|---|---|
| 医保结算数据 | 首信医保接口、收费系统 | 结算异常导办、运营指标 |
| 费用明细 | HIS、收费系统 | 合规审核、DRG/DIP 分析 |
| 医嘱 | HIS、EMR | 事前审核解释、出院质控 |
| 诊断手术 | EMR、病案系统 | DRG/DIP、病案风险 |
| 病案首页 | 病案系统 | 入组风险、首页质控 |
| 审核结果 | 东软事前审核 | 合规风险解释 |
| DRG/DIP 结果 | 大瑞集思 | 盈亏分析、科室运营 |
| 拒付申诉数据 | 医保办、医保反馈 | 申诉助手 |

### 4.2 知识资产

| 知识 | 用途 |
|---|---|
| 医保政策知识库 | 政策解释、申诉依据 |
| 院内制度知识库 | 院内规则、管理制度解释 |
| 错误码知识库 | 结算异常解释 |
| 规则解释库 | 审核规则、目录规则解释 |
| 申诉模板库 | 申诉材料生成 |

## 6. 患者医保画像

画像维度：

1. 患者身份与待遇。
2. 当前就诊与住院状态。
3. 费用上传与结算状态。
4. 审核风险与规则命中。
5. DRG/DIP 分组与盈亏。
6. 病案首页质量。
7. 拒付与申诉历史。
8. 任务处理状态。

接口：

```text
PatientProfileService.build(patientId, encounterId) -> PatientInsuranceProfile
PatientProfileService.refresh(patientId, encounterId) -> RefreshResult
PatientProfileService.getRiskSummary(patientId, encounterId) -> RiskSummary
```

## 7. 医保主数据

| 主数据 | 说明 |
|---|---|
| 药品目录 | 药品编码、医保编码、限制条件 |
| 诊疗项目 | 项目编码、医保编码、适用范围 |
| 耗材目录 | 耗材编码、医保分类、支付规则 |
| 科室医生 | 科室、医生、角色、权限 |
| 病种病组 | DRG/DIP 病种、病组、权重 |
| 规则主数据 | 审核规则、政策规则、错误码规则 |

## 8. 指标体系

第一期指标：

1. 医保结算成功率。
2. 结算异常平均处理时长。
3. 违规风险金额。
4. DRG/DIP 盈亏金额。
5. 病案首页缺陷率。
6. 出院前风险发现率。
7. 任务闭环完成率。

## 9. 数据质量监控

| 质量维度 | 检查内容 |
|---|---|
| 完整性 | 必填字段缺失、关键对象缺失 |
| 一致性 | 患者、就诊、费用、病案之间关联不一致 |
| 及时性 | 数据更新时间滞后 |
| 准确性 | 编码映射错误、金额异常 |
| 可追溯性 | 缺少来源系统、来源记录、采集时间 |

## 10. 数据访问服务

```text
DataAccessService.query(dataset, filters, permissionContext) -> DataResult
DataAccessService.getByReference(dataRef) -> DataObject
VectorSearchService.search(query, knowledgeScope, topK) -> RetrievedChunks
ObjectStorageService.getSignedUrl(objectId, permissionContext) -> Url
```

## 11. 安全约束

1. 数据访问必须携带权限上下文。
2. 患者敏感数据默认脱敏。
3. AI 引用数据必须保留来源引用。
4. 文件访问必须使用短期授权链接。
5. 数据质量不足时必须向上游返回明确提示。

## 12. MVP 范围

第一期建设结构化存储、向量存储、文件存储、缓存基础能力；实现患者医保画像基础版、医保主数据基础版、错误码知识库、政策知识库和数据访问服务。
