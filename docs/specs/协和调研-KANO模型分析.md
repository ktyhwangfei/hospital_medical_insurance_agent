## 3. KANO 分类矩阵

### 3.1 分类标准

| 类型 | 代码 | 规律 | 产品策略 |
|------|:--:|------|---------|
| **基本型** | M | 不满足 → 极度不满；满足 → 无额外满意 | 必须做到，底线 |
| **期望型** | O | 满足度与实现度成正比 | 做越多越好，竞争力核心 |
| **兴奋型** | A | 不满足 → 无不满；满足 → 惊喜 | 差异化亮点，按节奏投入 |
| **无差异型** | I | 有无均不影响满意度 | 不做或极低成本做 |
| **反向型** | R | 有了反而引起不满 | 绝对不做 |

## 4. 分领域 KANO 分析

### 4.1 慢特病办理（最高频，18% 咨询量）

```
MUST:   慢特病办理流程指引（申请/取消/续期/材料清单）
MUST:   慢特病资格判定规则（D5 14 种白名单 + D4 第7条办理路径）
EXPECT: 慢特病报销比例解释（案例 38/40/68）
EXPECT: 慢特病与其他费别差异对比（案例 45/62）
ATTRACT: 表单预填辅助（D3 申请表）
ATTRACT: 特病到期自动提醒
REVERSE: AI 自动修改特病身份 ← ⛔ 必须拦截
```

**当前 gap**：慢特病办理是协和最高频场景（15/82=18%），但当前产品**完全未覆盖**此能力。P0 紧急。

### 4.2 异地医保（第二高频，13% 咨询量）

```
MUST:   异地备案流程指引（D4 第1条）
MUST:   异地慢特病直结 9 种判定（D6 分流规则）
EXPECT: 异地报销比例差异解释（案例 2/31/59）
EXPECT: 参保地政策差异提示（"问参保地"标准话术）
ATTRACT: 异地慢特病自动分流（9 种内→直结，外→身份证+回当地报）
```

**当前 gap**：异地医保场景完全未覆盖。与慢特病交叉场景（异地慢特）是核心混淆点，需特别注意 D5(北京 14 种) 与 D6(异地 9 种) 的清单隔离。

### 4.3 费用解释（AI 价值最大场景）

```
MUST:   自付一/自付二/自费三者的区别解释（D1 字段 + 案例 38/40）
MUST:   起付线/封顶线/报销比例的基础概念解释
EXPECT: 两次结算差异归因解释（"为什么这次报得少" → 起付线进度/比例切换/年度变更）
EXPECT: 结算金额计算公式复现（D2 公式引擎）
ATTRACT: 费用最优路径建议（"怎么划算" → 不同费别/身份的费用模拟）
ATTRACT: 票据 OCR 上传 + 自动解析 → 自动解释
```

**当前 gap**：已有费用解释 Skill 框架（`settlement_explain_skill/`），但：
1. 缺少 D2 结算公式引擎（OCR 乱码，系数不可靠，**实现前必须获取官方公式**）
2. 缺少报销差异对比能力
3. 缺少票据 OCR 解析

### 4.4 医保身份问题（9% 咨询量）

```
MUST:   医保身份诊断（"为什么没走医保" → 自费身份/未取号/机器关联失败）
EXPECT: 费别纠错指引（改身份 → 收费窗口重新关联）
EXPECT: 医保号获取流程（持卡到 5-13 号窗口）
```

**当前 gap**：需对接 HIS 查询患者当前就诊身份和费别，当前适配器为内存实现。

### 4.5 退费咨询（6% 咨询量）

EXPECT: 退费路径指引（挂号费/检查费/药费各自退费窗口）

### 4.6 住院医保（5% 咨询量）

### 4.7 政策资格审核（4% 咨询量）

## 附录 A：KANO 问卷设计模板（供后续用户验证）

每个需求可通过以下标准问题验证 KANO 分类：

```
正向问题：如果系统[具备某功能]，您觉得如何？
  1. 我喜欢  2. 理所当然  3. 无所谓  4. 勉强接受  5. 不喜欢

反向问题：如果系统[不具备某功能]，您觉得如何？
  1. 我喜欢  2. 理所当然  3. 无所谓  4. 勉强接受  5. 不喜欢
```

正向↔反向交叉得出 KANO 分类：
- 喜欢 + 不喜欢 = O（期望型）
- 理所当然 + 不喜欢 = M（基本型）
- 喜欢 + 无所谓 = A（兴奋型）
- 无所谓 + 无所谓 = I（无差异型）
- 不喜欢 + 喜欢 = R（反向型）

> 建议在协和医院医保科对 5-10 名一线咨询人员进行 KANO 问卷验证，以校准本文档的分类。
