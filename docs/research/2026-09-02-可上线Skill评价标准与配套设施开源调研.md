# 可上线 Skill 评价标准与配套设施开源调研

> 2026-09-02 · 由 mzsettlement_verify_skill 九轮迭代（1.0.4→1.0.18）反推产出的调研与方案。
> 结论待确认后再启动开发。

## 一、背景

门诊结算核验 Skill 经过九轮用户驱动的修复（路由子串不命中 ×3、费用分解到根、按问题相关性精简、起付/封顶阶段解读、焦点首行、前端换单缺陷），已形成较完整的"评测-修复-回归"实践。本调研回答三个问题：

1. 什么样的 Skill 算"能上线"？（评价标准）
2. 应该怎么开发？（方法论）
3. 配套设施怎么搭？（方案）

### 关键结论

1. 架构没有轮子可搬，但每个部件都有成熟原型：Skill 打包 + 评测门禁 + 确定性校验 + 网关的组合正是本仓库已有形态。
2. 领先通用框架（需保住）：数据集不可变版本、benchmark 环境快照、artifact hash 锁定运行时、草稿→物化→评测→发布治理链、医保口径逐单验证分解。
3. 落后成熟经验（需补）：CI 门禁自动化、问题变体回归表、案例挖掘流水线、线上观测闭环。

## 三、评价标准：什么算"能上线"（八条）

| 维度 | 标准 | 证据方式 | 迭代教训 |
|---|---|---|---|
| 1. 数值正确 | 真值集（31 例）自付一容差 0 全过；勾稽恒等式逐单验证 | self_tests + benchmark gate=100% | 已达 |
| 2. 路由正确 | 问题变体表 100% 命中声明场景，未声明问题优雅降级 | routing 变体测试表 | 三次子串不命中（个人支付/起付金额/大额自付） |
| 3. 解释到根 | 问"为什么"必给因果分解；逐单可证才断言渠道归因 | 分解段断言 + 焦点首行断言 | 修了 5 轮才到"起付 1800 + 大额自付 180"水平 |
| 4. 术语一致 | 回答术语 = 结算单字段名 | 术语表测试 | "统筹段个人自付"是自造词，改回"大额自付" |
| 5. 数据覆盖 | 人群 × 阶段（起付前/跨线/大额段/近封顶/超封顶）× 特殊渠道矩阵饱和 | 覆盖矩阵清单 | 阶段维度补 3 例，仍有空格（退休跨线、居民近封顶等） |
| 6. 诚实降级 | 无证据不猜（封顶门槛缺政策 → 声明不确定性） | uncertainty 断言 | 保命线 |
| 7. 可发布可回滚 | 版本+hash+gate 三锁 | eval-run 记录 | 已有，缺自动化 |
| 8. 上线观测 | answer_status 分布、uncertainty 率、路由命中率趋势可看 | qa_turn 统计 | 缺 |

一句话：**能上线 = 八条全绿 + 有门禁保证它一直绿**。

## 四、开发方法论（从迭代教训固化）

1. 先红后绿：任何修复先写失败测试（九轮全部如此，零例外）
2. 缺陷驱动喂案例：用户每个"不对吧"→ self_test_cases 加一条 + routing 变体加一行；抱怨即测试资产
3. 先数据后逻辑：新能力先用真实库验证数据形态（恒等式 31 单验证 → 27 成立 4 不成立 → 逐单验证设计），禁止拍脑袋写公式
4. 发布仪式固定：升版本 → sync → restart → 全量 benchmark → 31/31 才算完
5. 最小改动纪律：每轮 diff 控制在"测试+一处实现"，不顺手重构

## 五、配套设施方案（P0-P2）

| 设施 | 借鉴 | 形态 | 优先级 |
|---|---|---|---|
| A. CI 门禁脚本 | promptfoo CI mode | 一条命令：skill 单测 + routing 变体表 + headless benchmark（走现有 API）+ gate 判定退出码 | P0 |
| B. 问题变体回归表 | 三次子串 bug | YAML：每 profile 列 10+ 真实问法（含用户原话），断言路由+焦点；改 hints 必须先加变体 | P0 |
| C. 案例挖掘脚本 | 手工 SQL 实践 | 按阶段×人群条件扫真实库 → 输出勾稽自洽候选 → 人工确认入库 | P1 |
| D. 上线观测看板 | Phoenix 理念（不引依赖） | 聚合 qa_turn：answer_status/uncertainty/路由分布/耗时趋势 + 漂移告警 | P1 |
| E. 反馈闭环 SOP | 现有 EvalCasePool | "回答有误"→案例池→定期评审入数据集→接 A 门禁 | P2 |
| F. 发布 SOP 文档 | — | 版本/gate/回滚 checklist 一页纸 | P2 |

### 明确不做（规避重复造轮子）

- 不自研评测框架（eval-runs 已有，promptfoo 思路够用）
- 不引 OTel（qa_turn 落库够用）
- 不引编排框架（已退役 langgraph 同类）
- 不引 guardrails 库（verify_settlement 已是领域版）
