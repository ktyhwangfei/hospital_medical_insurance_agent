# 医保政策规则结构化技术设计方案

## 一、核心目标

你现在已有：

```text
政策文件原文
政策解读原文
附件文件
政策来源链接
发布日期
```

下一步不是简单做 RAG，而是要把政策变成产品可用的三类资产：

```text
1. 政策知识资产：用于检索和引用
2. 规则结构化资产：用于计算和判断
3. 解释语料资产：用于面向患者自然语言解释
```

最终目标：

```text
患者诊次数据 + 结构化医保规则 + 政策依据 + AI解释
= 可追溯的医保结算解释结果
```

---

# 二、总体处理链路

```text
原始政策文件
↓
文本清洗
↓
政策元数据识别
↓
条款级切分
↓
条款分类
↓
规则候选抽取
↓
结构化规则生成
↓
人工审核确认
↓
规则版本发布
↓
诊次解释产品调用
```

# 三、核心数据分层

建议你不要把所有内容混在一个表里，至少分成四层。

## 1. 原始文件层

保存原始政策和解读文件。

```text
policy_documents
```

核心字段：

```text
id
title
source_type              政策文件 / 政策解读 / 医院指南
source_url
publish_date
effective_date
policy_no                文号
raw_text
attachment_path
crawl_time
```

---

## 2. 条款切分层

把政策拆成条款级内容。

```text
policy_chunks
```

核心字段：

```text
id
document_id
chunk_no
chapter_title
article_no
chunk_text
chunk_type
embedding_id
```

chunk_type 建议分为：

```text
definition        概念定义
eligibility       适用对象
benefit_rule      待遇规则
payment_rule      支付规则
deductible_rule   起付线规则
ratio_rule        报销比例规则
cap_rule          封顶线规则
period_rule       周期规则
exception_rule    例外规则
process_rule      经办流程
explanation       政策解读
```

---

## 3. 结构化规则层

这是产品核心。

```text
medical_insurance_rules
```

核心字段：

```text
id

insurance_type
person_type
medical_scene
hospital_level
condition_json
action_json

version
review_status
```

---

## 4. 解释模板层

用于生成患者能听懂的解释。


核心字段：

```text

```

# 四、政策规则结构化的核心对象

你要把自然语言政策转成这种结构：

```json
{
  "rule_code": "BJ_ZY_QFX_001",
  "rule_name": "北京市职工医保住院起付线规则",
  "rule_type": "deductible_rule",
  "insurance_type": "职工医保",
  "medical_scene": "住院",
  "hospital_level": "三级医院",
  "condition": {
    "hospitalization_count_in_year": 1
  },
  "action": {
    "deductible_amount": 1300
  },
  "source": {
    "document_title": "xxx政策文件",
    "article": "第x条",
    "chunk_text": "xxx"
  }
}
```

再比如减半规则：

```json
{
  "rule_code": "BJ_ZY_QFX_002",
  "rule_name": "第二次及以后住院起付线减半规则",
  "rule_type": "deductible_rule",
  "insurance_type": "职工医保",
  "medical_scene": "住院",
  "condition": {
    "hospitalization_count_in_year": ">=2"
  },
  "action": {
    "deductible_amount": "standard_deductible * 0.5"
  },
  "source": {
    "chunk_text": "第二次及以后住院起付线减半"
  }
}
```

# 五、不要直接让大模型生成最终规则

推荐采用：

```text
大模型抽取候选规则
+
程序校验格式
+
人工审核发布
```

也就是：

```text
AI 负责“提取”
人负责“确认”
系统负责“执行”
```

原因：

```text
医保规则涉及金额计算
不能让大模型直接决定
必须有人审、可追溯、可回滚
```

# 七、以“起付线 1950”场景为例

## 7.1 原始政策表达

```text
第一次住院起付标准为1300元。
第二次及以后住院起付标准减半。
住院治疗每90天为一个结算周期。
```

---

## 7.2 抽取后的规则

### 规则一：首次住院起付线

```json
{
  "rule_code": "BJ_ZY_QFX_001",
  "rule_name": "首次住院起付线",
  "rule_type": "deductible_rule",
  "insurance_type": "职工医保",
  "medical_scene": "住院",
  "hospital_level": "三级医院",
  "applicable_condition": {
    "conditions": [
      {
        "field": "hospitalization_count",
        "operator": "=",
        "value": 1
      }
    ]
  },
  "calculation": {
    "formula": "1300"
  },
  "result": {
    "benefit_type": "deductible",
    "amount": 1300
  }
}
```

### 规则二：第二次及以后减半

```json
{
  "rule_code": "BJ_ZY_QFX_002",
  "rule_name": "第二次及以后住院起付线减半",
  "rule_type": "deductible_rule",
  "insurance_type": "职工医保",
  "medical_scene": "住院",
  "applicable_condition": {
    "conditions": [
      {
        "field": "hospitalization_count",
        "operator": ">=",
        "value": 2

  },
```

# 八、规则抽取 Prompt 模板

你可以让大模型按这个模板抽取。

```text
你是医保政策规则结构化专家。

请从以下政策条款中抽取可计算的医保规则。

要求：
1. 只基于原文，不要自行扩展。
2. 如果原文没有明确金额、比例、周期，不要编造。
3. 输出 JSON。
4. 每条规则必须保留原文依据。
5. 无法结构化的内容，放入 unable_to_structure。
6. 判断该条款属于哪类规则：
   - deductible_rule 起付线规则
   - ratio_rule 报销比例规则
   - cap_rule 封顶线规则
   - period_rule 周期规则
   - eligibility_rule 适用对象规则
   - exception_rule 例外规则
   - process_rule 经办流程规则
7. 输出字段包括：
   - rule_name
   - rule_type
   - insurance_type
   - person_type
   - medical_scene
   - hospital_level
   - applicable_condition
   - calculation
   - result
   - period_rule
   - exception_rule
   - source_original_text
   - confidence

政策标题：
{title}

政策文号：
{policy_no}

发布日期：
{publish_date}

政策条款：
{chunk_text}
```

# 九、实现步骤

## 第一步：清洗原始政策

处理内容：

```text
去掉网页导航
去掉页脚版权
去掉重复空行
保留标题、文号、发布日期、正文、附件
```

输出：

```text
clean_text
```

---

## 第二步：条款切分

按这些规则切分：

```text
第一章
第一条
一、
（一）
1.
附件表格
```

不要简单按固定长度切。

建议切分粒度：

```text
一个完整条款 = 一个 chunk
一个表格 = 一个 chunk
一个政策解读问答 = 一个 chunk
```

---

## 第三步：条款分类

先判断每个 chunk 是什么类型：

```text
起付线
报销比例
封顶线
周期
适用人群
目录范围
经办流程
解释说明
```

这一步可以用：

```text
关键词规则 + 大模型分类
```

关键词示例：

```text
起付线、起付标准、起付金额
报销比例、支付比例、基金支付
封顶线、最高支付限额
90天、周期、年度、自然年度
第一次、第二次、以后、减半
职工、居民、退休、在职
三级、二级、一级、社区
```

---

## 第四步：抽取候选规则

对疑似规则类 chunk 调用大模型抽取 JSON。

输出到：

```text
rule_candidates
```

状态为：

```text
pending_review
```

---

## 第五步：规则校验

程序自动校验：

```text
JSON是否合法
金额是否为数字
比例是否在0到1之间
日期是否有效
rule_type是否合法
是否有source_original_text
是否有source_chunk_id
是否缺少关键字段
```

---

## 第六步：人工审核

这是必须的。

审核动作：

```text
确认规则有效
修改规则条件
补充适用人群
补充医院等级
标记不适合结构化
发布规则
```

审核后的规则进入：

```text
medical_insurance_rules
```

---

## 第七步：规则发布

发布后规则才能被产品调用。

规则状态建议：

```text
draft
pending_review
published
deprecated
```

# 十、规则与产品调用关系

患者问：

```text
为什么我的起付线是1950？
```

系统执行：

```text
1. 识别问题类型：起付线解释
2. 查询患者本次诊次
3. 查询历史住院记录
4. 匹配起付线规则
5. 执行规则计算
6. 检索政策依据
7. 生成解释
```


# 十三、第一版产品能力边界

第一版可以回答：

```text
为什么起付线是这个金额？
为什么这次又扣起付线？
为什么第二次住院起付线减半？
为什么超过90天重新计算？
为什么报销比例不是我以为的比例？
```

暂时不要回答：

```text
复杂门特待遇
异地就医多地政策差异
生育待遇
长期护理
目录限制
商保联合理赔
```

# 十四、最推荐的落地路线

```text

文本清洗

```

## 第 2 周：起付线规则抽取

```text

```

```text
准备10-50个脱敏诊次案例
实现起付线规则计算函数
验证计算结果
```

## 第 4 周：AI解释闭环

```text
接入大模型
生成患者版解释
引用政策依据
记录执行日志
形成演示Demo
```

# 十五、最终建议

你现在最应该做的不是继续扩大爬虫，而是进入：

```text
政策条款结构化
+
起付线规则抽取
+
患者案例验证
```

第一版只盯住一个问题：

```text
为什么这个患者起付线是1950，而不是1300？
```

只要这个问题能做到：

```text
政策能引用
规则能计算
历史诊次能关联
AI能解释
过程能留痕
```

这个产品的技术路线就成立了。
