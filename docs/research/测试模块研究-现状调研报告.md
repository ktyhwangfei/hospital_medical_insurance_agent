## 二、Skill 质量现状

### 2.1 架构概览

`settlement_explain_skill` 是当前唯一的 Skill（v2.0.0），采用 Strategy Pattern 设计：

```
skills/settlement_explain_skill/
├── skill_manifest.yaml      ← 业务动作声明 (explain/settlement)
├── SKILL.md                 ← 14步执行流程规范
├── assembler.py             ← 轻量调度器 (~120行)
├── strategies/              ← Strategy Pattern
│   ├── base.py              ← BaseFeeStrategy（7抽象方法）
│   ├── registry.py          ← STRATEGY_REGISTRY
│   ├── pooling_self_pay/    ← 统筹自付策略
│   ├── deductible/          ← 起付线策略
│   ├── large_amount_self_pay/ ← 大额自付策略
│   ├── pooling_payment/     ← 统筹支付策略
│   ├── personal_total_pay/  ← 个人总支付策略
│   └── out_of_scope/        ← 医保外费用策略
├── tests/                   ← 验收测试（含 6 个 YAML case）
├── schemas/                 ← JSON Schema
├── templates/               ← 解释模板
└── scripts/                 ← 校验/标准化脚本
```

[来源: `skills/settlement_explain_skill/SKILL.md`, `skills/AGENTS.md`]

## 三、知识召回质量现状

### 3.1 检索管线架构

```
用户问题
  ↓
query_understanding.py   ← 关键词识别（起付线/支付比例/封顶线）+ 实体抽取
  ↓
semantic_mapping.py      ← 口语→系统术语映射（医院业务字段→政策标准字段）
  ↓
milvus_retriever.py      ← Milvus 向量搜索（node_col + fact_col）
  ↓
reranker.py              ← RuleBasedReranker（fact_type/医院等级/人群/入院次序打分）
  ↓
policy_rules_search.py   ← 生产 SSE 端点用的 policy_rules_v2 搜索引擎
  ↓
structured_policy_retriever.py ← 结构化策略检索（custom_queries）
```

[来源: `src/knowledge_extension/rule_explanation/policy_retrieval/`, `src/runtime/policy_qa/policy_rules_search.py`]

## 五、总结

三个研究对象的核心结论：

1. **测试模块**：四层金字塔结构完整，API 覆盖率 100%，但缺少代码覆盖率工具、CI pipeline、质量评估框架。预存 ~56 测试失败为已知债务。

2. **Skill 质量**：`settlement_explain_skill` 架构良好（Strategy Pattern），有自己的单元测试，但缺少端到端集成测试、输出质量评估、路由准确性评估。所有测试用 mock 数据，未验证真实 MCP/SQL Server/Milvus 集成。

3. **知识召回质量**：检索管线完整（query_understanding → semantic_mapping → Milvus → reranker），Milvus 数据 337 rules 就绪。但**完全缺少检索质量评估能力**（无 Recall@k、MRR、ground truth dataset），现有测试只是单元级的 API 正确性验证。
