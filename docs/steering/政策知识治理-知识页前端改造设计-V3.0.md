# 政策知识治理 · 知识页前端改造设计（V3.0）

> **定位**：知识页（`/policy-knowledge/knowledge`）从"三栏加工流水线"重构为
> "**知识工作台（列表） + 知识详情页（原文×事实双栏 + 语义映射抽屉）**"的前端改造设计。
> **依据**：`docs/steering/政策知识治理-需求迭代记录.md` 迭代 13 评审意见
> （用户对当前三栏页面的核心对象与用户任务未收住的问题）。
> **范围**：本文只给前端修改设计；后端模型扩展列为依赖项（§7），不展开实现。
> **对照现状**：`src/apps/portal/app/policy-knowledge/knowledge/page.tsx` +
> `src/apps/portal/src/components/policy-knowledge/workbench-*.tsx`（V2.1 §5.5 三栏实现）。

---

## 1. 设计结论

> 知识页的用户只有两个真实任务：
> **① 批量回答"有哪些知识要处理、哪些有问题"；② 单条回答"这条知识对不对、能不能被 Agent 稳定使用"。**

| 旧（三栏流水线） | 新（两页一对象） |
|---|---|
| 左：单元列表（来源） | **工作台**：知识列表 + 筛选 + 问题清单（批量管理） |
| 中：结构化知识卡片（加工） | **详情页**：左 60% 政策原文 × 右 40% 知识事实（精细审核） |
| 右：指标/值域标化表格（加工） | **抽屉**：语义映射（概念 / 值域 / 指标三类关联，按需打开） |
| 顶部流程暗示：单元审核→知识评审→值域标化→指标映射 | 顶部只放：文件 / 版本 / 有效状态 / 进度 / 保存审核 |

核心对象收敛为**一条政策知识事实**，流程状态降为辅助信息。

---

## 2. 页面路由与导航

现有导航（`policy-knowledge/layout.tsx`）：概览 / 文档 / 单元 / 知识 / 测试。**导航不变**，仅改造"知识"tab 内部：

```text
/policy-knowledge/knowledge                → 知识工作台（列表，改造现有页）
/policy-knowledge/knowledge/[knowledgeId]  → 知识详情页（新增，双栏 + 抽屉）
```

- 工作台 = 现有 `knowledge/page.tsx` 的**外壳复用**（文档选择器、指标/发布通知栏保留），内容从 `KnowledgeWorkbench`（三栏）替换为 `KnowledgeWorktable`（列表）。
- 详情页 = 新路由 + 新组件树；从工作台点击行进入，面包屑返回。
- 旧三栏组件（`workbench-units-column` / `workbench-knowledge-column` / `workbench-standardization-column`）**不继续作为主页面**，其高价值逻辑（高亮联动、评审落库、语义对齐调用）抽取复用进新页面。

## 3. 页面一：知识工作台（列表）

**定位**：只做"搜索、筛选、发现问题、进入单条处理"，不铺开原文与全部映射。

### 3.1 布局

```text
┌─ 顶部（复用现有页头）─────────────────────────────────────────┐
│ 文档选择器 │ 契约 vX │ 内部候选版本chips │ 批量审核工具栏          │
├─ 筛选区 ─────────────────────────────────────────────────────┤
│ 知识类型▾ 来源文件▾ 适用范围▾ 完整度▾ 映射状态▾ 审核状态▾ 风险☑ 搜索□ │
├─ 知识列表（默认按 风险×完整度×审核状态 排序）──────────────────┤
│ [类型徽标] 知识标题（主题+结论）        完整度▦ 72% │ 审核：待审核 │
│   来源：第三十五条第二款 · 适用范围：职工/住院/三级 · 有效期：2025.1.1起 │
│   ⚠ 缺适用人群 · 数值无单位 · 与XX文件疑似冲突                     │
├─ 行操作： [通过] [退回补充] [标记不适用] · 更多▾（拆分/合并/重抽取）───┤
└────────────────────────────────────────────────────────────────┘
```

### 3.2 列表字段（前端映射现状数据）

| 列 | 数据来源（现有 `KnowledgeItem`/`ApprovedUnit`） | 说明 |
|---|---|---|
| 知识标题 | `business_sentence` 截断 + 主题字段 | 首屏判读"讲什么" |
| 知识类型 | `rule_type`（payment_ratio/deductible/cap/eligibility…）→ 中文类型 | 待遇标准/计算规则/资格条件/办理流程/排除规则 |
| 来源文件+条款 | `citations[0].title` + `unit.path` | 出处可溯 |
| 适用范围摘要 | `psn_type/med_type/hosp_lv/insu_type/setl_type` 拼接 | 人群/业务/机构等级 |
| 有效期 | 后端新增（§7 P1）；未上线时显示"待确认" | — |
| 完整度 | **前端启发式**（§5.4） | 取代置信度作为主指标 |
| 映射状态 | `standardized_fields[].status` 聚合：已映射 n/未映射 m | 概念/值域/指标三态后续细化 |
| 审核状态 | `review_status`（pending/approved/rejected）+ 生命周期扩展 | 待审核/已通过/需补充/已失效 |
| 风险提示 | **前端问题检测器**（§5.5） | 条件缺失/冲突/无证据等 |

### 3.3 批量操作（主工具栏）

- 批量**通过 / 退回补充 / 标记不适用**（复用现有评审落库 API `reviewKnowledge`，状态映射：approved / 新增 rejected=退回 / not_applicable 需后端扩展枚举）。
- **移除**「批量生成指标草稿」为主操作；"生成语义映射建议"降级为详情页抽屉内的次级动作（§4.5）。

## 4. 页面二：知识详情页（原文 × 知识事实）

**定位**：单条知识的精细审核与长期维护，可追溯、可编辑、可被 Agent 稳定使用。

### 4.1 双栏布局（替代三栏）

```text
┌───────────────────────────────┬──────────────────────────────┐
│ 左侧：政策原文（约60%）        │ 右侧：知识事实（约40%）        │
│                               │                              │
│ · 文档目录（章节树，定位条款）  │ · 知识标题（可编辑）           │
│ · 当前引用段落（source_text）  │ · 知识类型（下拉）             │
│ · 上下文前后段（相邻 unit）    │ · 适用条件（chips 编辑）       │
│ · 原文高亮（联动右侧字段）     │ · 规则行为 + 规则结果（表单）   │
│ · 页码/条款号（后端P1占位）    │ · 例外及补充                   │
│ · 历史版本差异（后端P2占位）   │ · 生效范围（有效期）            │
│                               │ · 证据完整度 + 机器可用性      │
│                               │ · 审核意见 + 主操作按钮        │
├───────────────────────────────┴──────────────────────────────┤
│ 语义映射抽屉（从右侧按钮打开）：业务概念 │ 标准值域 │ 数据指标   │
└──────────────────────────────────────────────────────────────┘
```

### 4.2 左侧：政策原文与条款定位

- **目录导航**：`unit.path` 还原为章节树（如 `第一条 → （一）`），点击定位到对应 unit 卡片。
- **当前段落**：渲染选中 `unit.source_text` 全文 + 数字高亮（复用 `EvidenceQuote`）。
- **上下文**：`document.units` 中相邻 `order_no` 的前后 1–2 个单元，折叠/展开。
- **双向高亮联动**：右侧任意条件/结论/数值点击 → 左侧原文中该值 `<mark>` 高亮并 `scrollIntoView`（复用现有 `HighlightText` + `onLocate` 机制，从"中栏→左栏"改为"右栏→左栏"）。
- **证据锚点**：证据块固定于原文区顶部（政策名 + 条款号 + 原文片段），保证"证据-知识"不分离。

### 4.3 右侧：知识事实编辑器

一条知识按以下结构组织（对应目标模型，字段名沿用现有 `KnowledgeField.field_code`）：

| 区块 | 字段（现有 field_code） | 交互 |
|---|---|---|
| **知识结论** | 结论句（`business_sentence` 可编辑） | 单行输入，变更后提示"证据一致性需复核" |
| **适用条件** | `psn_type / med_type / hosp_lv / insu_type / setl_type / time_period` | chips 编辑（增删），每个条件点击→左栏高亮 |
| **规则行为** | 行为类型（固定值/按比例/阶梯/排除/资格） | 下拉；由 `rule_type` 推断默认 |
| **规则结果** | `payment_ratio / deductible_amount / cap_amount / amount_band` + 单位 | 数值输入 + 单位下拉；每个值点击→左栏高亮 |
| **例外及补充** | `rule_value / exception` 文本 | 多行编辑；"是否存在未处理例外"计入完整度 |
| **生效范围** | 有效期（起止） | 日期输入；后端 P1，未上线时占位 |
| **证据** | `citations[0]`（title/evidence/unit_id） | 只读展示 + 定位按钮；页码/条款号为后端 P1 |
| **机器可用性** | 问答 / 计算 / 资格判断 三开关 | 前端推断（§5.6），可人工改 |

> **要点**：现有 `fields[]` 已经是"半结构化条件/结果"，本页做的是**分组编排 + 可编辑 + 可追溯**，而不是新造一套模型；字段分层（fact/dimension/descriptive，`workbench-shared.tsx`）直接复用。

### 4.4 审核：问题驱动 + 主操作

**主操作**（替换"批量生成草稿"的支配地位）：

```
[保存草稿] [通过审核] [退回补充] [标记不适用] · 更多▾：拆分知识 / 合并知识 / 重新提取
```

- **保存草稿**：本地编辑持久化（后端 P1 新增 `knowledge_drafts`；前端先用 `review_note`/本地 state 降级）。
- **通过 / 退回 / 不适用**：走现有评审落库 API（`review_status` 扩展 rejected→需补充、新增 not_applicable）。
- **拆分 / 合并**：详情页内发起，后端 P1（一条原文多个结论时提示拆分——由问题检测器触发）。

**问题清单**（右上角，点击定位对应字段）：由 §5.5 检测器生成，审核人只处理问题。

### 4.5 语义映射抽屉（替代右栏常驻）

- 入口：右侧"语义映射"按钮；**不常驻主页面**。
- 抽屉内三分类 Tab：

```
① 业务概念关联   起付线 / 支付比例 / 医院等级 / 参保类型（现有 semantic/metrics）
② 标准值域关联   "职工医保"→标准参保体系；"三级医院"→标准医院等级（value-domains）
③ 数据指标关联   仅当需要从业务数据取实际值时才绑定（如本次起付线、年度累计费用）
```

- **政策参数 ≠ 业务指标**（本次评审的核心纠偏）：
  - **政策参数**（如"三级医院首次起付标准 1300 元"）→ 属于知识事实本身，**不强制绑定指标**；在抽屉②中只做概念/值域关联。
  - **业务指标**（如"患者本次实际起付线"）→ 才进入抽屉③做指标绑定。
  - UI 区分：③内指标行标注"来自业务数据"；①/②标注"政策概念/标准值域"。现有 `Metric.metric_type` 增加"参数/指标"维度（后端 P1）。
- 复用现有语义对齐 API（`bindings / metrics / standard-values`，PG 持久化已具备）；交互从"表格行操作"改为"抽屉卡片 + 建议/确认"：**系统自动建议候选关联，人工确认**。

## 5. 前端逻辑设计

### 5.1 组件树（新增/改造）

```text
knowledge/page.tsx（改造）
 └─ KnowledgeWorktable（新）           知识工作台
     ├─ KnowledgeFilters（新）
     ├─ KnowledgeList（新）
     │   └─ KnowledgeRow（新，含风险chips）
     └─ BatchReviewBar（新）

knowledge/[knowledgeId]/page.tsx（新）
 └─ KnowledgeDetail（新）
     ├─ SourcePanel（新，左60%：目录/原文/上下文/高亮）
     ├─ FactEditor（新，右40%）
     │   ├─ FactConclusion / FactConditions / FactBehavior / FactResult /
     │   │  FactExceptions / FactValidity / FactEvidence / FactMachineUse
     ├─ ReviewPanel（问题清单 + 主操作）
     └─ SemanticMappingDrawer（新，三Tab）

复用（从三栏抽取）：
 ├─ EvidenceQuote / HighlightText / fieldTier / readableValue（workbench-shared）
 ├─ 评审落库 API reviewKnowledge；语义对齐 API bindExistingMetric/createMetricDraft/proposeStandardValue
 └─ 文档选择器 / 通知栏（现有 page 外壳）
```

### 5.2 状态管理

- **工作台**：筛选条件 + 选中集 + 批量动作 → 组件局部 state（沿用现有轻量模式，不引入全局 store）。
- **详情页**：`knowledgeId` 路由参数 + `getWorkbenchDocument` 加载文档后按 id 定位；编辑草稿存本地 state，保存时调后端（P1）或暂存 `review_note`。
- **跨页面联动**：无全局状态；工作台行点击 → 详情页 URL 传参。

### 5.3 数据流

```text
getWorkbenchDocuments → 文档选择器（复用）
getWorkbenchDocument(docId) → units[]（含 knowledge[]）
  → 工作台：拍平为 knowledge 列表 + 聚合列 + 检测器
  → 详情页：按 knowledgeId 定位 → SourcePanel 渲染 unit.source_text，
            FactEditor 编排 knowledge.fields，Drawer 调语义对齐 API
评审/保存 → reviewKnowledge / (P1) draft API → 落库 → 回列表刷新
```

### 5.4 完整度（取代置信度为主指标）

前端启发式评分（0–100），各维度可点击查看明细：

| 维度 | 判定（现有数据） |
|---|---|
| 结论明确 | 存在 `payment_ratio/deductible_amount/cap_amount/rule_value` 等结果字段 |
| 适用对象 | 存在 `psn_type/med_type` 任一 |
| 业务场景 | `med_type/hosp_lv/insu_type` 覆盖 |
| 有效期 | 后端 P1；未上线记 0 并提示 |
| 原文证据 | `citations[0].evidence` 非空且与结论值在原文中可匹配（`source_fidelity`） |
| 数值单位 | 结果字段含 `元/%/万元` 等单位 |
| 例外处理 | 无未处理例外标记 |
| 概念映射 | 关键字段完成值域/概念关联（`standardized_fields` 非 unmapped 比例） |

> 置信度（`confidence.overall`）保留为次要信息（tooltip），不再作为卡片主数字。

### 5.5 问题检测器（前端规则集）

工作台行/详情页右上角展示，问题可点击定位：

| 问题 | 规则 | 严重度 |
|---|---|---|
| 缺少适用人群 | 无 `psn_type` | 高 |
| 缺少明确结论 | 无任何结果字段 | 高 |
| 数值缺少单位 | 结果字段纯数字无单位 | 中 |
| 疑似应拆分 | 同一 unit 内 `rule_value` 含多个分段值/同一 knowledge 多结果 | 中 |
| 值域未映射 | `standardized_fields` 存在 unmapped/invalid | 中 |
| 与同文件他条冲突 | 同一 `psn_type+med_type` 下两 knowledge 结果值不同 | 高 |
| 证据不足 | 无 citation 或 evidence 为空 | 高 |
| 低置信 | `confidence.overall < 0.8` | 低 |

### 5.6 机器可用性推断（前端默认值，可人工改）

- 可用于**问答**：完整度 ≥ 60% 且证据非空；
- 可用于**计算**：存在数值结果且单位明确；
- 可用于**资格判断**：存在 `psn_type/med_type` 条件且结论为资格/排除类。

## 8. 分阶段落地计划

| 阶段 | 内容 | 验证 |
|---|---|---|
| A | 工作台列表（前端改造，无后端依赖；检测器/完整度用启发式） | 现有 vitest 用例更新 + 手工筛选/批量通过 |

**建议先做 A + B**（不依赖后端扩展即可显著改善"核心对象未收住"问题），C/D 随后端依赖推进。

## 9. 取舍与风险

1. **旧三栏代码处理**：不立即删除；工作台/详情页稳定后，将 `workbench-*` 中复用逻辑抽取为共享模块再清理死代码（避免并行期破坏现有验证通过的逻辑）。
