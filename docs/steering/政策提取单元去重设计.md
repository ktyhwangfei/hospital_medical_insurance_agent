# 政策提取单元去重设计

> 状态：设计稿（待评审）
> 日期：2026-08-25
> 背景：语义发现检测器修复（issue-20）后，跨单元一致性检测归零。复盘发现其诱因是
> `policy_extractions` 存在重复单元；本设计在管线源头消除重复，而非在检测器侧打补丁。

## 1. 问题

真实库 17 组重复（同 `doc_id + source_text_hash` 多行），分两类：

| 类别 | 数量 | 形态 | 影响 |
|---|---|---|---|
| A. dummy 脏数据 | 22 行 | 「示例提取结果（dummy 模式）」，archived | 无（扫描已排除），但污染审计与统计 |
| B. 归档复活 | 9 组 | **同 doc 同 hash 同 unit_id，一行 archived 一行 reviewed** | 真实问题：`reconcile` 归档旧版后，`batch_create_extractions` 的 UPDATE 分支把 archived 行复活为 draft，同一原文两行并存 |

B 类正是此前喂给检测器 3「同一原文、提取完整度不一」的噪声源。

## 2. 根因

两套写入路径的去重语义不一致：

```
batch_create_extractions（追加式）
  查 doc+unit+hash（有 unit）或 doc+hash（无 unit）→ 命中则 UPDATE（status 强制回 'draft'）

reconcile_extractions（单事务重写式）
  本轮行全部写入；本轮未覆盖的旧行整体置 archived
```

时序冲突：`reconcile` 归档旧行后，任何一次 `batch_create` 落到同 hash 就把该
archived 行 UPDATE 回 draft——复活。反过来，`batch_create` 写入的 draft 行也会被
下一次 `reconcile` 归档（若未被本轮覆盖），再被下一次 `batch_create` 复活。

此外去重键含 `unit_id`：同原文若重跑时切句边界变化（unit_id 变），
doc+hash 查重失效，插入新行 → 同 doc 同 hash 不同 unit（真实库 466953309ccf
有 3 组）。

## 3. 设计目标

1. **同一文档内同一原文至多一行活跃记录**（unit_id 变化不再产生重复）；
2. 归档行不可被 UPDATE 复活（复活 = 语义倒退）；
3. 兼容既有数据（迁移幂等、可回滚）；
4. 去重判定全部走数据库唯一约束（应用层查重为辅助，不承担正确性）。

## 4. 方案

### 4.1 唯一索引（核心）

```sql
-- 活跃行唯一：同文档同原文只允许一行非 archived
CREATE UNIQUE INDEX IF NOT EXISTS uq_ext_active_doc_text
    ON policy_extractions (doc_id, source_text_hash)
    WHERE status <> 'archived';
```

部分唯一索引（partial unique index）：

- archived 行不受限（历史证据按设计保留多版，外键不丢）；
- unit_id 从键中移除——切句边界变化时新行替换旧行，而非并存；
- DDL 双写原则：`CREATE INDEX` 与启动迁移一致（无 ALTER 对应物，幂等）。

> ponytail: 先上部分唯一索引，若未来需要「同 unit 多版本活跃」再演化，不预建。

### 4.2 写入路径调整

`batch_create_extractions`（追加式）改为：

```
命中 archived 行（doc+hash，忽略 unit）→ 不复活，改为 INSERT 新行
  （唯一索引保证旧 archived 不挡路：WHERE status <> 'archived'）
命中活跃行 → 维持现状（UPDATE 该行）
```

`reconcile_extractions`（重写式）维持单事务：本轮未覆盖的活跃行置 archived。
两条路径在「活跃至多一行」上由唯一索引兜底，冲突时（并发重跑）靠 ON CONFLICT
不吞错，直接抛出让调用方重试——提取是幂等重跑场景，重试即收敛。

### 4.3 存量数据迁移（一次性）

```
1. 复活组（B 类）：每组保留 status 最「新」的一行（reviewed > draft），
   其余活跃行置 archived；已被双写的（同 unit 两行）合并为单行
2. dummy 行（A 类）：22 条 archived 保留（不动历史），但提供运维清理脚本
   scripts/purge_dummy_extractions.py（按 source_text 前缀「示例提取结果」+archived）
3. 迁移脚本与索引创建同事务，先清数据后建索引，保证索引一次建成
```

### 4.4 验证

| 项 | 方式 |
|---|---|
| 唯一索引生效 | 单测：同 doc 同 hash 第二次 INSERT 活跃行抛 UniqueViolation |
| batch_create 不复活 | 单测：archived 行存在时走 INSERT 分支，archived 行不变 |
| reconcile 幂等 | 现有回归 + 新增「重跑后无复活组」断言 |
| 存量清零 | 迁移后 SQL：`group by doc_id, source_text_hash having count(*) filter (where status<>'archived') > 1` 返回 0 行 |
| 检测器侧 | PDSC 扫描重跑，cross_unit_inconsistency 保持 0（不再依赖检测器 3 的跨文档门限兜底） |

## 5. 风险与边界

- **切句变化导致内容丢失？** 不会丢原文（旧行 archived 保留），但 unit_id 映射会指向新行；
  受影响的是 `policy_unit_claims` 等按 extraction_id 的外键——archived 行保留即可追溯。
- **并发写入**：两条路径并发同 doc 时靠唯一索引冲突暴露，调用方重试；不做应用层锁
  （提取无实时并发场景）。
- **回滚**：`DROP INDEX uq_ext_active_doc_text` 即回退约束；迁移脚本配套 down（恢复
  原 status 需按迁移日志表，见脚本设计）。
