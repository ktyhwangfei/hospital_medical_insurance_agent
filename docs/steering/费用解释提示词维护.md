# 费用解释提示词维护

费用解释的正常路径为：确定性费用分解 → 当前目标及计算依赖 → 模型解释 → 事实校验 → SSE 正文。
金额计算、待遇适用与缺证状态由分解内核决定；文字组织由模型根据提示词完成。

## 修改入口

只修改 `src/runtime/policy_qa/fee_decomposition/explanation_prompt.yaml`：

- `system_prompt` 的“费用分解算法”说明模型必须理解的整体业务过程。
- “字段解释”集中维护个别字段的解释需求，如自付二不重复相加、大病/救助如何解释分桶、账户/现金如何说明。
- “回答范围”和“表达”控制回答详略、段落、术语及需要省略的内部信息。
- `repair_prompt` 是事实校验失败后的统一纠正指令。

文件每次请求重新读取；保存合法 YAML 后，下一轮问答即使用新提示词，无须重启服务。
修改旧 `skills/settlement_explain_skill/prompt_template.yaml` 不会改变费用分解的这条解释链路。

不要再增加按字段跳过模型、强制某一种等价算式或按关键词删掉模型整句的逻辑。
确实需要新增业务数据或修改计算规则时，仍应修改对应适配器/内核并完成测试，不能用提示词补造事实。

## 运行与回退

`FEE_EXPLANATION_MODE=structured` 为默认模型解释；旧值 `adjust` 使用同一条链路，避免两套提示词互相偏离。
`deterministic` 用于离线与测试。非法值会记录警告并使用 `structured`，不再静默关闭模型。
无数据或目标歧义时仍返回明确的缺证/澄清结果。

模型不合格回答最多纠正一次，仍不合格或网关故障则返回原单和确定性计算依据。
日志记录 `attempted`、`used_model`、`fallback_reason`，可区分未调用、调用失败与校验拒绝；不记录模型原文。
账单数字、来源对话框与计算核对视图保留事实展示；其中的固定说明不作为模型必须照抄的正文。

## 修改后的检查

按 Unit → API → Flow 顺序运行相关测试；提示词修改至少检查四条链路的总费用、单字段、零金额、分桶、多目标和明细追问。

```powershell
uv run python -m pytest src/tests/unit/runtime/policy_qa/fee_decomposition -q
uv run python -m pytest src/tests/integration/api/test_policy_qa_fee_decomposition_api.py -q
uv run python -m pytest src/tests/integration/flow/test_policy_qa_outpatient_settlement_flow.py -q
```

单测中的模型替身用于检查调用、目标覆盖和错误回退；实际语言质量还应使用配置好的真实模型复验。
事实校验检查数字来源、字段归属、目标/合计分量遗漏与明确等式，不能代替对自然语言因果关系的业务评审。
