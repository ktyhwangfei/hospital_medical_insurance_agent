> **版本**：V1.0（2026-08-06）
> **范围**：`src/apps/portal/app/policy-knowledge/page.tsx`（概览页单页改造），不动 layout 导航与其他 tab。
> **设计来源**：`设计.pen`（政策知识对齐工作台设计稿，组件库 + 三栏布局 + 弹框态 + 移动端）+ 本仓政策知识治理功能现状。
> **上游依据**：`政策知识治理平台设计-V2.1.md` §5.2（概览·治理看板）、`政策知识治理-需求迭代记录.md` 迭代 16/17。

## 1. 背景与目标

设计.pen 为「政策知识对齐工作台」定义了一套完整的视觉与交互语言：评审流引导（单元审核 → 知识评审 → 值域标化 → 指标草稿）、状态徽标体系、置信度轨道、字段 Chip、标化概览四格、医疗蓝浅色令牌。

当前概览页只回答"有多少"（四张统计卡 + 生命周期堆叠条），没有回答治理看板更该回答的两个问题：

1. **流水线跑到哪了** —— 构建 → 审核 → 发布 → 标化各阶段积压多少、卡在哪；
2. **我现在该做什么** —— 待审、待发布、待处理决策任务、低置信预警的 actionable 入口。

**目标**：以设计.pen 的视觉语言重构概览页，把"治理流水线状态 + 待办队列 + 质量风险"提到首屏，全部优先使用现有 API，缺口显式标注待新增。

**非目标**：不实现影响分析后端（保持占位）、不改 layout 导航配色、不动知识/构建/审核子页面。

## 3. 信息架构（ wireframe ）

```
┌─ 页头 ────────────────────────────────────────────────────────────────┐
│ 治理概览                                    [语义契约 v2.1] [生效版本 R3]│
├─ A. 治理流水线（设计.pen 评审流引导，6 步，每步可点击）────────────────┤
│ ①文档 ●5 → ②单元 ●12 → ③知识提取 ●2运行 → ④知识审核 ●4 → ⑤待发布 ●1 → ⑥已生效 R3 │
├─ B. 待办队列（actionable，设计.pen 徽标 + 左色条卡片）────────────────┤
│ ⚠ 待审变更集 4    → 知识/审核    │ 🕐 待发布 1    → 知识/发布          │
│ ⚠ 决策任务待处理 N → 知识/决策   │ ⚠ 低置信预警 N  → 知识/审核(低置信)  │
├─ C. 统计卡带（保留现有四卡，改令牌 + 补 sub）─────────────────────────┤
│ 📄文档 │ ⚓单元 │ 💡已发布知识(进检索池) │ 🛡待审知识                   │
├─ D. 生命周期分布（保留堆叠条）+ E. 标化概览（设计.pen 四格）───────────┤
│ Draft/Review/Published/Rejected 堆叠条  │ 已映射 值域未映射 未映射 映射率│
├─ F. 质量与风险 ────────────────┬─ G. 影响分析（占位，待新增 API）──────┤
│ 平均保真度/完整度 · 风险摘要 ·  │ 政策变更 → Unit → Knowledge → Metric │
│ 最近质量门禁结果               │ [待新增 policy-pipeline/impact/recent]│
└────────────────────────────────┴──────────────────────────────────────┘
```

**首屏优先级**：A（流水线）> B（待办）> C（统计）> D/E > F > G。移动端按此顺序单列堆叠（设计.pen 移动端折叠原则）。

## 4. 区块设计

### A. 治理流水线（PipelineFlow）⭐ 首屏核心

复用设计.pen「评审流引导」模式：圆点/数字 + 步骤名 + 计数 chip + 连接线。**完整覆盖治理生命周期：文档 → 单元 → 知识 → 发布**（用户确认口径：从文档开始，非仅单元）。

| 步骤 | 数据来源 | 计数含义 | 点击跳转 |
|------|----------|----------|----------|
| ① 文档 | `policy-pipeline/summary` → `documents_count`（`documents_raw>0` 时副标"导入 · N 待解析"） | 政策文档总数 | `/policy-knowledge/documents` |
| ② 单元 | `GET /policy-workbench/knowledge-build/eligible-units`（仅取长度；注意该接口 ~2s，见 §7 性能） | 可构建单元数 | `/policy-knowledge/units` |
| ③ 知识提取 | `GET /policy-workbench/knowledge-build/tasks` → status ∈ `QUEUED/RUNNING` | 提取中任务数 | `/policy-knowledge/knowledge/build` |
| ④ 知识审核 | 同上 → status = `WAITING_REVIEW`（构建任务口径，与构建页五卡一致；ChangeSet 状态机为 `PENDING_REVIEW`，不同枚举勿混用） | 待审批次数 | `/policy-knowledge/knowledge/review` |
| ⑤ 待发布 | 同上 → status = `APPROVED_PENDING_RELEASE` | 审核通过待发布数 | `/policy-knowledge/knowledge/releases` |
| ⑥ 已生效 | `GET /policy-workbench/releases/active`（**404 → "未发布"**，非错误） | 当前版本号 `release_id` | `/policy-knowledge/knowledge/published` |

**步骤状态机**（沿用设计.pen 语义）：`idle（muted）→ active（primary 脉冲）→ done（success ✓）`。判定：counter 步骤计数 >0 为 active（需处理），=0 为 done；①文档/②单元为 info 恒蓝信息态。

### B. 待办队列（WorkQueue）

左色条卡片（沿用现有 StatCard hover 模式，配色取设计.pen warning/danger soft 对）：

| 待办 | 数据源 | 展示 | 跳转 |
|------|--------|------|------|
| 待审变更集 | governance/dashboard `change_sets_by_status.PENDING_REVIEW`（+ `NEEDS_DECISION`） | 数量 | 知识/审核 |
| 待发布 | `knowledge-build/tasks` status = `APPROVED_PENDING_RELEASE`（构建任务口径，与迭代 17 构建页五卡一致） | 数量 | 知识/发布 |
| 决策任务待处理 | governance/dashboard `tasks_pending` + `tasks_by_type` | 数量 + 类型分布 chip | 知识/决策 |
| 低置信预警 | `policy-pipeline/extractions?page_size=100` 前端统计（**保持现状**，上限 100 条标注"前 100 条中"） | 数量 + 阈值说明 <0.8 | 知识/审核 |

空态：全部清零时显示"暂无待办 · 流水线畅通"（success-soft 底）。

### C. 统计卡带（保留 + 微调）

沿用现有四卡（文档/单元/已发布知识/待审知识），改动仅：图标色换设计.pen 令牌、待审知识卡改链 `/policy-knowledge/knowledge/review`（现链 `knowledge?sub=audit` 为旧锚点，核实后修正）。

### D. 生命周期分布（保留）

现有堆叠条保留；"已替代/已废止"提示条保留（V2.1 §3.1 数据未承载）。

### E. 标化概览（SemanticStrip，设计.pen 右栏四格复用）

四格横排（边框分隔、标签 9.5px muted + 值 15px 700，与设计.pen 标化概览一致）：

| 格 | 数据源（`GET /semantic/summary`） | 值色 |
|----|----------------------------------|------|
| 已映射 | `mapped_count` | success |
| 未映射 | `unmapped_count` | primary |
| 映射率 | `mapping_rate`（百分比） | text-primary |
| 指标总数 | `metrics_count` | muted |

整卡点击跳 `/semantic-layer`（跨链只读，不在治理平台内编辑映射 —— V2.1 §5.6）。

### F. 质量与风险

| 项 | 数据源 |
|----|--------|
| 平均来源保真度 / 平均完整度 | governance/dashboard `avg_source_fidelity` / `avg_completeness`（进度轨道样式，设计.pen 置信度轨道复用） |
| 风险摘要 | governance/dashboard `risk_summary`（按级别 chip 计数） |
| 最近质量门禁 | `GET /policy-workbench/releases/active` → `GET /policy-workbench/releases/{id}/quality/latest`（有 active 才查；无则显示"未发布"） |

### G. 影响分析（占位保留）

保留现有占位卡，文案微调指向**待新增** `GET /policy-pipeline/impact/recent`（V2.1 §5.2 已规划），不在本期实现。

## 5. 视觉规范（设计.pen 令牌 → Tailwind 映射）

概览页内部统一采用设计.pen 浅色医疗令牌（`variables` 节）：

| 令牌 | 色值 | 用途 | Tailwind 落法 |
|------|------|------|----------------|
| `page-bg` | `#F2F5F9` | 页面底 | 沿用 layout 的 slate-50 渐变，不另设 |
| `surface` / `surface-soft` | `#FFFFFF` / `#F6F8FB` | 卡片 / 副标题条 | `bg-white` / `bg-[#F6F8FB]` |
| `border` / `border-strong` | `#DCE3EC` / `#C3D0E2` | 卡片边 / 强调边 | `border-[#DCE3EC]` |
| `primary` / `primary-soft` | `#1E5AA8` / `#E9F1FB` | 主色（步骤激活、链接、主按钮） | `text/bg-[#1E5AA8]` |
| `success` / `success-soft` | `#1C8A55` / `#E5F6EC` | 已通过、已映射、畅通态 | 同上模式 |
| `warning` / `warning-soft` | `#A16207` / `#FBF0DC` | 待办、值域未映射、低置信 | 同上 |
| `danger` / `danger-soft` | `#C0392B` / `#FBEAE8` | 驳回、高风险 | 同上 |
| `indigo` / `indigo-soft` | `#4F46E5` / `#EEF0FD` | 知识类徽标 | 同上 |
| `text-primary/secondary/muted` | `#1F2A37 / #4B5A6C / #7B8A9C` | 三级文字 | `text-slate-800/600/400`（近似映射，避免散色） |
| `font-sans` / `font-mono` | Noto Sans SC / Geist Mono | 正文 / ID·数值 | 全局已有 Noto Sans SC；ID 列加 `font-mono` |

**组件复用约定**：状态徽标（圆角 8px、soft 底 + 实色字）、置信度/进度轨道（5px 高、圆角 3、border 色轨道 + 语义色填充）、四格概览（右边框分隔、标签 9.5px muted、值 15px 700）、步骤引导（圆 + 连接线）。全部用 Tailwind 内联实现，不新增 UI 库依赖。

**与 layout 的关系**：layout 导航 active 色仍为 emerald（本期不动），概览页内部以 `#1E5AA8` 为主色 —— 已识别为不一致点，后续迭代统一（见 §9 后续）。

## 6. 数据来源汇总

**全部使用现有接口，本期零后端改动：**

| 接口 | 用途 |
|------|------|
| `GET /policy-pipeline/summary` | 文档/单元/已发布/待审计数（实际字段：`documents_count/documents_raw/extractions_count/extractions_draft/reviewed/published`，**无 low_confidence_count**） |
| `GET /policy-pipeline/extractions?page_size=100` | 低置信统计（保持现状，≤100 条上限） |
| `GET /policy-knowledge/stats` | Milvus 已发布总数（检索池） |
| `GET /policy-workbench/governance/dashboard` | 变更集状态分布（`PENDING_REVIEW/NEEDS_DECISION/...`）、决策任务、风险摘要、平均保真度/完整度 |
| `GET /policy-workbench/knowledge-build/tasks` | 流水线②③④计数（`QUEUED/RUNNING/WAITING_REVIEW/APPROVED_PENDING_RELEASE`） |
| `GET /policy-workbench/knowledge-build/eligible-units` | 单元就绪计数（慢接口，见 §7） |
| `GET /policy-workbench/releases/active` + `…/quality/latest` | 生效版本 + 最近质量门禁（均可能 404，按"未发布/暂无"处理） |
| `GET /semantic/summary` | 标化四格（`mapped_count/unmapped_count/mapping_rate/metrics_count`） |

**待新增（仅标注，不本期实现）**：`policy-pipeline/impact/recent`（影响报告）、评审时效（待审时长分桶）、发布流水线汇总、质量门禁趋势。

**加载策略**：`Promise.allSettled` 并发，单接口失败仅降级对应区块为"暂不可用"卡片，不拖垮整页（现页面是整页报错）。

## 7. 性能与边界

- `eligible-units` ~2s（迭代 16 已诊断）：流水线步骤①计数**懒加载**——首屏先渲染骨架，到达后填充；不因它阻塞 A/B/C 区。
- `governance/dashboard` 单接口覆盖 B/F 大半数据，只调一次。
- `extractions?page_size=100` 低置信扫描保持现状（上限 100 条时标注"前 100 条中"）；后端 `summary.low_confidence_count` 字段列入 Phase 2。
- 空数据约定：无 active release → ⑤显示"未发布"，F 区质量门禁显示"暂无"；dashboard 接口失败 → B/F 降级，A/C/D/E 不受影响。
