# 医保 Agent · 政策问答前端改造设计（V4.0）— 智能体中心

> **版本**：V4.0 ｜ **日期**：2026-09-14 ｜ **状态**：设计评审稿
> **定位**：`/policy-qa` 重构为**智能体中心（Agent Hub）**——一个页面承载三个各司其职的智能体（政策问答 / 结算解释 / 运营问数），各自有独立身份与工作区，统一展示、无需到处找。
> **评审演化记录**（2026-09-14，用户六轮决策，此为终稿方向）：
> 1. V2.0 否决：三套独立页面骨架 = 碎片化，视觉失控
> 2. V3.0 否决：一个助手 + 三语境 tab = 会话归属/分组"感觉没啥用"，差异程度才是重点
> 3. **终稿**：三个**智能体**（非模式、非页面）→ 各自工作区**差异程度是核心**
>    - 政策问答 = **纯自然语言政策问答**，政策来源是重点（无结算单锚点，后端 broad router 已支持）
>    - 结算解释 = **按时间选择**（今天/本周/自定义），不是按结算单号；时段内结算单列表 → 点单看费用构成解释
>    - 运营问数 = **自然语言问数**，结果**同时**呈现数据表格 + 图表富块
>    - 会话归属/分组 = **砍掉**（用户判定无用），极简：每智能体记住最近会话 + 新会话按钮
> **前置事实**（2026-09-14 代码核实）：
> - 后端无智能体实体（"智能体"为产品层概念，后端 mode 路由承载）；`GET /policy-qa/settlement-explanation`、`GET /policy-qa/sessions`、`GET /sessions/{id}/trajectory`、`GET /semantic-layer/metrics` 已存在
> - 政策问答无结算单：后端 #33 broad router 已放行，**零改动**
> - 结算解释按时间：后端 `get_settlement_context` 仅支持按单号查，**无"按时间段列结算单"能力**——真实后端缺口（§七）
> - 运营问数：`data_query` 工作流 + `DataQueryResultBlock`（表格+图表）已存在
> - 项目无 framer-motion、无 `--font-mono`；图标 lucide-react（项目约定）；Tailwind v4 + oklch tokens

---

## 〇、一句话结论

> **这不是"一个助手的三个模式"，是"一个中心里的三个智能体"。** 政策问答智能体回答政策（来源可追溯）、结算解释智能体按时间段浏览结算（选时间→看单据→追问）、运营问数智能体用自然语言提数（回答必带表格+图表）。三者共享外壳（智能体切换器 + 视觉系统）与输入哲学（自然语言优先），但**工作区内部是三种真正不同的交互语法**——差异程度是本设计的第一重点，会话归属被明确砍掉。

## 一、背景与目标

### 1.1 为什么改（原始三问 + 评审收敛）

| # | 用户反馈 | 根因 | V4.0 解法 |
|---|---|---|---|
| 1 | 交互习惯与场景不匹配 | 三场景共用一套聊天套壳 | 三个**智能体**，各自工作区不同范式：对话问答 / 时间浏览 / 问数出表图 |
| 2 | 三个界面不够有质感 | 无设计系统 | 共享视觉系统 + 每智能体身份（图标/名字/降饱和身份色） |
| 3 | 会话历史有没有用 | 后端已自动管上下文；历史展示/分组**用户判定无用** | 极简：每智能体记住最近会话 + 新会话按钮，不做侧栏/分组 |

### 1.2 设计目标

1. **智能体中心**：一个页面，三个智能体，切换器常驻，永不离开页面去"找"。
2. **工作区差异是核心**：三智能体交互范式彻底不同（对话 / 时间浏览 / 问数），共享仅限外壳。
3. **政策来源可追溯**：政策问答的答案以来源卡片为视觉重点。
4. **时间驱动结算解释**：主输入是时间选择器，时段结算列表 + 单笔费用构成。
5. **问数必出表图**：运营问数自然语言提问，答案同时含数据表格 + 图表。
6. **会话极简**：不做历史分组/侧栏；后端记忆自动延续上下文。

## 二、设计原则

| 原则 | 说明 |
|---|---|
| **智能体不是模式** | 每个智能体是独立实体：身份（图标/名字/身份色）+ 独立工作区交互语法 + 独立最近会话 |
| **差异程度第一** | 工作区内部三种范式（对话 / 时间浏览 / 问数），不做表面化 tab 换色 |
| **自然语言优先** | 政策问答与运营问数的主输入都是自然语言；结算解释的时间选择是唯一结构化主输入 |
| **富块承载答案** | 来源卡片、费用构成、表格、图表都以富块内嵌答案，复用既有组件 |
| **会话极简** | 不做侧栏/分组/历史时间线；每智能体 localStorage 记住最近会话，新会话一键 |
| **克制动效** | 纯 CSS 过渡，不引入 framer-motion |
| **复用而非重写** | `DataQueryResultBlock`、`CalculationDisclosure`、`PolicySourcesDialog`、`VerificationSummary`、SSE 链全部复用 |

## 三、整体框架（智能体中心）

```
┌──────────────────────────────────────────────────────────┐
│ Header：医保AI导办平台 · [🤖 政策问答] [🧾 结算解释] [📊 运营问数] │
│              （智能体切换器：图标+名字+身份色，当前高亮）        │
├──────────────────────────────────────────────────────────┤
│                   当前智能体工作区（§四）                     │
│                                                            │
│   政策问答：对话画布（72ch）· 文字 + 来源卡片                 │
│   结算解释：时间选择器 → 时段结算列表 → 单笔费用构成           │
│   运营问数：对话画布 · 自然语言问数 → 表格 + 图表富块          │
│                                                            │
│   （切换智能体 = 工作区整体切换，轻 fade 150ms）              │
└──────────────────────────────────────────────────────────┘
```

- **智能体切换器**：Header 内三枚智能体 chip（图标 + 名字 + 身份色描边），当前高亮。切换 = 工作区整体切换（无路由变化、无页面跳转）——"省的到处去找"。
- **工作区**：每智能体独立组件树，内部交互语法完全不同（§四）。
- **会话**：极简处理（§五），不占主结构。

## 四、三个智能体工作区（重点：差异程度）

### 4.1 🤖 政策问答智能体 — 纯自然语言政策问答，来源是重点

```
┌──────────────────────────────────────────────┐
│ 政策问答智能体                                │
│                                              │
│ [用户] 门诊大额互助的报销比例是多少？          │
│ [助手] 在职职工门诊大额医疗互助费用按 80% 报销…│
│                                              │
│  📄 政策来源（重点，常显不折叠）               │
│  京医保发〔2024〕12号 §3.2 · 门诊大额互助     │
│  「门诊大额医疗互助费用由统筹基金按 80% 报销，│
│   年度封顶 10 万元。」                       │
│                                              │
│ [用户] 退休人员起付线标准呢？                 │
│ [助手] …（文字 + 来源卡片）                   │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ 直接问政策问题…                     [发送] │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

- **交互**：纯对话，无结算单锚点（无 chip、无单号要求）。
- **答案**：文字（72ch 排版）+ **政策来源卡片常显**（文档标题 + 条款 + 摘要 + 链接 `/policy-document/[docId]`）——来源可追溯是本智能体的核心价值，不做折叠引用角标。
- **复用**：`PolicySourcesDialog` 语义改造为内联来源卡片；`VerificationSummary` 保留核验摘要。

### 4.2 🧾 结算解释智能体 — 按时间选择，不是按结算单号

```
┌──────────────────────────────────────────────┐
│ 结算解释智能体                                │
│ 时间: [今天 ▾] [本周] [自定义日期范围]  ← 主输入│
├──────────────────────────────────────────────┤
│ 今日结算单（5 笔）                           │
│  1671213  张三  住院  12,386.40  ▸ 解释       │
│  1671218  李四  门诊   1,240.00  ▸ 解释       │
│  1680002  王五  住院  32,000.50  ▸ 解释       │
│  ⚠ 其中 1 笔含未解释费用项                    │
│ ── 点击「解释」→ 单笔费用构成富块 ──          │
│ 结算单 1671213 · 住院费用构成                 │
│ 总费用      12,386.40 元   ← 等宽大字         │
│ 统筹基金    8,432.50  68%  ██████████░░      │
│ 个人自付    2,953.90  24%  ████░░░░░░░░      │
│ 大额互助    1,000.00   8%  ██░░░░░░░░░░      │
│ 费用明细 ▸（每项展开 → 政策依据）             │
│ [针对此单追问…]                        [发送]  │
└──────────────────────────────────────────────┘
```

- **主输入 = 时间选择器**（今天/本周/自定义范围），**不是结算单搜索框**——经办按班次/时段工作，不是按单号找。
- **数据流**：选时段 → 该时段结算单列表（需 §7.1 新能力）→ 点「解释」→ `GET /settlement-explanation?settlement_id=X` → 费用构成富块 → 可追问（走 `stream.send`，已锚定）。
- **异常提示**：时段列表内标注异常项（如未解释费用项、可疑自付比），引导经办点开核对——按时间的价值在于**批量发现异常**，而非单点查询。

### 4.3 📊 运营问数智能体 — 自然语言问数，结果必出表格 + 图表

```
┌──────────────────────────────────────────────┐
│ 运营问数智能体                                │
│                                              │
│ [用户] 本月门诊次均费用是多少？               │
│ [助手] 本月门诊次均费用 512.40 元，环比 +3.2%。│
│  ┌ 数据表格 ───────────────────────────────┐ │
│  │ 月份   次均费用   环比    门诊人次        │ │
│  │ 7月    496.40    +1.8%   2,310          │ │
│  │ 8月    512.40    +3.2%   2,548          │ │
│  └────────────────────────────────────────┘ │
│  ┌ 图表（趋势/柱状）──────────────────────┐  │
│  └────────────────────────────────────────┘ │
│                                              │
│ [用户] 各科室药品费用排名呢？                 │
│ [助手] （表格 + 柱状图富块）                  │
│                                              │
│ ┌──────────────────────────────────────────┐ │
│ │ 用自然语言问运营数据…               [问数] │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

- **交互**：纯对话问数（NL 请求为主），指标 chip 仅在空状态作建议（辅助，非强制）。
- **答案**：**数据表格 + 图表两个富块同时呈现**（复用 `DataQueryResultBlock`）——"结果肯定得有表格类和图表类的"。
- **无结算单依赖**；口径/时间范围信息并入回答富块头部（如"口径：结算清单/人次"）。

### 4.4 差异程度对照

| 维度 | 政策问答 | 结算解释 | 运营问数 |
|---|---|---|---|
| 交互范式 | 对话问答 | **按时段浏览** | 对话问数 |
| 主输入 | NL 政策问题 | **时间选择器** | NL 数据问题 |
| 答案形态 | 文字 + **来源卡片** | 时段列表 + **费用构成富块** | **表格 + 图表富块** |
| 结算锚点 | 无 | 时段内多笔（点选） | 无 |
| 核心价值 | 来源可追溯 | 按时段发现/核对 | 拿到数据 |

## 五、会话处理（极简，用户判定无用即砍）

- **不做**：会话侧栏、按模式分组、历史时间线（V3.0 否决点）。
- **做**：每智能体 localStorage 记住自己的最近会话 ID（`policy-qa-session-id-<agent>`），切回该智能体自动恢复；Header 内"新会话"按钮（等价 `@新会话`）。
- **上下文**：后端 `MemoryManager` + `ContextComposer` 已自动管理（4000 token 预算、importance 过滤 + 摘要压缩），连续追问不断片；轮数 ≥15 时 composer 上方轻提示"建议新会话"。
- 复用现有 `restoreSessionState`（刷新/切回恢复同路径）。

## 六、视觉系统

### 6.1 字体

| 角色 | 字体 |
|---|---|
| 正文/UI | `Noto Sans SC`（现有） |
| **数字/金额/指标值** | **新增 `--font-mono`**（JetBrains Mono / Geist Mono），一律 `tabular-nums` 等宽——金融数据质感的硬前提，当前项目缺失 |

### 6.2 色彩

- **UI 单 accent**：降饱和深青（如 `oklch(0.55 0.09 195)`），用于焦点环/链接/选中态——弃用 default AI 亮蓝 ring（oklch 0.708 0.165 254.624）。
- **智能体身份色**（3 个，仅用于切换器图标/描边/当前高亮，不侵入工作区）：政策问答=墨绿、结算解释=深青、运营问数=琥珀（均降饱和 <80%）。
- 金额分段：accent 深浅阶，禁彩虹渐变。
- 中性底：现有 oklch 白底 + slate 系（统一 slate，不混 zinc）。

### 6.3 间距与表面

- 对话画布 `max-w-[72ch]` 居中；消息间 24~32px；富块内 20~24px。
- 不套娃卡片：气泡/富块 = 1px border + 白底；分组靠留白与 `divide-y`。
- 来源卡片/费用构成块可浅底色区分（`bg-slate-50`）；圆角 `rounded-2xl`。

### 6.4 交互状态

| 状态 | 设计 |
|---|---|
| 流式 | 打字光标式（闪烁 caret），非转圈 |
| 空状态 | 大留白 + 一句话引导 + 建议（政策建议问题 / 时间快捷选择 / 指标 chip） |
| 错误 | 对话流内联错误富块 |
| 加载 | 富块骨架（分段条 shimmer），非 spinner |
| 按钮 | `:active` `scale-[0.98]` |

### 6.5 动效（纯 CSS）

消息进入 fade+上移 200ms 级联；富块展开 height/opacity 240ms；智能体切换工作区 fade 150ms；全部只动 `transform`/`opacity`。

| 智能体 | 后端需求 | 现状 |
