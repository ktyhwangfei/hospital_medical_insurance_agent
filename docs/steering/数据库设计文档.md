# 数据库设计文档

**版本**: 3.0 | **日期**: 2026-05-13 | **状态**: 正式版（架构修正）

## 1. 概述

本文档对照《总体技术架构-逻辑图》中 DaaS 数据与知识底座的定义，对当前已实现的所有数据库表进行校验，并列出规划中尚未实现的表。

### 架构对照

架构文档定义 DaaS 层结构化存储应包含：会话表、任务表、配置表、知识表、风控事件表、协同任务表。当前已实现 18 张表（v3.0 移除 tools 表、修正 2.4 节计数后），覆盖全部需求。

## 3. 存储分层架构

### 3.1 PostgreSQL — 结构化持久存储（18 张表）
> v3.0 移除 `tools` 表（统一通过 MCP 接入），修正 2.4 节计数后仍为 18 张（原 v2.0 中 2.4 节标题写 7 张，实际列出 8 张）。
承载所有需要 ACID 保证的结构化数据：患者、交易、工作流、执行单元、审计、配置、知识。

### 3.2 Milvus — 向量存储
| 数据类型 | 来源表 | 说明 |
|---------|--------|------|
| 知识切片向量 | `knowledge_chunks.text` → 向量化 → Milvus | RAG 检索的语义匹配 |
| 错误码解释向量 | `error_code_knowledge.recommendation` → Milvus (可选) | 错误码语义搜索 |

**不属于 Milvus 的数据**：所有结构化配置/关系数据（skills/rules/workflows/tasks/sessions/audit_logs/mcp）均存 PostgreSQL，不存 Milvus。

### 3.3 Redis — 缓存与热数据
| 数据类型 | Redis 用途 | 来源表 |
|---------|-----------|--------|
| 会话热状态 | 频繁访问的 session 上下文 | `sessions` |
| 高频配置 | 启动加载 skills/rules/mcp_capabilities，定期刷新 | `skills`, `risk_control_rules`, `mcp_capabilities` |
| 限流计数 | rate_limiter 请求频率控制 | — |
| 幂等性锁 | 防止重复请求 | — |

**不属于 Redis 的数据**：持久化业务数据（workflows/tasks/audit_logs）直接读写 PostgreSQL，不缓存 Redis。

## 6. 设计原则

1. **自动建表**: 所有表通过 `CREATE TABLE IF NOT EXISTS` 在首次连接时自动创建
2. **JSONB 字段**: Skill/MCP 等配置使用 JSONB 存储，支持灵活 Schema
3. **VARCHAR 主键**: 业务主键使用语义化字符串，不使用自增 ID
4. **时间戳**: 核心运行表用 TIMESTAMPTZ，配置表用 TIMESTAMP
5. **索引**: 仅对高频查询字段（owner、server_id、patient_id、workflow_id）建索引
6. **审计与执行分离**: `audit_logs`（网关层请求/响应留痕）与 `tasks`（编排层执行记录）职责清晰分离，不重叠
7. **工具统一 MCP**: 所有工具（含内置工具）通过 MCP 协议接入，不再维护独立的 tools 表
8. **tasks 记录执行细节**: 每个 workflow 步骤的 MCP 调用输入输出、LLM Prompt 与生成内容、执行耗时等均记录在 tasks 表
