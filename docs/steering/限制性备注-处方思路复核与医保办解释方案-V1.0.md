# 以证据解决本次用药与费用争议：方向设计

V2.0，2026-11-06，Issue #85。替代上一版“固定六问复核处方”的主方向。状态：方向与验证方案已修订，尚未实施新模型流程或完成独立业务验证。以下“专家会做”是依据原始研究和本项目失败机制提出的设计建议，未宣称已开展专家访谈。

## 1. 顶尖专家会补做什么

| 用户没有要求的工作 | 要检验的关键假设 | 对设计的改变 |
|---|---|---|
| 在现场观察真实咨询、医保办审核和原系统能力 | 用户究竟需要解释付款、判断支付资格，还是审查临床处方？现有系统是否已足够？ | 工作单元是一个实际争议及其处理，不强制每条药费都审一遍 |
| 分别建立临床用药、医保限定、实际结算的证据链 | 病种相符能否证明这次为何自付？临床合理能否证明医保应支付？ | 三种结论分别说明，不合并成“药开得对/不对” |
| 主动提出竞争解释并寻找反证 | 模型是否能给任意处方编出看似合理的理由？有没有待遇、结算状态、用途或数据关联等其他解释？ | 检查哪个解释被记录支持，以及什么事实可以推翻它；不为既有结果事后找理由 |
| 重建开药、给药、检查、取消、退费和结算的时间线 | 同单出现、事后补记、检查收费，是否真能代表开药当时的事实和实际用途？ | 先核对象、关联和时点；事后说明与同期原记录区别保存 |
| 计算下一次核查的价值，并允许停止 | 补一条资料会改变哪项判断或处理？是否值得打扰医生、患者或医保办？ | 能读现有记录就不先补表；无关缺口不派单，已有解释足够时不强用bz |
| 比较人工、模型与人机协作的实际结果 | 模型题目高分是否能转化为更正确的处理、更清楚的解释和更低总成本？ | 在真实任务中检验，而非用模型自评、采纳率或规则覆盖数证明成功 |

这项区分有实证依据：2024年一项50名医师、最多6个病例题的随机试验中，医师使用GPT-4未显著提高诊断推理得分，尽管模型单独表现较好。它提示需要检验协作方式，不能据此断言本项目或2026年的模型有效/无效。[原始研究](https://jamanetwork.com/journals/jamanetworkopen/fullarticle/2825395/)

开放能力也有新的实证线索：2026年的AMIE前瞻性研究让患者在真实就诊前与模型对话，并把摘要交给医生；98人完成了两环节，说明这种协作值得探索。但它是有人工安全监督的单中心、单臂可行性研究，没有证明相对原流程的工时或结局改善，也不直接证明医保审核有效。[原始研究](https://www.sciencedirect.com/science/article/pii/S0140673626015357)

## 2. 从哪些最原始素材入手

| 原始素材 | 要证明什么 | 当前材料的边界 |
|---|---|---|
| 原结算单、逐行收费原记录、原医保请求/响应、退费冲正链及原因字典 | 实际按什么金额、待遇和原因结算，是否已退/改 | 有测试库结算/明细及部分原因字典；未取得原医保报文。现有JSON和Excel是选择后的快照，不是独立真值 |
| 原处方/医嘱及版本、剂量/途径/频次、开具/实发/执行/取消记录和关联键 | 实际开什么、用于什么、何时发生，不能只看同单收费 | 有部分处方关联与收费，关键目的和执行关联缺失；不把空字段自动写成临床未发生 |
| 同期原始病程、护理、检验、必要的既往记录及修订时间 | 支持/反对某个解释的当时事实是什么 | 目前仅部分诊断摘录且有占位；完整病历未取得。按问题取必要材料，不先搬全量病历 |
| 当时正式目录、凡例、执行通知、补充解释、适用药品说明书/院内规范原件 | 要求来自哪里、适用何时何人，临床依据与支付依据是否一致 | 官方材料只核过部分条目；院内有效至2050不代替政策有效期，bz也不代替药品说明书 |
| 医保办已办结案卷、原审方意见、医生当时解释及整改凭证 | 哪种疑点真实成立、怎样补证和关闭、原流程是否已处理 | 尚未取得完整真实闭环；原告警、已支付、事后补写理由都不能单独当正确标签 |
| 患者最初问句/原工单或授权录音、实际答复和追问、人工操作日志 | 真实困惑、错误行动、查阅/补证/复核工时 | 当前主要是设计讨论，未取得代表性真实用户任务及全程成本记录 |

先围绕一个真实争议拼齐必要原件，保留来源、版本、原关联和时间。其他结算单、额外病史或机构资料按明确问题及授权补取，不能因模型好奇自动扩大范围。

## 3. 具体方法和工具

| 方法 | 可用工具/材料 | 本项目怎样用 |
|---|---|---|
| 任务观察与关键决策复盘 | 真实咨询、屏幕操作记录、半结构访谈、已办结案卷 | 记录“做什么决定、查哪份材料、哪一步无效”，不把专家口述步骤直接固化成程序 |
| 数据血缘与事件时间线 | 经现有adapters执行参数化只读SQL，关联键/版本检查，Decimal复算 | 先区分未取到、未记载、明确反证；核重复关联及退款，费用继续用原算法 |
| 原件阅读与按需检索 | 短原文直接给上下文；长PDF/文本按需OCR、关键词/编码/时间过滤与混合检索 | 先取可定位的相关原件，不预设必须建向量库；检索结果保留页段、时间及上下文 |
| 竞争解释与按价值补查 | 现有ModelGateway；受控只读取证工具；必要的相似审核案例 | 模型可选择查结算依据、对照用途、寻找反证或停止，不要求每药维护条件树，也不把相似案结论当本案事实 |
| 独立盲审与配对比较 | 医保人员及相应医生/药师、简洁标注表、固定输入和版本 | 先独立判断再看模型答案；相同资料权限下比较人工与人机，保留分歧及未知 |
| 变形/反事实测试及真实任务回放 | pytest、来源快照、脱敏Excel、已有轨迹日志 | 改“无法口服”为“可以口服”、改为既往史或其他处方时应识别变化；调换顺序或添加无关内容不应改变结论 |

技术检查只能确认金额没改、引用存在、范围没越界，不能证明引用足以支持判断。Almanac的原始研究把引用准确性纳入事实性评价；其开放问答实验也不等于真实医保流程验证。[原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC10857783/)

## 4. 除你我之外，谁和什么能证明正确

| 要证明的事 | 独立证据/验证者 | 不能替代它的东西 |
|---|---|---|
| 本单实际怎样结算 | 原始交易响应、收费/退费链及另一条可复算核对路径 | 模型根据药理、bz或观察比例推算出来的理由 |
| 所用要求及病例事实正确 | 当时适用的权威原文、同期原记录及其关联/版本 | 引用数量、院内占位有效期、模型记忆或事后合理化 |
| 建议处理有依据 | 未参与提示词设计的医保人员；涉及临床时由医生/药师按原件独立复核，分歧另行裁决或保留未知 | 另一个模型赞同、专家看过模型后表示同意、系统未发现冲突 |
| 系统判断不是碰巧 | 按患者/就诊隔离的留出病例、专家确认可成立的配对反例、跨药品/条款类型及版本测试、完整失败记录 | 同处方多行拆到训练与测试；只在调试样例上通过；合成案例伪装真实发现 |
| 对使用者有实际价值 | 患者能正确复述并采取适当下一步；医保办能有依据关闭；端到端总工时与成本 | 文案更长、满意度、采纳率、疑点数或“待补证”数量增加 |

试验前由业务负责人和独立复核者确定可接受错误、最小有意义改善及样本/精度要求。小样本报告逐例与分母；未见错误不等于风险为零。DECIDE-AI强调早期真实场景、人机交互和流程影响的评价；它是评估方法依据，不证明本产品已有效。[原始指南](https://www.nature.com/articles/s41591-022-01772-9)

## 5. 修改后的方向：围绕一个可行动问题进行证据调查

**目标是帮助患者理解本次费用，并让医保办作出有依据、负担可接受的处理。** 医生开药思路是调查时的一种视角，不再是产品必须照抄的固定六步。模型能力用于理解分散原件、比较解释、识别冲突、选择有价值的下一次核查和组织沟通。

一个问题可涉及多个费用行；同一原件和同一根因合并处理。结算解释入口先服务用户所问问题，医保办审核可发现相关疑点，但不把整单每项药费都生成待办。以下三类判断分别标明证据及覆盖范围：

| 判断 | 需要回答 | 处理边界 |
|---|---|---|
| 临床用药 | 记录支持什么用途，有无相应临床疑点 | 有必要且有相应资料时调查；明确目的、推测目的和未知分开，不能替医生编造开药理由 |
| 医保支付条件 | 当时条款与本次事实在哪些方面相符或相冲突 | 支持一个分支可说明该分支；未覆盖的必要条件继续保留，临床合理不自动推出可以支付 |
| 实际结算原因 | 本次费用实际采用了什么分支/原因 | 用原结算证据和已验证费用分解；支付条件不符也不能单独证明这次正因它全自费 |

限定支付与临床用药分别说明的业务依据见[国家医保局说明](https://www.nhsa.gov.cn/art/2021/8/9/art_110_7026.html)。实际结算因果仍须查本次交易证据。

### 开放调查，固定边界

系统提供选中结算单的已知事实、缺失状态和可访问材料目录。模型按问题自行选择直接解释、读取相关原件、核对版本/时间线、比较候选解释、提出具体疑点或停止。**固定的是来源、权限、金额精度和可复核性，调查顺序不按药写死。**

补查前说明它会影响哪一项结论，以及拿不到时该如何限定答复。可取得的关键证据先由系统读取；只有会影响处理且无法直接取得的缺口，才提出必要补证请求。低价值缺口可以保留未知，不转整改；现有费用解释已足够时，允许不给新增医学判断。

输出围绕当前问题提供：能确定的解释、支持它的原件位置、尚未解决或与之相反的证据、建议动作及责任方。可以只解释已支持的部分；整体未知不应掩盖局部信息，也不应被局部支持掩盖。引用对齐不等于语义成立，语义须经独立验证及相应业务复核。

医保办维护原文/必要的自然语言口径和审核结论，信息人员维护数据连接。审核案例只作可追溯参考，不自动变成规则；不逐药配置ICD白名单，也不要求医生逐单补写开药理由。模型、提示词、检索及案例更新仍需回归，不把维护成本转移后称作“零维护”。

复用四链路取数、费用算法、字段状态、ModelGateway和既有任务留痕。工具只读、按授权范围访问；临床疑点由医保办协调相应人员确认，实际整改在原业务系统执行。现有规则引擎及Excel保留研究证据，不作为放行前提。

可重新设计的是信息探索和问题分解方式。金额计算、来源关联和执行权限仍保留确定性约束；不因“大模型时代”取消这些已经适用的能力，也不预先认定需要多轮或多模型。

## 6. 已有样例如何检验这个方向

| 当前资料 | 最有价值的调查/解释 | 不值得直接推进的动作 |
|---|---|---|
| 艾普拉唑同处方诊断“消化性溃疡伴出血”，52.60元、医保外5.26元 | 可说明这项病种文字对应关系；若问题是“为什么付5.26”，优先核原费用分支/原因及有效政策 | 继续扩写药理，或者把病种相符当成5.26元的实际原因 |
| 卡络磺钠有出血诊断，缺本次不能口服该药的理由 | 先查本次已有记录/取数缺口；只有该信息会改变本次处理时才定向核实 | 因缺字段就要求医生补一份证明，或先把它标为用药不当 |
| 西甲硅油同单有检查收费，缺医嘱/执行关联 | 核实际用途及开药、检查/取消时点，保留检查前用药与事后执行的区别 | 把有收费当已执行，或把未执行/取消检查一律当用药用途不符 |
| 同一回放单明细医保外6.7880，表头3.34 | 先核源字段性质及原交易依据，保留原值与差异 | 让模型为了“算平”而更改费用、补造自费类型或找临床理由 |

## 7. 先做哪一个最小验证

先选一个真实争议，取得能支持该问题的原件、一个独立复核结论及原流程耗时。模型在影子模式生成建议，医保办核对后用于沟通/处理；保存模型原文、出口实际采用正文、人工修改及采纳/拒绝原因。已有金额作用域/算式排版造成的出口误拒须单独识别处理，其修复收益不归给新模型流程，不能把未交付的生成当患者收益。

先比较“同资料人工处理”和“同资料＋模型证据摘要”。证据相同、原人工工具与权限保留，分配时避免同一人重复处理同一病例产生记忆收益，不能把新接数据的收益归给模型。只在发现单次上下文确实受限时，再比较一次性阅读与按需工具取证；不预设Agent、长推理、多模型或更大上下文必然更好，选择同等质量下最简单、成本最低的方法。

放行观察同时看：错误支持、错误升级、关键无来源断言、拒答/未知覆盖、患者理解与正确行动、有效关闭、查阅/补证/二审及维护的总工时；关键案例重复运行，报告结论波动。明确冲突要经人工确认再整改，不把补证、取数失败和政策疑义混成风险单。

若摘要没有改善处理，缩回原文检索；若按需调查没有额外收益，保留单次阅读；若补证和误报抵消收益，收缩自动化范围。初期的未知与失败保留为选择依据，不以多写规则、多建模块或多派任务补偿。

本次完成方向及证明方法修订，未修改运行代码、未新查实库或调用模型，尚不能宣称新方向已获临床或实际收益验证。
