## 3. 开发前锁定的最小契约

### 3.1 字段事实、匹配动作与核验结论分开

保留已有类型化业务值，增加实际被使用字段的状态元数据；不把所有标量都改为复杂包装对象。

| 层次 | 约定 | 关键约束 |
|---|---|---|
| 字段观察 | 字段键、取数/质量状态、来源关联、时点、缺失原因 | 状态沿用设计§2.1；空/占位/失败不得折叠成“未匹配”，0和false不是缺值 |
| 规则定位 | `matched / not_found / not_evaluated / ambiguous`及原因 | `not_found`只在定位依据有效且实际查找后产生；有bz却无规则不能变成无限制 |
| 条件匹配 | `matched / not_matched / not_evaluated`及已使用事实 | 指执行动作，不等于条件真实性；其他诊断未匹配不自动构成反证 |
| 条件结论 | 复用`supported / contradicted / insufficient_evidence / unverifiable` | 支持/冲突有对应证据，未知保留原因；按原OR/AND关系聚合 |

字段依赖按证据路径判定：合法编码已足以证明某个经审核条件时，不因另一可选名称/病历路径缺失而阻断。反之，有某个字段或关键词不意味着整个复合条件已满足。

### 3.2 对现有返回结构的最小增加

公开核验结果放在现有`fee_items[].payment_condition_context.verification`可选字段；工作台和SSE复用同一逐行投影，模型只取得选中目标的摘要。**本阶段不新增另一份费用结果。**

`verification`摘要包含：规则定位状态及原因、所用规则标识/版本、可为空的根核验结论、逐条件原文/结论/证据说明/缺口，以及现有公开契约允许的citations或uncertainties。未执行时根结论为空，并写明规则定位或字段缺口；已执行但资料不足时用既有未知结论。内部SQL、物理表列、原始关联键、未脱敏病历不进入公开摘要或模型消息。

`clinical_conditions_verified`不再作为新核验结果的总开关；迁移期公开DTO保留原`False`字段并标为旧字段，新消费端以`verification`的逐条件结果和范围为准。模型输入已有`verification`时省略这个旧布尔字段，并同步更新提示约束，避免两个判断口径混用。不能把“完成了一次核验”或“一个分支支持”翻成全临床条件均已验证。

解释分三类：有支持时说明条件及事实依据；有直接冲突时说明具体不一致且不替代正式结算判断；未知时说明缺哪项。条件结果不自行生成自付类别和比例原因，也不声称已经发起人工办理。

## 4. 按两个可独立验收的迭代开发

### 迭代A：现有核心与探针的质量修正

目标：单张样例的原型输出可信，且所有费用行都有处理状态，包括未命中、不可核验和明确不在本次处理范围的行。

1. **先落回归预期。** 将已有反例转为独立测试，先复现错误再修改；不得继续把“售价超过支付标准必反证”作为通用正确预期。
2. **补输入与定位状态。** 在现有模型和执行入口补§3.1；校验来源关联及当日版本。修探针按项目编码覆盖多版本、目录多行静默取最后一行及无规则直接continue的处理；输出歧义和未执行原因，原费用按来源行键保留，诊断多行不复制费用。
3. **修两类核验器。** 删除把“溃疡”直接当“溃疡出血”的弱支持；无法正确判断否定、时点及主体的名称/病历文本只作线索。价格条件明确具体适用口径，统一规格量纲及包装单位；缺少支付基数或换算依据时保留未知，不能改写费用算法。
4. **收紧配置及输出边界。** 空树/空组及非法参数拒收，配置态与领域态转换有测试；未审核规则的探针回放明确标注调试结果，不生成正式“已符合”的患者结论。修模板的金额分类和办理承诺。
5. **留下最小可复核输入。** 探针保存实际使用的脱敏事实、状态、规则/映射及版本与输出；不是只存哈希。已有可复核JSON足以验收本轮，不新增审计存储系统。

验收产物：正确预期的单元测试、样例回放JSON，以及每个未知能指向字段/配置/政策绑定缺口的解释。仅通过技术回放的人工规则不因此自动获得政策或临床审核状态。

### 迭代B：接入现有四链路费用解释

目标：在真实入口上，患者可以看到有质量依据的补充解释，原金额计算和原费用解释仍正常工作。

1. 复用已有适配层的取数与状态；在运行时装配处转换为领域输入。普通门诊保留结算＋处方关联，门特保留原`jylsh/cfh`链；同结算线索不能冒充同处方或用药执行证据。症状源缺失继续明确标记。
2. 在逐行事实装配后调用核验，把安全摘要挂到`verification`；费用数值仍来自原分解结果。条件查询或核验不可用时降级为明确未知，不能让主费用解释整体失败，也不能吞掉故障原因。
3. 更新后端投影、模型目标裁剪和前端DTO/SSE解析。按问题需要展示相关条件，模型不得把结构化未知改成支持或不符；沿用已有模型网关和出口校验。
4. 选取四链路真实脱敏样例，对比接入前后金额/分支/核对状态，并查看实际模型输入、原始生成及最终采用结果。已有模型金额作用域/算式排版拒绝问题单独识别；若阻断本轮结果，只修必要范围，不能把被出口拒绝的正文算作患者收益。

验收产物：四链路真实入口的返回样例、模型采用/未采用记录，及费用不变的回归结果。正式解释使用的规则/映射须已完成相应质量审核；尚未审核的条目明确保留不可确认范围，不妨碍其他合格条目接入。

## 5. 必测样例与正确预期

| 样例 | 必须观察到的结果 |
|---|---|
| 艾普拉唑真实样例中的关联出血诊断 | 可定位原字段；支持范围受实际规则审核、版本及关联质量约束，不从一张正例宣布全规则正确 |
| 只有溃疡，未取得出血事实；明确否定吞咽困难 | 不得因弱关键词得到条件支持 |
| 卡络磺钠有诊断但没有口服能力事实 | 明确缺口，不判不符，不编造可口服或不能口服 |
| 未取到字段、查询失败、占位；字段有效但未匹配 | 前者未执行，后者确实执行，两类状态与解释可区分 |
| 有bz无适用规则；版本/目录多义；空条件树 | 保留未执行/歧义，空树拒收，均不能误作通过或无限制 |
| 允许超标准自付的合成政策，100/80/10%，72/28划分 | 不仅因售价100>80判冲突；另一划分不能只凭同售价得到同一支付基数结论 |
| 10g与10mg；0.01g与10mg；多级包装缺换算 | 量纲不混淆，等价含量正确归一，包装不明则未知 |
| OR有效支持＋可选分支缺资料；AND支持＋未知 | 前者保留有效支持及未核验范围，后者整体未知 |
| 条件支持但自费类型/原因未知；未创建复核任务 | 不填造乙类先行自付或因果原因，不称医保办正在办理 |
| 诊断一对多、退费/非正费用、单行与整单范围不同 | 不重复费用，排除有原因，不错用整单金额解释本行 |

## 6. 验证顺序与完成定义

代码实现先完成审查—查漏—修复—再审查，再按仓库矩阵执行Unit→API→Flow。迭代A优先领域/探针单元，API/Flow跑已有入口回归，不为尚未存在的核验API造测试入口；迭代B增加实际费用入口及SSE字段的API/Flow覆盖，并执行Portal解析测试和类型检查。

本轮完成需同时满足：关键反例按正确预期通过；真实链路能够取得/解释状态；费用计算不变；模型实际采用的解释没有越过结构化事实。对“患者更理解、医保办少做无效工作”的业务收益另留真实任务观察，不能用技术测试通过代替，也不把正式收益试验作为开始开发的前置条件。

PG规则仓储、批量治理API、全量目录解析、更多条件类型、治理页面和跨结算单历史查询沿总体设计后续推进，本轮无需提前实现。
