# 模型治理 — 新模型接入与模型列表下拉选择 设计 V1.0

> 状态：已实施（待页面验收）
> 需求来源：用户 2026-08-19（issue #19 验证会话后续）
> 关联：§1 模型服务与管理 4.5（真实资产版本与模型接入，已 verified）

## 1. 背景与目标

用户通过「后台管理 → 模型 → 新建模型」接入 **opencode Go 套餐**的 **DeepSeek v4 flash** 模型，并把路由指向它。opencode 端点是标准 OpenAI-compatible API，本质与现有 deepseek-chat 同构——**不需要为特定厂商写任何代码**，缺的只是「模型名从哪来」：

**当前痛点**：model_profile 表单的「模型名」是纯手填输入框。换一个新端点（如 opencode）时，用户不知道该填 `deepseek-v4-flash` 还是 `deepseek-v4/flash` 还是别的——写错只能靠连接测试失败再猜。

**目标**：
1. 在模型表单中配置 `API 访问地址` + `API Key` 后，可**一键拉取该端点的模型列表**，模型名改为**下拉选择**（保留手动输入兜底）。
2. 新模型 profile 走既有链路（保存 → 连接测试 → 审核 → 发布）后，自动出现在**路由规则**的主/备模型下拉中（此能力已存在，验收即可）。

**非目标**：
- 不支持非 OpenAI-compatible 提供商
- 不做流式/异步探测，不做模型能力元数据（价格、上下文长度）展示
- 不改凭据库结构（Fernet 加密、endpoint fingerprint 绑定均维持现状）

## 2. 现状确认（代码级）

| 环节 | 现状 | 缺口 |
|------|------|------|
| 新建模型 profile | `model-governance` 工作台「新建模型」→ 表单（Provider 固定 OpenAI-compatible、base_url、模型名手填、Credential ID、API Key） | 模型名手填 |
| 连接测试 | `POST /model-governance/drafts/{id}/test-connection`，发最小 ping 请求，是发布硬门禁 | 无 |
| 列出端点模型 | `OpenAICompatibleProvider` 只有 `invoke`/`invoke_stream` | **无 `GET /v1/models` 能力** |
| 路由到新模型 | route_rule 表单主/备模型下拉 = 已发布 model_profile 列表 | 无 |
| 运行时生效 | 发布后 `resolve_governed_route(scene)` 驱动 dev/test 真实路由 | 无 |

## 3. 方案设计

### 3.1 后端：模型列表探测

**Provider 层**（`src/model_service/providers/openai_compatible.py`）：

```python
def list_models(self) -> list[str]:
    """GET {base_url}/models，返回 data[].id 列表（按字母序）。

    401/403 → ModelAuthError；超时 → ModelTimeoutError；
    404/405 → ModelServerError（端点不支持列表，由上层转为可读提示）。
    """
```

**API 层**（`model_governance_routes.py` 新增，无状态、不依赖已存草稿）：

```
POST /model-governance/models/probe-list     权限：model:governance:write
body:  { "base_url": "https://opencode.ai/zen/go/v1",
         "api_key": "sk-xxx",            # 取自表单当前输入；未填则匿名探测（OpenCode Go 实测匿名可列模型）
         "timeout_seconds": 10 }         # 默认 10，上限 30
resp:  { "models": ["deepseek-v4-flash", "claude-...", ...],
         "safe_message": "成功获取 23 个模型",
         "audit_event": {...} }
失败:  401 → {"safe_message": "认证失败：检查 API Key"}
       404/405 → {"safe_message": "该端点不支持模型列表接口，请手动输入模型名"}
       超时 → {"safe_message": "连接超时：检查 API 访问地址"}
```

**安全边界**（延续 4.5 验证标准）：
- `api_key` 仅在请求体**瞬时**使用：不写库、不进任何日志（现有 observability 中间件只记指标/链路、不记 body，实测确认）、不回显（响应只有模型 id 列表与 safe_message）
- 审计事件只记 `action=model_list_probe` + base_url 域名 + 结果状态，不含 key

### 3.2 前端：模型表单联动（`model-governance-workspace.tsx`）

model_profile 表单改为：

```
API 访问地址 [https://api.opencode.ai/v1 ]  Credential ID [.........]  API Key [**** ]
                                          [ 获取模型列表 ]  ← 按钮在三者就绪时可用
模型名  [ ▼ deepseek-v4-flash        ] [手动输入]   ← 拉取成功=下拉(可搜索)；
                                                      失败/未拉取=手动输入框 + 提示
```

- 按钮点击 → `probeModelList(baseUrl, apiKey)` → 成功填充下拉（模型多时前端做子串过滤），**默认选中原值或列表第一个**
- 失败 → 表单内联提示 safe_message，模型名回退手动输入（用户仍可手填继续）
- base_url / api_key 变更后下拉置灰并提示「配置已变更，请重新获取」，防选到旧端点的模型名
- **API Key 全程在页面配置**（既有 4.5 机制零改动）：表单填 key → 保存草稿时经 `GovernanceCredentialVault` Fernet 加密写入治理凭据库（`credential_ref` 绑定 endpoint fingerprint，base_url 变更须重新提交 key）→ 连接测试/发布运行时从凭据库解密使用；页面/响应/日志永不回显明文
- 本地前置：工作区 `.env` 需一次性生成 `MODEL_GOVERNANCE_MASTER_KEY`（Fernet 主密钥，开发时随交付生成；这是加密钥的钥，不是 API key）

### 3.3 路由配置（零开发，验收项）

新模型发布后：route_rule「新建路由」→ 主模型下拉出现 `model.opencode.deepseek_v4_flash`（资产 ID）→ 选择并发布 → 该 scene 的 dev/test 请求经治理路由实际打到新端点。

### 3.4 opencode Go 套餐接入路径（验收场景，非代码）

opencode 是 OpenAI-compatible 网关，接入即通用流程：

1. 新建模型：base_url 填 `https://opencode.ai/zen/go/v1`（Go 套餐已核实，见 §6），API Key 填套餐 key
2. 获取模型列表 → 下拉选 DeepSeek v4 flash 对应的模型 id
3. 保存 → 连接测试通过 → 提审 → 审批 → 发布
4. 新建/修改路由规则 → 主模型选它 → 发布
5. 在政策提取/问答场景验证真实调用

## 4. 边界与异常

| 情形 | 行为 |
|------|------|
| `/models` 返回 404/405 | 明确提示端点不支持列表，回退手动输入（不阻塞建模型） |
| key 无效（401/403） | 提示认证失败，与连接测试同口径 |
| 响应非标准 JSON（无 `data[].id`） | 提示"端点返回格式无法识别"，回退手动输入 |
| 模型列表超长（>100） | 下拉内子串过滤，不截断数据 |
| base_url 带尾斜杠 | 复用 provider 既有规范化（rstrip `/`） |
| 探测超时 | 10s 默认上限 30s，报"连接超时" |

## 6. OpenCode **Go** 套餐事实（联网核实，2026-08-19）

**来源**：https://opencode.ai/docs/go/ + 对真实 API 的匿名实测。

| 事实 | 值 |
|------|---|
| 套餐 | OpenCode **Go**（$5 首月 / 之后 $10 月订阅，面向开源编码模型的低成本稳定通道；与按量计费的 Zen 套餐**不同**） |
| **API base_url** | **`https://opencode.ai/zen/go/v1`** |
| **DeepSeek V4 Flash 模型 ID** | **`deepseek-v4-flash`**（文档确认在 Go 模型清单内；同端点另有 `deepseek-v4-pro`） |
| 调用接口 | `/chat/completions`（标准 OpenAI-compatible，文档 Endpoints 表确认）——**与现有 provider 完全兼容，零专用代码** |
| 限额（按美元额度） | 5 小时 $12 / 周 $30 / 月 $60 |
| 模型清单 | Grok 4.5、GLM-5.3/5.2/5.1、GPT 5.6 Luna、Kimi K3/K2.7 Code/K2.6、MiMo-V2.5(+Pro)、MiniMax M3/M2.7、Muse Spark 1.2、Qwen3.8/3.7/3.6、DeepSeek V4 Pro/**Flash**、Hy3 |
| 模型列表端点 | `GET /zen/go/v1/models`，标准 `data[].id`，**匿名即可访问**（实测 200，28 个模型；key 仅 chat 调用时需要） |

**实测验证**：`curl https://opencode.ai/zen/go/v1/models`（无 key）→ 200，28 个 id，含 `deepseek-v4-flash` 与 `deepseek-v4-pro`。probe-list 设计直接可行，选模型不需要先有 key。

**重要边界（写进表单提示）**：Go 端点上 GPT 5.6 Luna 走 `/responses`、Claude 系走 `/messages`——非 OpenAI-compatible；本平台治理仅支持 `/chat/completions` 路线模型（DeepSeek / GLM / Kimi / MiniMax / Qwen / MiMo / Grok 等，占 Go 清单绝大多数）。选错路线会在连接测试时明确报错，属预期拦截。

**API Key 配置方式（无需任何 .env）**：opencode.ai 登录 → 订阅 Go → 复制 API key → **在模型治理页面表单中粘贴**，保存时 Fernet 加密入治理凭据库（4.5 已验证机制：endpoint fingerprint 绑定、响应/日志/页面不回显明文），git 与 `.env` 均不落 API key。本地仅需 `MODEL_GOVERNANCE_MASTER_KEY` 加密主密钥（随开发交付生成）。
