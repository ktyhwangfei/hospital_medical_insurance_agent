# 限制性备注：支付条件解释与医保办证据核验设计

V5.0，2026-11-06，Issue #85。当前方向为[以证据解决本次用药与费用争议（V2.0）](限制性备注-处方思路复核与医保办解释方案-V1.0.md)：以真实问题及处理为工作单元，临床用药、支付条件和实际结算分别给依据。模型按案情选择阅读、比较、补查或停止，不再固定六问或逐药维护规则。专家补充工作、原始材料、具体方法工具和独立证明已落实到该方向设计；以下证据基础保留，历史引擎记录仅作研究对照。新模型流程和独立业务验证尚未实施，范围仍为选中结算单及既有四条费用分解链路。

## 1. 重写前的四个问题

| 问题 | 专家会补做什么 | 本设计如何落实 |
|---|---|---|
| 用户没要求什么 | 查现有系统已做什么；主动查误导、补证负担和失败反例 | 分别验证患者理解、医保办办结；规则数量不作收益 |
| 从什么原料开始 | 当时有效的完整政策、原单、临床原记录、真实咨询、已复核案卷 | Excel和告警只作线索，标记已取得与缺失材料 |
| 用什么方法工具 | 只读SQL、Decimal复算、关联基数检查、逐条件审核、盲审、受控任务比较 | 锁定输入和评价方案，保留失败与未知结果 |
| 谁能独立证明 | 未参与设计的医保政策人员、临床药师、实际使用者及可复算记录 | 业务依据、判断正确、实际有用分别举证，模型不能自证 |

## 2. 两个价值假设与否证条件

**患者假设**：面对真实的支付条件疑问，bz能提高用户对条件、本单已知事实及适当下一步的理解。不要求bz参与金额计算；只问金额且已有比例解释足够时，不强制展示临床条款。

**医保办假设**：bz能帮助准确提出核查问题、取得必要证据并有依据关闭；结论质量不下降时减少总工作量，或发现现有流程遗漏且经复核确认的事项。多生成“待核”不算价值。

**如何推翻**：相对实际现有流程，理解、正确行动、有效办结均无改善；既有系统已提供同样帮助；误导、无效补证增加；取证与维护成本超过节省。出现这些结果即收缩或停止该场景，不能以“备注多”继续论证建设。

当前只证明原文存在独特信息；未找到四链路内“限制明确不符导致全自费”的闭环正例，也没有经独立临床复核确认的违规样本。未找到不等于不存在，测试库不能估计生产发生率。

## 5. 最小工作单元：条件证据卡

每卡绑定“原费用行＋实际规格＋费用日期＋地区/险种/支付体系＋官方政策版本”，保存原文片段、原子条件、关系、事实来源、结论、缺口和下一步。当日备注空不能借旧版本补齐，院内jzrq=2050不证明政策有效至2050。

先判条件适用/不适用/适用性未知，再判有支持/明确冲突/未知。明确冲突必须有针对该条件、时点和对象的直接反证，不能从未检出推导。首次处方有资格要求时，“首次与否未知”不能跳过该要求。未知区分临床事实缺失、技术映射缺失、政策歧义及未解析；映射不能补出事实。

| 条件 | 充分证据应指向什么 | 禁止的替代判断 |
|---|---|---|
| 疾病/病因 | 同期关联本次用药的临床记录，必要时病因关系 | 其他诊断或关键词未命中不证明不符；CKD与贫血两个编码不自动证明因果 |
| 用途/联合使用 | 对应医嘱、执行及药物关联 | 同单检查或另一药收费只是线索，不能判用途满足 |
| 机构/医师/首次/既往治疗 | 正确角色、时点、资格和病史事实 | 科室方向差异不是不合规结论；缺首次、BMI、疗效不能默认符合 |
| 支付标准/比例 | 按适用凡例核规格单位、允许支付基数及实际费用划分 | 支付标准不能统一当售价上限；真正收费上限按对应政策另判 |

**按原文整体判断，不必维护可执行条件树**：替代分支有充分支持可以说明对应分支，必需条件缺失则不能整项通过；只有实际直接反证才形成冲突。模型逐项对照原文，保留条件间关系和未覆盖范围，不把一次解析结果转成医保办要维护的规则资产。

**结算原因与条件判断并列**：v_NoRightReason等按源字段及源字典解释；条件有支持不保证最终比例一致，条件冲突也不证明本次结算采用了这个原因。支付限定不等于临床用药合理性结论。[依据：医保函〔2021〕77号](https://www.nhsa.gov.cn/art/2021/8/9/art_110_7026.html)。

金额分开保存项目总额、医保内/外、先行负担及整单基金支付，跨条件不重复累加。12行中2行对应整单基金支付0，已反证“FeeIn即基金损失”。逐行基金影响不能可靠归属时写未知，不按比例摊出损失或追款额。

## 7. 怎样证明价值来自bz

先观察真实咨询与已办结案卷，记录原流程查什么、用什么工具、如何取证与关闭，不能假设已有系统没有同类能力。

| 比较版本 | 保留/增加内容 | 检验目的 |
|---|---|---|
| C0：实际现有流程 | 保留原系统、人工政策查阅、原审核工具与正常资料权限 | 真实基线，不能剥夺查阅制造收益 |
| C1：C0＋关联bz原文 | 增加正确项目/时点的原文及出处 | 原文就近可得是否已足够 |
| C2：C1＋条件证据卡 | 增加逐条件事实、来源、缺口与下一步 | 结构化处理额外增加什么 |

新增病历/检验事实必须等量提供各组，不能把接通数据的收益归给bz解析。离线去除bz可探测信息依赖，但不能据此声称部署收益。固定输入、政策及模型版本；患者与医保办分别比较，随机分配或按难度配对；同一参与者不重复做同一案例，避免记忆效应。

患者主任务是用自己的话说明条件、能/不能确认的事实和适当下一步，按独立预设答案评分；记录误认为已拒付、用药违规或需自行停药等错误行动，满意度仅辅助。医保办评价与独立复核的一致性、遗漏/误报、必要补证、可用关闭及总人时；总人时包含查阅、取证、往返、二审和分摊规则/映射维护。

按支持、冲突、资料不足、OR分支、正确价格分摊及依赖历史分层，不能只挑好解释的药。真实案卷优先；人为修改的反例只测逻辑，不计真实违规数或准确率。当前测试库可回放，不能替代代表性用户样本。

**试验前锁定验收表**：业务负责人和独立复核者预先确定主任务、严重错误、最小有意义改善幅度、允许误差及样本量/精度依据，后收结果，不事后调门槛。少样本报逐例结果、分母、耗时分布与不确定性，不声称显著提升。此表和独立验证未完成前，仅可做探索评估，不宣称价值已证实。

## 8. 除你我之外的证明链

1. **政策真值**：官方条款及生效背景证明要求是什么，历史费用不用新年度规则倒推。
2. **病例真值**：未参与设计的医保政策人员和临床药师先不看模型答案，分别按原资料逐条件判断；分歧追溯条款并交相应权威确认，未解决保留未知。专家一致、已支付或旧告警不能单独作真值。
3. **计算真值**：另一只读核对路径复算费用键基数、状态、金额与版本命中；Decimal计算，锁定输入/规则/映射/求值器版本及哈希，允许复现。
4. **效果证据**：患者实际任务答案和错误行动、医保办复核案卷与全程工时，证明是否有用；独立评分与未参与调试的留出案例防止只对示例有效。

国家“两库”办法支持知识、规则、多方论证和动态反馈；北京公开规则采用目录备注核查限定支付。这证明业务依据，不代替本产品效果。[国家办法](https://www.nhsa.gov.cn/art/2022/4/7/art_104_8069.html)、[北京公开规则](https://ybj.beijing.gov.cn/tzgg2022/202609/t20260930_4887205.html)。

## 9. 改为维护原文、口径和审核案例

医保办通过已有知识治理核对原文、版本与必要的院内自然语言口径，审核案例并写明依据。信息人员维护数据来源与关联；模型围绕当前争议选择证据、比较解释并决定是否补查或停止，不要求医保办维护概念码、ICD集合或逐药提示词。临床用药、医保支付和实际结算分别说明，按问题及证据安排相应复核。

复用现有适配器、ModelGateway与任务留痕；保留费用精度、来源和快照。原引擎作历史研究对照，不再作为当前主入口或确定性放行前置，详见新方案§2、§7。

## 10. 最小实施与必须通过的反例

**已完成的字段探索阶段**：复用四链路费用分解，将当日唯一目录bz、关联诊断、现有机构等级、规格/单位/用法、科室及医师等级原值交给现有模型。无独立症状字段如实标记；既往疗效、首次、BMI和执行关联未取到时不猜。对用途/联合使用，补充同单收费名称线索，明确不是执行。探索不以建立规则库、人工复核平台或完成正式用户试验为前置条件。

阶段验收是“真实字段取到→公开投影保留→目标裁剪后进入实际模型消息→有/无上下文对比”，并证明原金额、分支和核对状态不变。记录原始生成、是否被出口采用及退回原因，不把模型说得更具体当作正确或有效。详细字段与样例见[患者设计§8](费用解释-项目内涵与药品支付备注应用设计-V1.0.md)。
