# 数据接入规范（一页纸）— Agent 取数契约

> 依据：issue #27《数据供给规范设计：语义层标准 + 分档适配接入》。
> 用途：与医院信息科（首个对象：协和）谈数据供给时的**需求清单与合同口径**。
> 原则：**不建数据平台，建数据供给规范**——语义层是需求侧标准（跨院不变），供给层是每院落地一个适配器（可变）。

## 1. 分档接入形态（按医院现状对号入座）

| 档位 | 医院现状 | 接入方式 | 平台侧落点 |
|---|---|---|---|
| 一档 | 有数据中心/集成平台（CDR） | 只读账号 + 视图直连 | `SqlServerDirectSupplyAdapter`（已实现，协和谈判基线） |
| 二档 | 只有 HIS 等业务系统 | 厂商接口 或 定时同步中间库 | 实现 `DataSupplyConnectionPort`；门诊链路已按此形态产品化（SQL Server → PG 落地库同步） |
| 三档 | 医保局数据 | 代理服务器/专网合规通道 | 方向三立项后再议，本期不涉及 |

**换档承诺**：语义层与 Skill 零改动，只替换 `src/adapters/data_supply/` 下的供给实现。合同 = `DataSupplyConnectionPort.connect(datasource_id)`（只读连接，PEP 249）。

## 4. 供给方承诺（只读 + 可审计）

1. **只读**：供给账号仅 `SELECT` 权限；供给端口合同不提供任何写通道（适配器层硬约束）。
2. **可审计**：连接来源可追溯（数据源注册中心登记 datasource_id + 连接配置）；查询经语义层编译为白名单只读 SELECT（Query Planner 出口校验），无裸拼业务 SQL。
3. **量级**：单条、低频（一次解释一张结算单），可容忍接口延迟；不做批量抽取。
4. **码值**：源码值 + 字典映射关系一并供给（或允许平台侧维护映射表）。

## 5. 平台侧对应承诺

1. 语义层指标/码值/血缘跨院复用不随医院变（需求侧标准）。
2. 医院落地只需：注册数据源（datasource_id + 连接配置）→ 按档位选择/实现供给适配器 → 字段映射对齐 §2 清单。
3. 给不了库就给接口，给不了接口就定时同步中间库——差异全部由适配器层吸收。
