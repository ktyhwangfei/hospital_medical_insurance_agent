## 1. 信息架构

### 1.1 系统概览

原型为**单页应用（SPA）**，所有功能通过 `page.tsx` 的标签页系统切换渲染。**全部数据通过 API 从 PostgreSQL 数据库获取，无 Mock 回退**。

```
医保AI导办与运营协同平台
│
├── Header（全局顶栏）
│   ├── 品牌标识（logo + 标题 + 版本号）
│   ├── API 连接状态指示器
│   └── 角色切换器（收费员/医保办/信息科/病案室/临床医生）
│
├── Sidebar（可折叠侧边导航）
│   ├── 业务应用
│   │   ├── AI导办对话     ← POST /chat + SSE /chat/stream
│   │   │                   ← 数据库: patients, insurance_transactions,
│   │   │                      error_code_knowledge, skills, workflows, audit_logs
│   │   ├── 结算异常导办    ← GET /workflows?scenario=settlement_exception
│   │   │                   ← 数据库: workflows, patients, insurance_transactions
│   │   ├── 出院前联合质控   ← GET /workflows?scenario=pre_discharge_qc
│   │   │                   ← LangGraph 图执行 → POST /tasks/confirm
│   │   └── 运营驾驶舱     ← 聚合查询 workflows + audit_logs（统计接口）
│   │
│   └── 平台管理
│       ├── 技能管理        ← CRUD /skills → skills 表
│       ├── MCP管理         ← CRUD /mcp/servers, /mcp/capabilities
│       │                   ← 数据库: mcp_servers, mcp_capabilities
│       ├── 知识管理        ← CRUD /knowledge/error-codes, /knowledge/rules,
│       │   │                  /knowledge/assets, /knowledge/appeal-templates,
```

### 1.3 数据流架构

```
用户操作 → 业务组件
         → api-client.ts → fetch(API_PREFIX + path)
         → next.config.ts rewrites → http://127.0.0.1:8000/api/v1/...

  ├── 200 OK → 渲染数据（从 PostgreSQL 查询返回）
```

> **2026-05-14 更新**: 基于 `public/chat-v3-prototype.html` 原型验证，Portal 对话界面的视觉方向确定为**暗色系 + 半透明玻璃拟态**风格。以下为新设计 token 体系，后续 Portal 实现以该原型为视觉基准。

| `--bg-chat` | 聊天区底色 | `#0f1520` |
| `--bg-card` | 卡片底色 | `rgba(255,255,255,0.03)` |

**语义色法则**: 推理链每一步使用独立语义色，在 dots、badges、glow 上保持一致。

**核心交互范式**: **"导办即对话"（Guidance as Conversation）** — AI 推理过程**内联嵌入聊天流**，用户可逐步骤观察 AI 的意图识别、适配器调用、知识检索、MCP 工具调用、规则校验全过程。

#### 2.0.1 聊天流 CSS 布局架构（关键约束）

聊天区采用 **Flex Column** 布局，所有消息节点（用户气泡、思维链卡片、导办卡片、AI 回复）均为 `chat-viewport` 的直接子元素，按时间线自然排列：

```
.chat-viewport (flex column, overflow-y: auto, gap: 18px)
  ├── .message.user          ← 用户消息气泡
  ├── .thinking-chain-card   ← AI 思维链卡片（内联）
  ├── .guidance-card         ← 导办结果卡片（内联）
  ├── .message.bot           ← AI 回复气泡
  ├── .message.user          ← 下一轮用户消息
  └── ...
```

**⚠️ 关键 CSS 约束 — `flex-shrink: 0`**：

```css
/* 思维链卡片和导办卡片必须设置 flex-shrink: 0 */
.thinking-chain-card { flex-shrink: 0; /* ... */ }
.guidance-card         { flex-shrink: 0; /* ... */ }
```

**原因**: 这两个卡片均设置了 `overflow: hidden`（用于 `border-radius` 裁剪圆角），根据 CSS Flexbox 规范，`overflow: hidden` 的 flex 子项会将其隐式 `min-height: auto` 解析为 `0`，允许 flex 容器将其压缩至内容高度以下。当聊天内容超出视口时，卡片被压缩而后续消息（无 `overflow: hidden`，`min-height` 保持 `auto`）保持完整高度，导致**消息覆盖在卡片之上**。

**解决方案**: 为所有 `overflow: hidden` 的 flex 子项显式添加 `flex-shrink: 0`，禁止容器压缩，确保卡片始终以完整内容高度参与布局。

**动画注意事项**: 组件的入场动画（`thinking-in`、`guidance-slide-in`、`message-in`）均使用 CSS `transform`，`transform` 不影响文档流布局，不会造成重叠。入场动画的 `animation-fill-mode: both` 确保动画结束后元素保持在最终位置。

#### 2.0.2 背景氛围效果

| 效果 | 实现方式 | 说明 |
|------|---------|------|
| **Scan-line 扫描线** | `.chat-area::after` 伪元素，`position: absolute; inset: 0; z-index: 0` | `repeating-linear-gradient` 绘制间隔 2px 的半透 cyan 横纹，`pointer-events: none` 不阻挡交互 |
| **Particle 浮动粒子** | JS 动态创建 12 颗 `.particle` 元素 | `position: fixed; inset: 0; pointer-events: none; z-index: 0`，2px 光点从底部上浮，随机延迟（8-18s）和速度，`particle-float` 动画 |
| **玻璃拟态** | `backdrop-filter: blur()` + 半透明背景 | 应用于 Header（`blur(18px)`）、Drawer（`blur(20px)`）、Input 容器（`blur(8px)`） |

> **z-index 层级**: 粒子层 `z-index: 0` → scan-line `z-index: 0` → chat-viewport `z-index: 1` → header `z-index: 100` → drawer-overlay `z-index: 200` → drawer `z-index: 210`

#### 2.1.1 Policy QA Chat-first 专项布局

`/policy-qa` 面向 1280–1920px 桌面端，保留 Portal 深色全局导航，但业务内容区使用浅色、居中的单一阅读轴。该页面不继承 §2.0 的思维链常驻展示和暗色卡片密度。

| 约束项 | Policy QA 规范 |
|--------|----------------|
| **内容宽度** | 主阅读轴最大宽度 `840px`，问题、回答、来源入口与输入框沿同一轴排列 |
| **页面结构** | 空闲引导或连续消息列表 + 底部 Composer；无顶部传统查询表单 |
| **分栏** | 无常驻左栏、右栏、会话记忆栏、执行时间线或数据来源栏 |
| **执行反馈** | 流式处理中只显示最新一条可公开状态消息；不显示常驻步骤链、推理链或工具轨迹 |
| **渐进披露** | 先答案，再查证摘要；计算过程、费用明细按需展开，政策来源在临时 Dialog 中查看 |
| **上下文** | 结算单号以 Composer context chip 展示并随请求发送，不占用独立表单区 |
| **连续追问** | 同一会话内 Composer 始终可用；请求进行中禁用重复提交 |

空闲态以 Agent 能力说明和示例问题引导。完成态必须展示单一院端答案；`partial` 明确列出缺失信息，`unavailable` 不输出确定性结论并提供重试或人工咨询建议。

### 2.2 数据展示约束

| 场景 | 规范 |
|------|------|
| **列表加载中** | Skeleton 骨架屏（`shimmer` 动画），非空白页 |
| **列表为空** | 居中提示 + 引导操作按钮（如"创建第一个错误码"） |
| **API 错误** | Alert 组件展示错误信息，含可重试按钮 |
| **服务不可用** | 全页面状态提示"服务暂不可用"，禁用所有表单交互 |
| **表单提交中** | 提交按钮显示 `Loader2` 旋转 + disabled |
| **数据刷新** | 手动刷新按钮（非自动轮询），操作成功后自动刷新列表 |

### 2.3 CRUD 操作约束

| 操作 | 规范 |
|------|------|
| **列表页** | 支持按关键字段搜索 + 排序；分页（每页 20 条） |
| **创建** | Dialog/Sheet 表单，必填字段标注 *；提交前前端校验 |
| **编辑** | 同创建表单，回填已有数据；保存后列表原地刷新 |
| **删除** | 二次确认 Dialog；删除后列表移除该项 |
| **批量操作** | 暂不支持（v1.0） |

### 2.4 表单校验规则

| 字段类型 | 规则 |
|----------|------|
| **必填字段** | 空值不允许提交，红色边框 + 提示文案 |
| **ID 字段** | 字母数字下划线，2-128 字符 |
| **URL/端点** | 合法 URL 格式校验 |
| **JSON 字段** | Textarea 输入，提交时 JSON.parse 校验 |
| **风险等级** | 下拉选择：HIGH / MEDIUM / LOW |
| **布尔值** | Switch/Toggle 组件 |


## 5. 已知陷阱与约束

### 5.1 CSS 布局陷阱

#### 陷阱 1: `overflow: hidden` + flex 列容器 → 子项高度被压缩

**场景**: flex 列容器的直接子项同时设置了 `overflow: hidden`（如用于 `border-radius` 裁剪）。

**原理**: 根据 CSS Flexbox 规范，`overflow: hidden` 的 flex 子项会将其隐式 `min-height: auto` 解析为 `0`，在容器高度受限时被子项被压缩至内容高度以下。

**影响范围**:
| 组件 | 文件 | 修复状态 |
|------|------|---------|
| `.thinking-chain-card` | `public/chat-v3-prototype.html` | ✅ 已修复（`flex-shrink: 0`） |
| `.guidance-card` | `public/chat-v3-prototype.html` | ✅ 已修复（`flex-shrink: 0`） |
| React `Card` 组件 | `components/ui/card.tsx:15` | ⚠️ 所有 Card 自带 `overflow-hidden` + `flex flex-col`，使用时需确保子项有 `min-h-0` |

**React 中的安全模式**（`settlement-chat.tsx:369-370`）:
```tsx
// ✅ 正确: min-h-0 覆盖 flex 默认值，允许收缩 + 内部滚动
<CardContent className="flex-1 ... min-h-0">
  <div className="flex min-h-0 flex-col">
    <ScrollArea className="flex-1" />
    <ChatInput />
  </div>
</CardContent>
```

**React 中不需要修复的原因**: 思维链等价组件（`IntentTraceCard`、`ExecutionTimeline`）均渲染在 `ScrollArea` 内部，ScrollArea 的 viewport 隐式 `overflow: auto` 提供正确的滚动行为。未被直接置于 `overflow: hidden` 的 flex 父容器中。

#### 陷阱 2: shadcn/ui Card 组件的 `overflow: hidden`

`card.tsx:15` 所有 `<Card>` 组件内置 `overflow: hidden` + `flex flex-col`。当 Card 嵌套在另一个 flex 容器中时，必须确保所有内容型子项有 `min-h-0`（Tailwind class），否则内容超出时会被裁剪而非滚动。

### 5.2 动画约束

- **入场动画使用 `transform` 而非 `top/left`**: `transform` 不影响文档流布局，不会导致重叠。`animation-fill-mode: both` 确保动画结束后保持在最终位置。
- **`pointer-events: none`**: 背景效果（scan-line、particles）必须设置此属性，避免阻挡交互。
- **z-index 层级**: 粒子 `z:0` → scan-line `z:0` → chat-viewport `z:1` → header `z:100` → drawer-overlay `z:200` → drawer `z:210`。
