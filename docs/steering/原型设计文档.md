**版本**: 2.0 | **日期**: 2026-05-12 | **技术栈**: Next.js 16 + React 19 + shadcn/ui (base-nova) + Tailwind CSS v4

> 本文档基于 `prototype/` 源代码、`docs/steering/接口设计文档.md` 和 `docs/steering/数据库设计文档.md` 生成。

## 1. 信息架构

### 1.1 系统概览

原型为**单页应用（SPA）**，所有功能通过 `page.tsx` 的标签页系统切换渲染。**全部数据通过 API 从 PostgreSQL 数据库获取，无 Mock 回退**。

```
医保AI导办与运营协同平台
│
├── Header（全局顶栏）
│   ├── 品牌标识（logo + 标题 + 版本号）
│   ├── API 连接状态指示器
│   └── 角色切换器（收费员/医保办/信息科/病案室/临床医生）
│
├── Sidebar（可折叠侧边导航）
│   ├── 业务应用
│   │   ├── AI导办对话     ← POST /chat + SSE /chat/stream
│   │   │                   ← 数据库: patients, insurance_transactions,
│   │   │                      error_code_knowledge, skills, workflows, audit_logs
│   │   ├── 结算异常导办    ← GET /workflows?scenario=settlement_exception
│   │   │                   ← 数据库: workflows, patients, insurance_transactions
│   │   ├── 出院前联合质控   ← GET /workflows?scenario=pre_discharge_qc
│   │   │                   ← LangGraph 图执行 → POST /tasks/confirm
│   │   └── 运营驾驶舱     ← 聚合查询 workflows + audit_logs（统计接口）
│   │
│   └── 平台管理
│       ├── 技能管理        ← CRUD /skills → skills 表
│       ├── MCP管理         ← CRUD /mcp/servers, /mcp/capabilities
│       │                   ← 数据库: mcp_servers, mcp_capabilities
│       ├── 知识管理        ← CRUD /knowledge/error-codes, /knowledge/rules,
│       │   │                  /knowledge/assets, /knowledge/appeal-templates,
│       │   │                  /knowledge/prompt-templates
│       │   │               ← 数据库: error_code_knowledge, rule_explanations,
│       │   │                  knowledge_assets, knowledge_chunks,
│       │   │                  appeal_templates, prompt_templates
│       │   └── RAG检索     ← POST /knowledge/assets/{id}/chunks → Milvus 向量检索
│       │
│       └── 模型管理
│           ├── 模型测试    ← POST /model-test, /model-test/stream
│           ├── 模型配置    ← GET/PUT /model-config
│           ├── 模型路由    ← CRUD /model-routes, /model-routes/fallbacks, /model-routes/params
│           └── Provider管理 ← CRUD /model-providers
│
└── Main Content（内容区，条件渲染对应组件）
```

### 1.3 数据流架构

```
用户操作 → 业务组件
         → api-client.ts → fetch(API_PREFIX + path)
         → next.config.ts rewrites → http://127.0.0.1:8000/api/v1/...

所有数据请求结果:
  ├── 200 OK → 渲染数据（从 PostgreSQL 查询返回）
  ├── 4xx/5xx → ApiClientError（展示错误提示）
  └── 网络不可达 → 展示"服务不可用"状态页面（不降级到 mock）
```

### 1.4 知识管理子页面结构

"知识管理" Tab 为复合页面，内部通过二级 Tab 切换 6 个子模块：

### 1.5 模型管理子页面结构

"模型管理" Tab 为复合页面，内部通过二级 Tab 切换 4 个子模块：

```
模型管理 (model Tab)

```

## 2. 页面约束

### 2.1 布局规范

| 约束项 | 规范 |
|--------|------|
| **视口** | 最小宽度 1024px（桌面端优先） |
| **整体高度** | `min-h-screen`，Header 56px sticky，内容区 `h-[calc(100vh-56px)]` |
| **侧边栏宽度** | 展开 232px（`w-58`），收起 56px（`w-14`），`transition-all duration-300` |
| **内容区** | `max-w-7xl mx-auto`，`p-6 lg:p-8` |
| **字体** | Noto Sans SC（思源黑体），400/500/600/700 字重 |
| **背景** | `#f6f8fc` + `bg-subtle-grid` 纹理 |

### 2.2 数据展示约束

| 场景 | 规范 |
|------|------|
| **列表加载中** | Skeleton 骨架屏（`shimmer` 动画），非空白页 |
| **列表为空** | 居中提示 + 引导操作按钮（如"创建第一个错误码"） |
| **API 错误** | Alert 组件展示错误信息，含可重试按钮 |
| **服务不可用** | 全页面状态提示"服务暂不可用"，禁用所有表单交互 |
| **表单提交中** | 提交按钮显示 `Loader2` 旋转 + disabled |
| **数据刷新** | 手动刷新按钮（非自动轮询），操作成功后自动刷新列表 |

### 2.3 CRUD 操作约束

| 操作 | 规范 |
|------|------|
| **列表页** | 支持按关键字段搜索 + 排序；分页（每页 20 条） |
| **创建** | Dialog/Sheet 表单，必填字段标注 *；提交前前端校验 |
| **编辑** | 同创建表单，回填已有数据；保存后列表原地刷新 |
| **删除** | 二次确认 Dialog；删除后列表移除该项 |
| **批量操作** | 暂不支持（v1.0） |

### 2.4 表单校验规则

| 字段类型 | 规则 |
|----------|------|
| **必填字段** | 空值不允许提交，红色边框 + 提示文案 |
| **ID 字段** | 字母数字下划线，2-128 字符 |
| **URL/端点** | 合法 URL 格式校验 |
| **JSON 字段** | Textarea 输入，提交时 JSON.parse 校验 |
| **风险等级** | 下拉选择：HIGH / MEDIUM / LOW |
| **布尔值** | Switch/Toggle 组件 |

## 4. 验收标准

### 4.1 AI 导办对话

| 编号 | 验收项 | 数据来源 |
|------|--------|----------|
| AC-1.1 | 输入"患者P001结算失败，错误码E-UPLOAD-001" → 返回错误码解释 + 导办建议 | `POST /chat/stream` → `error_code_knowledge` 表 |
| AC-1.2 | SSE 逐步显示进度事件（step/intent_trace/final/done） | SSE 事件流 |
| AC-1.3 | 意图追踪面板显示查询改写、TopN 候选、管道阶段 | SSE `intent_trace` 事件 |
| AC-1.4 | 输入含"退费"消息 → 弹出高风险确认 Dialog | `verify_security` 拦截 |
| AC-1.5 | 确认后调用 `/tasks/confirm` → 任务状态更新为 confirmed | `tasks` 表 UPDATE |
| AC-1.6 | 拒绝后任务状态为 rejected，操作被阻止 | `tasks` 表 UPDATE |
| AC-1.7 | 患者上下文显示脱敏信息（姓名"张**"） | `GET /patient-context` → `patients` 表 + 脱敏 |
| AC-1.8 | AI 回复含 citations 来源引用 | `AgentResponse.citations` |
| AC-1.9 | `@` 触发技能补全 → 选择后发送 | `GET /skills` → `skills` 表 |
| AC-1.10 | 后端服务不可用时展示"服务暂不可用"状态页 | 网络不可达处理 |

### 4.2 结算异常导办列表

| 编号 | 验收项 | 数据来源 |
|------|--------|----------|
| AC-2.1 | 从数据库加载待处理的结算异常工作流列表 | `GET /workflows?scenario=settlement_exception` → `workflows` 表 |
| AC-2.2 | 按优先级颜色标识（红/黄/绿） | `workflows.steps` 中的风险信息 |
