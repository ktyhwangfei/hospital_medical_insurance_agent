## 3. 核心业务流程：POST /chat

`POST /chat` 是平台唯一业务入口，所有场景（结算异常导办、出院前联合质控、MCP工具调用等）均通过此接口进入，由意图识别 + 编排引擎自动路由到对应执行路径。

### 3.1 请求 / 响应

**请求** `ChatRequest`：
```json
{
  "user_id": "U001",
  "role": "doctor",
  "message": "患者P001结算失败，错误码ERR001",
  "patient_id": "P001",
  "encounter_id": "E001",
  "mentioned_skill_ids": []
}
```

**正常响应** `AgentResponse`：
```json
{
  "scenario": "settlement_exception_guidance",
  "status": "completed",
  "result": { "summary": "...", "recommendation": "...", "_intent_trace": {...} },
  "citations": [{"source_type": "error_code_knowledge", "source_id": "ERR001", "summary": "..."}],
  "tasks": [],
  "blocked_actions": [],
  "audit": {"workflow_id": "wf-xxx"}
}
```

**高风险拦截响应**：
```json
{
  "scenario": "high_risk_action_confirmation",
  "status": "waiting_human_confirmation",
  "result": {"message": "检测到高风险操作：[退费]"},
  "tasks": [{"task_id": "task-xxx", "status": "waiting_confirmation"}],
  "blocked_actions": ["退费"],
  "audit": {"workflow_id": "wf-xxx"}
}
```

### 3.2 处理流程与数据库表访问

以下是 `POST /chat` 从请求进入到响应返回的完整处理链路，标注每一步访问的数据库表。

```
POST /chat
│
├─ [1. 网关中间件] GatewayAuditMiddleware — 自动审计
│   ├─ [表] sessions       — UPSERT（session_id, user_id, role, last_active）
│   └─ [表] audit_logs     — INSERT（event_type='api_request', 请求元信息）
│
├─ [2. 步骤] verify_security — 高风险动作筛查
│   └─ detect_blocked_actions(message)
│       命中 → 返回 waiting_human_confirmation，以下步骤全部跳过
│              ├─ [表] tasks       — INSERT（task_type='human_confirmation'）
│              ├─ [表] workflows   — INSERT（scenario='high_risk_action_confirmation'）
│              └─ [表] audit_logs  — INSERT（event_type='workflow_executed'）
│
├─ [3. 步骤] detect_intent_smart — 意图识别
│   └─ LLM 解析 + 关键词降级，无 DB 访问
│
├─ [4. 步骤] 若意图含 "appeal" → 预加载申诉模板
│   └─ [表] appeal_templates — SELECT（list_templates）
│
├─ [5. 步骤] RuntimeOrchestrator.execute_request — 编排引擎
│   │
│   ├─ 5a. 意图解析 → 上下文构建，无 DB 访问
│   │
│   ├─ 5b. UnifiedScenarioExecutor — 场景分发（四阶段匹配）
│   │   │
│   │   ├── Phase 1: @-mention 技能执行
│   │   │   └─ [表] skills — SELECT（skill_id）
│   │   │
│   │   ├── Phase 2: 关键词技能匹配（结算异常导办等场景）
│   │   │   ├─ [表] skills            — SELECT（intent_keywords 匹配）
│   │   │   │
│   │   │   ├─ SkillExecutionEngine._call_insurance_adapter()
│   │   │   │   ├─ [表] patients              — SELECT（patient_id → name）
│   │   │   │   └─ [表] insurance_transactions — SELECT（patient_id, encounter_id → settlement_status, error_code）
│   │   │   │
│   │   │   └─ SkillExecutionEngine._call_knowledge_service()
│   │   │       └─ [表] error_code_knowledge — SELECT（error_code → description, recommendation, responsible_role）
│   │   │
│   │   ├── Phase 3: LangGraph 业务场景图执行
│   │   │   ├─ settlement_exception_guidance — 图节点: retrieve → discriminate → validate → decide
│   │   │   │   ├─ [适配器] insurance_adapter  → 查询 [表] patients + insurance_transactions
│   │   │   │   ├─ [适配器] billing_adapter
│   │   │   │   └─ 若 interrupt() 触发人工确认:
│   │   │   │       └─ [表] tasks — INSERT（task_type='human_confirmation'）
│   │   │   │
│   │   │   └─ pre_discharge_quality_control — 图节点: candidate_retrieval → discrimination → validation → decision
│   │   │       ├─ [适配器] pre_audit, drg_dip, his, emr, medical_record（外部系统，不查 DB）
│   │   │       └─ 若 interrupt() → [表] tasks — INSERT
│   │   │
│   │   └── Phase 4: MCP 工具调用
│   │       ├─ [表] mcp_servers      — SELECT（server_id → payload_json, transport）
│   │       └─ [表] mcp_capabilities — SELECT（capability_id → payload_json, risk_level）
│   │
│   └─ 返回 AgentResponse
│
├─ [6. 步骤] 结果持久化
│   ├─ [表] workflows   — INSERT（workflow_id, scenario, status, steps, audit_refs, patient_id）
│   └─ [表] audit_logs  — INSERT（event_type='workflow_executed', workflow_id, payload）
│
└─ [7. 网关中间件] 响应返回
    └─ [表] audit_logs — INSERT（event_type='api_response', response_status, duration_ms）
```

### 3.3 /chat/stream（SSE 流式）

处理流程与 `/chat` 完全一致，区别在响应方式：通过 SSE 逐步推送处理进度，事件序列如下：

```
event: step       → {"step": "intent_detection", "message": "正在识别意图"}
event: intent_trace → {"intent": "...", "confidence": 0.95}
event: step       → {"step": "risk_control", "message": "正在检查高风险动作"}
event: step       → {"step": "scenario_processing", "message": "正在执行场景导办"}
event: step       → {"step": "response_rendering", "message": "正在生成结构化结果"}
event: final      → AgentResponse 完整数据
event: done       → {}
```

数据库表访问与 `/chat` 完全相同。

## 4. 人工确认：POST /tasks/confirm

高风险动作被拦截或 LangGraph 图执行中 `interrupt()` 暂停后，前端调用此接口进行人工确认或拒绝。

**请求**:
```json
{
  "task_id": "task-xxx",
  "action": "confirm",
  "user_id": "U001",
  "reason": "已核实"
}
```

**处理流程与表访问**:

```
POST /tasks/confirm
│
├─ [表] tasks      — SELECT（task_id → task_type, status, workflow_id）
│
├─ 若 _checkpoint_registry 中存在（LangGraph 内存路径）:
│   ├─ graph.invoke(Command(resume=...))   — 恢复图执行
│   ├─ [表] tasks      — UPDATE（status, confirmed_by, confirmed_at）
│   ├─ [表] workflows  — UPDATE（status）
│   └─ [表] audit_logs  — INSERT
│
├─ 若服务重启（LangGraph PG 恢复路径）:
│   ├─ [表] workflows  — SELECT（scenario）
│   ├─ [表] checkpoints — SELECT（恢复图状态）
│   ├─ graph.invoke(Command(resume=...))
│   ├─ [表] tasks      — UPDATE
│   ├─ [表] workflows  — UPDATE
│   └─ [表] audit_logs  — INSERT
│
└─ 普通人工确认路径（非 LangGraph）:
    ├─ [表] tasks      — UPDATE（status, confirmed_by, confirmed_at, reason）
    ├─ [表] workflows  — UPDATE（若有 workflow_id 关联）
    └─ [表] audit_logs  — INSERT
```

**响应**:
```json
{
  "task_id": "task-xxx",
  "status": "confirmed",
  "confirmed_by": "U001",
  "confirmed_at": "2026-05-12T10:30:00Z",
  "reason": "已核实",
  "result": { "scenario": "settlement_exception_guidance", "status": "completed" }
}
```

| `POST` | `/knowledge/error-codes` | `error_code_knowledge` | INSERT（ON CONFLICT UPSERT） |

## 11. 模型管理

模型管理是平台 AI 能力的配置中枢，管理模型连接配置、路由策略、Provider 和退避参数。

### 11.1 模型配置管理

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/model-config` | 获取当前模型服务配置（base_url, timeout, max_retries 等） |
| `PUT` | `/model-config` | 更新模型服务配置（api_key 写时不返回明文） |

**响应示例** (GET):
```json
{
  "base_url": "https://api.example.com/v1",
  "timeout": 30,
  "max_retries": 3,
  "default_model": "deepseek-v3"
}
```

### 11.2 模型路由管理

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/model-routes` | 列出所有路由规则（scene + model_type → model_name） |
| `POST` | `/model-routes` | 新增路由规则 |
| `PUT` | `/model-routes/{route_id}` | 更新路由规则 |
| `DELETE` | `/model-routes/{route_id}` | 删除路由规则 |
| `GET` | `/model-routes/fallbacks/{model_name}` | 查询指定模型的退避链 |
| `PUT` | `/model-routes/fallbacks/{model_name}` | 更新退避链 |
| `GET` | `/model-routes/params/{model_name}` | 查询模型参数（temperature, max_tokens, top_p 等） |
| `PUT` | `/model-routes/params/{model_name}` | 更新模型参数 |

**请求示例** (POST /model-routes):
```json
{
  "scene": "settlement_exception",
  "model_type": "llm",
  "model_name": "deepseek-v3",
  "priority": 1,
  "enabled": true
}
```

### 11.3 Provider 管理
