**版本**: 2.4 | **日期**: 2026-08-31

## 3. 政策问答 (Policy QA / Skill 驱动)

政策问答面向当前院端角色提供政策与费用解释服务。架构采用 Skill 驱动 + Strategy Pattern，Portal 通过 Chat-first 流式主入口消费单一答案。

### 3.1 架构概览

用户问题 → SkillRouter → policy-fee-explanation Skill → Strategy (pooling_self_pay/deductible/large_amount) → StructuredPolicyRuleRetriever (Milvus) → SkillResult

### 3.2 GET /policy-qa/settlement-explanation（兼容入口）

费用解释兼容入口。路径: GET /api/v1/medical-insurance-ai-agent/policy-qa/settlement-explanation。该路径暂时保留，但只返回 §3.4 定义的安全公开契约，Portal 页面不再调用。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| settlement_id | string | 是 | 结算单号 |
| question | string | 否 | 用户问题 |

费用项路由 (SkillRouter -> target_fee_item):

| 触发关键词 | target_fee_item | Strategy |
|-----------|----------------|----------|
| 统筹自付 | pooling_self_pay | PoolingSelfPayStrategy |
| 起付线 | deductible | DeductibleStrategy |
| 大额自付 | large_amount_self_pay | LargeAmountStrategy |

响应：`PolicyQAPublicResult`，与 `POST /policy-qa/stream` 的 `result` 事件完全一致。

### 3.3 POST /policy-qa/stream

SSE 流式主端点。请求体 `PolicyQARequest` 必填 `question` + `settlement_id`。公开事件包括 `step`、`result`、`error` 与 `done`；上下文事件仅携带经过过滤的公开信息。`step` 只允许展示 `public_message`，不得暴露推理、工具参数、SQL、表名、字段名或完整内部执行轨迹。`result` 事件的 `result` 字段遵循 §3.4。

门诊部分项目预退费分析当前处于 Skill 草稿阶段，尚未物化，不属于本端点公开契约。完成真实收费系统接入、隔离评测和人工审批后，发布时同步补充请求字段与结果契约。

结算读取和政策检索遵循一次请求级恢复预算：初始尝试计为 1，只有连接、超时及数据库/向量服务瞬时异常允许再尝试一次，因此 `attempt_count <= 2`。结算记录不存在、接口未配置和普通业务错误不重试。`done` 事件必须包含 `attempt_count` 与 `halt_reason`；成功查证使用 `verified`，错误使用稳定的公开停止原因。恢复和查证可发送公开 `step`，但不得输出内部推理。

### 3.4 Policy QA 安全公开结果契约

`POST /policy-qa/stream` 的 `result.result` 与兼容入口 `GET /policy-qa/settlement-explanation` 均使用同一个白名单模型 `PolicyQAPublicResult`：

| 字段 | 类型 | 说明 |
|------|------|------|
| `answer` | string | 面向当前院端角色的单一答案 |
| `answer_status` | `complete \| partial \| unavailable` | 答案完整性；不可可靠回答时必须为 `unavailable` |
| `case_context` | object \| null | 仅含获准公开的结算上下文字段 |
| `calculation_steps` | array | 经白名单过滤的计算过程 |
| `definition` | object \| null | 费用项目公开定义 |
| `warnings` | string[] | 经办提示与限制条件 |
| `policy_evidence` | array | 经脱敏、可公开的政策证据摘要 |
| `citations` | array | 可在 Portal 展示的政策依据，每项仅含 `title` 与 `excerpt` |
| `uncertainties` | string[] | 无法形成可靠结论时必须明确列出的不确定性 |
| `verification_summary` | object | 结算、计算与政策核对摘要，含 `settlement_checked`、`calculation_checked`、`policy_count` 与公开说明 |

来源门禁：确定性政策结论必须有可展示 `citations`；预退费金额或正式拒绝必须引用医院收费系统预结算来源。证据不足时通过 `uncertainties` 明确说明，不输出伪确定结论。公开结果使用严格白名单，嵌套对象同样拒绝额外字段。

#### 破坏性迁移说明

`patient_view`、`office_view`、`settlement_evidence` 已从后端公开契约和 Portal 消费模型中删除，不提供兼容字段。后端与 Portal 必须同步发布、同步回滚；旧前端不能单独搭配新后端运行。`/settlement-explanation` 只兼容路径，不兼容旧响应字段。

### 3.5 POST /policy-qa/test

非流式测试端点（返回请求回显），用于快速验证端点可用性。

### 3.6 GET /policy-qa/history

问答历史记录，支持 user_id 过滤 + 分页（limit/offset）。返回全量 session、workflow、task 数据。

### 3.6a 会话生命周期与轨迹（Issue #30）

> 前缀均为 `/api/v1/medical-insurance-ai-agent/policy-qa`；user_id 当前由查询参数声明（dev 口径），SSO 接入后改认证上下文。设计详见 `docs/steering/政策问答-轨迹持久化与挂起升级恢复-设计-V1.0.md`。

| Method/Path | 说明 | 关键响应/约束 |
|------|------|------|
| `GET /sessions?user_id=&limit=` | 用户可恢复会话列表 | 状态、轮次数、首问/末问摘要 |
| `GET /sessions/{session_id}?user_id=` | 会话详情 | 状态 + 原因 + 最近升级工单（含回复）；非本人 404 |
| `GET /sessions/{session_id}/trajectory?user_id=` | 轨迹重放 | 全部轮次快照（question + payload：context_need/memory_updates/result/attempt_count/halt_reason） |
| `POST /sessions/{session_id}/suspend?user_id=` | 挂起 | body `{reason?}`；仅 active；重复挂起 409 INVALID_SESSION_TRANSITION |
| `POST /sessions/{session_id}/resume?user_id=` | 恢复 | suspended→active；响应携带完整 trajectory |
| `POST /sessions/{session_id}/escalate?user_id=` | 升级医保办 | body `{question, reason?, qa_turn_id?}`；仅 active；创建工单（waiting_human_confirmation）|
| `POST /escalations/{task_id}/resolve` | 工单回复 | body `{reply, resolved_by}`；回填 escalation_reply 并恢复会话 active；幂等 |

> `POST /policy-qa/stream` 对非 active 会话返回 409（`SESSION_NOT_ACTIVE`）；每轮流式结束（成功与失败）均写入轨迹快照。

### 3.7 GET /policy-qa/debug/structured-policy-search

调试端点，展示结构化政策规则检索完整过程：settlement_context → normalized_policy_context → planned_queries → structured_hits → selected_policy_evidence → missing_required_rules → dedupe_info。

### 3.8 政策知识 CRUD（/policy-knowledge）

Milvus policy_rules 集合 CRUD。支持分页 + keyword + 多字段过滤（rule_type, insu_type, hosp_lv, psn_type, med_type, setl_type, admission_order, amount_band, priority）。

| 端点 | 说明 |
|------|------|
| `GET /rules` | 分页查询（page, page_size, keyword, 9 个过滤字段） |
| `POST /rules/query` | 高级表达式查询（自定义 expr, limit, offset, output_fields） |
| `GET /rules/{rule_id}` | 单条规则详情 |
| `PUT /rules/{rule_id}` | 更新规则（先删再插，仅可编辑字段） |
| `DELETE /rules/{rule_id}` | 删除规则 |
| `GET /stats` | 集合统计（总量 + rule_type/insu_type/hosp_lv/psn_type/med_type 分布） |
| `POST /import` | 触发数据导入（当前未实现，返回命令行指引） |

### 3.9 Skill 架构

SkillLoader: 扫描 skills/ 动态发现。SkillRouter: 关键词路由。新增 Skill: 创建目录 + manifest + assembler 即自动发现。

### 3.10 Strategy Pattern

strategies/ 下每个费用项独立策略，各自拥有 definition / policy_queries / build_answer / calculation_trace / warnings / completeness。

## 6. Skill 基础设施

见接口清单 §2。端点: `/infra-skills`, `/infra-skills/{id}`, `/infra-skills/route-test`, `/infra-skills/{id}/test`

### 6.1 GET /infra-skills

返回所有已加载 Skill 列表。响应体：

```json
{
  "skills": [
    {
      "skill_id": "settlement_explain_skill",
      "skill_name": "医保费用解释",
      "business_action": "explain",
      "business_object": "settlement",
      "include_keywords": ["统筹自付", "起付线", "报销比例", ...],
      "excluded_intents": []
    }
  ]
}
```

`business_action` 为 `BusinessAction` 七类枚举之一（explain / query / guide / verify / compare / evaluate / analyze），
`business_object` 为 `BusinessObject` 枚举值（settlement / benefit / policy / directory / chronic_disease / referral / appeal / medical_record / drg_dip / complaint）。
两者共同唯一确定一个 Skill。

### 6.2 路由机制

用户问题 → Business Action Recognition（做什么）→ Business Object Recognition（处理谁）→ Skill Router（关键词 + LLM 消歧）→ Skill Execution

## issue #2 政策知识测试与发布接口补充（2026-08-03）

前缀仍为 `/api/v1/medical-insurance-ai-agent`，候选版、用例集与质量运行统一使用以下接口：

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/policy-workbench/documents` | 列出审核通过单元文档 |
| `GET` | `/policy-workbench/documents/{doc_id}` | 返回 Unit、Knowledge 及字段/值域投影 |
| `POST` | `/semantic/alignment/metrics` | 创建带政策来源绑定的 `zcgz` 草稿，不直接发布 |
| `GET` | `/policy-workbench/test-cases` | 列出全部测试用例（含内置与自定义、停用） |
| `POST` | `/policy-workbench/test-cases` | 新增或更新经典用例及版本 |
| `GET` | `/policy-workbench/releases` | 列出候选/活动/退役版本 |
| `POST` | `/policy-workbench/releases` | 按 facts/rules collection 对创建候选版 |
| `POST` | `/policy-workbench/releases/{release_id}/build` | 校验并构建候选版 collection 对 |
| `POST` | `/policy-workbench/releases/{release_id}/test` | 同用例集重复对跑候选与当前基线 |
| `GET` | `/policy-workbench/releases/{release_id}/quality/latest` | 恢复最新质量运行和逐案结果 |
| `POST` | `/policy-workbench/releases/{release_id}/promote` | 人工确认后整批原子切换 active |
| `POST` | `/policy-workbench/releases/{release_id}/rollback` | 回滚到历史上曾 active 的 retired 版本 |

发布门禁必须校验最新 passed run、当前用例集版本、配置哈希和 active baseline；不接受单条 Unit/Knowledge 发布。

`POST /policy-workbench/test-cases` 请求体（部分字段即可，`case_id` 缺省自动生成 `tc_<hex>`）：
| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| case_id | string | 否 | 自定义用例ID，缺省自动生成 |
| name | string | 是 | 用例名称 |
| query | string | 是 | 政策查询语句 |
| mode | string | 否 | precise/semantic/hybrid，默认 semantic |
| expected_knowledge_ids | string[] | 否 | 期望命中知识ID，默认 []（内置用例留空=检索性校验） |
| required | boolean | 否 | 是否必测，默认 true |

> 新增用例后 `case_set_version` 递增（`policy_case_set_version_seq`），存量候选发布门禁会要求重新创建候选版本。
