## Why

当前 MVP 仅实现了错误码知识库的内存查询，尚未形成可复用的知识接入、RAG 检索、规则解释、提示词模板和扩展能力管理契约。医保导办、出院前质控、拒付申诉、DRG/DIP 运营等后续场景需要统一的知识与扩展服务，以保证知识来源可追溯、检索结果可审计、规则解释可复用，并与运行时编排、模型服务和业务适配器解耦。

## What Changes

- 新增知识资产管理能力，覆盖医保政策、院内制度、错误码、审核规则、申诉模板等知识的接入、切片、版本、状态、来源和审计元数据。
- 新增 RAG 检索能力，提供向量检索、关键词检索、重排、上下文组装、引用溯源和无结果降级契约。
- 新增规则解释能力，将错误码、医保规则、事前审核规则、DRG/DIP 规则和病案质控规则转换为可解释、可引用、可审计的导办依据。
- 新增提示词模板能力，为场景、角色、输出格式和安全约束提供版本化模板管理，并支持运行时按上下文选择模板。
- 新增扩展资产注册能力，定义 Tool、Skill、MCP、A2A 等扩展能力的元数据、安全边界、权限要求和调度契约。
- 新增统一知识与扩展服务门面契约，运行时通过门面完成资产检索、规则解释、模板选择和扩展选择，避免业务场景直接依赖具体知识子模块。
- 明确 MVP 阶段只交付内存实现、Pydantic 模型、Protocol 端口、确定性检索与解释闭环，不接入真实知识管理后台、真实向量库或远程扩展执行沙箱。
- 保持知识服务与业务场景、模型服务、外部系统适配器解耦，不直接访问真实业务系统，不替代正式医保裁决。

## Capabilities

### New Capabilities
- `knowledge-assets`: 知识资产接入、结构化元数据、版本状态、来源记录、切片索引和审计管理。
- `rag-retrieval`: 面向医保业务的混合检索、重排、上下文组装、引用溯源和降级输出。
- `rule-explanation`: 错误码、政策规则、审核规则、DRG/DIP 规则和病案质控规则的解释与证据引用。
- `prompt-template-management`: 场景模板、角色模板、输出格式模板和安全约束模板的版本化管理与运行时选择。
- `extension-registry`: Tool、Skill、MCP、A2A 扩展能力注册、权限约束、调用元数据和运行时调度契约。

### Modified Capabilities
- `runtime-execution-loop`: 运行时计划步骤需要能够调用知识检索、规则解释、提示词模板和扩展能力，并将引用、降级、不确定性和审计事件纳入 workflow 状态。
- `security-contracts`: 知识与扩展服务输出需要满足 citations 或 uncertainties 要求，扩展能力调用必须执行权限、风控和审计约束。

## Impact

- 受影响代码目录：`knowledge_extension/`、`runtime/`、`model_service/`、`security/`、`data_platform/storage/vector/`、`data_platform/storage/cache/`、`business_scenarios/`、`shared/schemas/`。
- 受影响 API：Chat 与流式 Chat 的响应引用来源、降级提示和审计事件；后续可新增知识管理与扩展注册管理接口。
- 受影响数据与基础设施：向量存储、缓存、知识元数据存储、审计日志；MVP 阶段仍可使用内存实现和 Protocol 端口。
- 受影响测试：新增知识资产、RAG、规则解释、提示词模板、扩展注册、运行时集成、安全边界和审计可追溯测试。

## Refinement Notes

- 第一阶段聚焦后端核心闭环，不新增管理 UI；若需要知识资产上传、审核发布、在线模板编辑或扩展目录管理端点，应另起后续变更。
- 知识资产、RAG、规则解释、提示词模板和扩展注册均必须先暴露稳定 Pydantic 模型与 Protocol，内存实现不得泄露可变内部状态。
- 运行时集成应采用可选依赖与确定性兜底，确保知识服务不可用时既有医保结算异常导办和出院前联合质控仍可返回带 uncertainties 的降级结果。
- API 响应仍沿用现有 `AgentResponse` 字段，新增知识增强信息优先进入 `citations`、`uncertainties`、`audit` 和 `result` 的结构化子字段，避免破坏前端与 OpenAPI 兼容性。
