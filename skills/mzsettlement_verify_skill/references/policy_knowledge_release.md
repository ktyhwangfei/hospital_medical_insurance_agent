# 政策与语义基线迁移说明

`policy_knowledge_baseline.yaml` 是本 Skill 的可追溯基线；数据库文档 ID、变更集 ID和发布 ID 是本次运行证据，不要求在新环境复用相同 ID。迁移以官方 URL、原文哈希、审核数量、语义契约和质量结果为准。

## 迁移顺序

1. 在政策知识治理页按 `source_url` 接入八份官方文档及附件。若同 URL、同 `content_hash` 已存在则复用；同 URL 但哈希变化时按新修订版重新审核，禁止静默覆盖。
2. 依次完成解析、提取和人工审核。编码标准数据库只作引用；不能从中生成待遇比例。基线结果为 195 个通过、2 个驳回，核心候选 31 项且编译 31 PASS、0 blocker。
3. 在语义发现页批量发布基线列出的指标和值域，然后发布 `mzjyxx` 新版本。版本号可以递增，但必须包含 `skill_manifest.yaml` 声明的全部指标；当前基线为 103 个已发布指标、Skill 所需 88 个、缺失 0 个。
4. 从审核通过的变更集构建候选知识发布，运行经典用例集 v2；只有候选质量、重复一致性和 blocker 门禁通过后才能激活。
5. 激活后用九个 Profile 各跑一例真实 `T_TradeNo`。字段解释必须有字段级 `citations`；场景核心金额缺失返回 `unavailable`；政策或非核心字段不足返回 `partial/uncertainties`。

## 当前不可迁移能力

- PostgreSQL/Milvus 的运行状态不随 Git 合并迁移，目标环境必须重新走治理管线；本目录不包含原始敏感结算数据。
- `mzjyxx.F_LEVEL` 已发布，`item_insurance_level` 值域已存在，但当前快照尚未把两者显式绑定；页面补齐绑定前只能解释原始等级值。
- `mzjyxx.T_State` 尚无已发布值域和“有效结算状态”口径；Skill 已把字段缺失和交易号多记录判为 `unavailable`，但不能凭未知代码猜测状态是否合法。
- 退休人员 70 岁分档缺少隐私安全派生指标 `retiree_age_band`，不能发布原始出生日期作为替代。
- 五个经典用例尚缺答案验证夹具，生产答案门禁保持关闭；检索质量门禁通过不等于答案门禁通过。
- 军残、公务员补助、军休、公费医照、单位补充医疗和医疗救助的具体支付公式缺少现行统筹区参数文件，相关结论必须降级。
